## 1. 使用边界

本文件只保留跨周期必须一致的职责、数据和执行边界。具体接口、表结构、依赖版本、部署参数及实现方案，在首次需要它们的周期开始前提交技术评审，由用户明确通过后实施。

产品需求、验收和阶段归属统一以 PRD 为准。历史技术文档中的对象名、端口、路径和框架示例不是已实现接口，也不自动成为已批准方案；历史内容可从 Git 记录查阅。

## 2. 当前实现与目标架构

| 范围 | 当前事实 | 后续实现要求 |
|---|---|---|
| Studio 原型 | prototype/ 使用 HTML、CSS、JavaScript 和浏览器本地数据演示流程 | 可作为交互参照，逐期替换为经过验收的真实能力 |
| 登录、空间与凭证 | 原型提供本地演示，不构成正式服务端鉴权或秘密保管 | 正式账号、租户、空间授权与凭证保护在相应周期实现 |
| 模型、工作流、Agent、知识、评测和发布 | 原型展示配置与运行交互 | 真实调用、持久任务、沙盒、审核与外部 API 均需服务端实现和验证 |
| 部署 | 尚无正式平台镜像和可交付 Compose 包 | 第七周期完成整包部署、恢复与全链路验收 |

## 3. 四个产品域的职责

| 产品域 | 负责的结果 | 与其他域的边界 |
|---|---|---|
| Studio | 构建、配置、调试应用及其能力 | 产出版本和运行输入；实际执行统一进入 Runtime |
| Runtime | 执行任务，保存步骤、结果、暂停状态和调用事实 | 使用当前授权与预算；不把模型建议直接当作执行许可 |
| Quality | 管理用户样本、评测、对比、失败分析和 Prompt 候选 | 锁定被测版本与条件；采用候选由用户决定 |
| Operations | 管理身份、凭证、用量、应用发布、公共审核及运行维护 | 授权和公开状态可约束各域；不替代任务执行和质量判断 |

四域用于组织产品职责和代码边界，不要求拆成四套微服务。起步沿用模块化控制服务与独立执行边界的方向；进程拆分以当期隔离、可靠性和运行需求为依据。

## 4. 控制与执行边界

| 逻辑组件 | 职责 | 必须守住的边界 |
|---|---|---|
| 控制台与入口 | 编辑、查询、事件展示和用户操作 | 不持有其他用户秘密，不通过隐藏菜单代替后端授权 |
| 控制服务 | 身份、资源、版本、审批、预算及任务受理 | 不在请求线程执行长任务，不直接运行租户代码 |
| Runtime 与后台 Worker | 调度、步骤执行、知识处理和评测 | 使用明确任务身份、固定依赖与持久状态；后台任务同样计量和鉴权 |
| Model / Tool Gateway | 解析当前连接、校验能力与授权、受控调用、记录用量 | 模型、MCP、Skill 和插件均不能绕过执行前检查 |
| 受信执行管理 | 创建、限制、停止和回收执行实例 | 不向普通 Worker 或租户代码暴露宿主管理能力 |
| 隔离执行实例与插件界面 | 运行获准代码，展示插件配置与结果 | 代码隔离和前端隔离分别验证，不共享平台会话或全量凭证 |

这些是逻辑职责，具体类、服务名和调用协议待当期评审；允许同一发行包按角色启动，不预先增加独立服务数量。

## 5. 必须保持的架构约束

1. **身份与归属**：个人账号对应独立租户，注册建立默认工作空间，可创建更多空间。服务端确定租户和资源范围；列表、详情、搜索、文件、异步任务与子任务均执行隔离。普通用户可使用完整产品能力，管理员承担平台治理和公共审核职责。
2. **Sa-Token 与用户凭证**：正式身份接入使用 Sa-Token。模型和工具由用户自行配置；缺少凭证时明确阻止相关调用，不能借用他人或作者的 Key。凭证不进入公共包、浏览器插件界面、普通日志和导出样例。
3. **资源与运行版本**：草稿、可运行版本、应用发布版本和公共审核版本分别管理。一次运行固定依赖版本；当前撤权、停用和预算限制仍然生效，快照不能成为永久授权。
4. **持久执行**：P1 保存运行和调用事实，P2 保存动作确认及外部效果记录，P3 保存计划版本和批准依据；P6 交付完整执行检查点、持久人工等待和跨进程续跑。浏览器关闭不等于任务取消；前期中断须显示真实状态，不承诺自动续跑，不自动重放结果不明的外部动作。持久计划不等于可恢复执行图，恢复时须复核当前授权、依赖和已发生效果。
5. **动作与审批**：模式切换、计划和子 Agent 不增加权限。需要审批的动作在执行前暂停，批准绑定明确对象、参数和范围；相关内容变化时重新判断授权。未知外部效果先核实，不盲目重试非幂等写入。
6. **插件动态管理**：配置插件、代码插件、自定义前端及统一表单共用有效配置和权限规则。安装、配置和升级不重启整个平台或全部 Runtime；旧任务保留所需版本，失败升级不破坏无关任务，卸载先检查引用。
7. **执行与界面隔离**：P2 在开放自定义界面前完成界面隔离、通信协议和插件包保存的评审与验证；P3 在开放代码插件、Skill 脚本和本地 MCP 进程前完成代码沙盒与实例生命周期验证。代码只获得指定文件、网络、资源额度和任务级能力；界面经受控通道获取必要数据，不能取得主平台登录令牌。
8. **上下文与记忆**：用户目标、最新修正、权限、已发生效果、待办和证据来源需保留。规则、Skill 与外部资料不能自我升级为平台指令；长期记忆有来源、范围、修改和删除路径，压缩结果支持回读依据。
9. **知识与质量**：原资料及版本是事实来源，索引和缓存可以重建。撤权先限制访问，更新失败保留可用旧版。评测固定样本、条件和版本，保留失败、未知与逐题证据；候选优化不直接覆盖已发布版本。
10. **用量与预算**：所有实际模型调用有唯一调用记录，包含重试、子 Agent、知识处理、压缩、评测和优化。报告值、估算值和未知值分开；父子汇总不重复计量，子任务继承父任务额度，费用估算不冒充供应商账单。
11. **公开与运行分离**：应用、插件、Skill、MCP、Prompt 的精确版本经管理员审核才公开。采用公共模板不继承作者凭证；托管应用另行声明调用者、执行租户和费用承担者。API Key 只授予指定应用权限，不能充当平台登录或模型凭证。
12. **完整部署与恢复**：Docker Compose 交付包含必需服务、初始化、持久挂载和操作说明。只填写约定的数据库与中间件秘密即可按说明启动；个人模型 Key 在部署后配置。备份必须覆盖业务数据、权威文件及解密材料，并在新环境验证恢复。

### 跨周期公共契约

P1 技术评审确定当期需要的资源标识、租户/空间/项目归属、访问检查、运行事实、调用记录、基础预算与版本引用边界；P2 增加审批对象及执行扩展契约，P3 增加统一模式策略和代码隔离边界，P6 扩展持久恢复而非重建前三期公共契约。新增协议或存储结构仍按首次需要的周期评审，不提前确定具体实现。

开发环境从 P1 起应可重复启动、数据与配置分离；P7 才交付正式一键部署和备份恢复验证。用户关闭页面或切换空间不应直接决定正式后台任务生命周期；浏览器原型的本地停止行为不作为生产契约。

## 6. 沿用的技术方向与待评审选型

| 领域 | 沿用方向或候选 | 首次需要锁定的周期 |
|---|---|---|
| 身份与交付方式 | Sa-Token、Docker / Compose 是已确定约束；具体兼容版本待验证 | 身份在周期一；正式部署组合在周期七 |
| 服务端 | Java / Spring 生态，Java 21 与 Spring Boot 为现有候选 | 周期一：实际工程、版本组合和构建方式 |
| 模型与执行 | Spring AI、Spring AI Alibaba 的适配方向；平台保留自身资源和运行契约 | 周期一：模型调用及运行事实；周期二：基础编排与确认记录；周期三：持久计划与批准；周期六：检查点、持久等待及跨进程恢复 |
| 前端与画布 | Vue 3、TypeScript、LogicFlow 为现有候选 | 周期一：控制台；周期二：画布与执行定义的映射 |
| 事务与协调 | MySQL、Redis 为现有候选；持久任务事实不只保存在缓存或内存 | 周期一：身份、版本、调用和任务基础；后续按新增需求扩展 |
| 代码与前端扩展 | 独立执行实例、受限前端承载和能力桥接 | 周期二：界面隔离、通信协议与兼容边界；周期三：代码沙盒及实例生命周期 |
| 知识与文件 | OpenSearch、S3 兼容存储为现有候选，SeaweedFS 为既有默认实现建议 | 周期二：插件包存储；周期四：知识原文存储、解析、检索与证据方案 |
| 质量与发布 | 复用运行、版本、权限和调用事实；评测器、发布接口与审核模型按当期设计 | 周期五：质量；周期六：对外入口与公共审核 |

候选项不等于已选定实现。每次评审需说明为什么适合本期、与已有组件是否兼容，以及验证失败的替代办法；未获用户通过的方案不进入开发。

周期一只确定当期工程与扩展边界，不提前冻结后续检索引擎、插件协议、发布接口和部署端口。后续确需改变已交付公共契约时，在当期评审说明迁移、兼容和回退影响。
