# 执行、上下文工程与权限设计

> 版本：v0.2 · 更新：2026-11-23 · 状态：后续实现契约；不是已存在的运行内核或安全验证结论。

## 1. 一套运行事实，多种开发入口

对话、工作流、Agent、评测和 Prompt 优化最终都创建可追踪运行。共同使用个人租户作用域、依赖版本清单、调用账本、预算、产物管理和事件记录，避免某个入口绕过成本或权限治理。不同入口的编排方式可以不同：固定图按预设控制流执行，Agent 根据观测选择下一动作，评测按固定样本创建子任务。

运行与浏览器连接解耦。API 返回运行标识，控制台订阅事件和查询状态；SSE 中断时可以重新定位已产生事件。用户点击取消才发出取消命令，关闭页面不应使已持久保存的任务丢失。

## 2. 工作流定义与节点契约

平台维护可版本化的图定义，画布编辑器负责视图及编辑动作，运行适配器负责将图编译为可执行计划。分别保存节点位置等展示信息与节点类型、参数、输入输出和控制边等执行信息。每次发布保存内容摘要，避免画布自动排版改变业务语义版本。

| 契约维度 | 拟定内容 | 校验时机 |
|---|---|---|
| 节点身份 | 稳定节点 ID、节点类型和实现版本、可选插件来源 | 保存时及发布时 |
| 输入输出 | 结构、必填、可空、默认值、类型转换策略 | 编辑时提示，运行前严格校验 |
| 数据绑定 | 引用上游节点已输出字段，区分缺失、空值与未执行 | 图校验与每次节点启动前 |
| 控制语义 | 顺序、条件、循环、并行、汇合、子流程、人工等待 | 编译时检查可达性、循环与汇合规则 |
| 执行效果 | 只读、可幂等写入、非幂等外部影响或未知 | 配置/安装时声明，执行时结合当前策略核验 |
| 资源边界 | 模型、工具、文件、网络、超时、重试、预算和最大输出 | 准入与每次调用前 |
| 结果与产物 | 成功/失败/待核实、结构化输出、受控文件引用、用量 | 写入检查点之前 |

节点声明不作为安全事实直接信任。标称“只读”的第三方工具仍需按连接权限和实际允许能力限制；代码插件不能用伪造类型绕过管理网关。

### 2.1 控制流的确定规则

- 条件分支只激活匹配路径及明确默认路径。未选择的节点标为跳过，其输出是不可用，不能当作空字符串自动流入下游。
- 并行节点分别写入隔离结果；汇合策略须声明等待全部、等待指定集合或满足阈值等允许方式。未交付的汇合方式不能出现在可选配置里。
- 循环必须有终止条件、最大次数及累计预算；记录迭代编号。循环中的节点重试与新一轮迭代不是同一个 attempt。
- 子流程引用固定版本，传入明确输入并返回明确输出。递归深度和重复调用受父任务预算限制，禁止无限自引用。
- 人工介入是可持久保存的等待状态，不能通过长时间占用一个线程等待用户响应。
- 每个错误分支说明哪些效果已经发生。没有补偿操作时只停止后续动作，不能在界面上宣称全部外部影响已回滚。

阶段 2 提供基础图和子流程；并行、循环、持久人工介入等完整语义在阶段 6 收口。节点契约在阶段 2 预留并明确哪些类型暂不支持，详见 [阶段需求](../requirements/phases/phase-02-visual-workflow.md)。

## 3. Agent Loop 与工具执行

Agent 的循环可以概括为：接收当前目标与上下文 → 生成回答或提出动作 → 校验动作 → 执行 → 记录结果 → 决定继续、等待或结束。模型只提出工具名称和参数，真实调用由受信执行层完成。[Spring AI Tool Calling 文档](https://docs.spring.io/spring-ai/reference/api/tools.html) 也区分模型请求工具与应用实际执行；PeachAgent 的授权、预算和外部效果保护必须位于实际执行之前。

产品模式可按对话建议、计划、受控执行和自动多步配置，但模式切换不能新增权限。用户已经在本任务范围内授予的权限可以复用；只有对象、动作或范围发生实质变化、或策略明确要求确认时才再次请求授权。计划、尝试动作、成功效果和最终任务成功分别记录。

工具选择先按当前租户、项目授权和适用能力产生候选，再按任务相关性控制放入模型的工具说明。减少工具说明可以降低上下文占用，但检索选中工具不等于获得调用权限。实际执行再次检查名称、版本、参数结构、凭证绑定、目的地和预算。

### 3.1 MCP 适配边界

MCP 连接分离服务配置、本人认证绑定、能力快照、允许集合和调用记录。按实际采用协议版本协商并保存支持能力；远程连接与受控本地进程连接分别验证传输、认证与取消行为。协议升级通过版本化适配器实现，不把某个厂商工具格式当作 MCP 全部能力。

[MCP 官方规范入口](https://modelcontextprotocol.io/specification) 描述协议和可选扩展，具体支持版本应在开发与发行时锁定。平台默认交付经过验证的协议/传输组合；例如可选的 UI 或长任务扩展只有双方明确支持并满足平台权限边界后才可启用，不能把存在于规范页面等同于本平台已经支持。

MCP 服务返回的说明、资源和 Prompt 属于外部内容。远端更新了工具列表或权限范围时，应重新验证当前绑定并向用户说明影响；公共仓库审核的是连接包及其声明，不是对外部服务所有未来内容永久背书。stdio 本地进程按代码执行边界运行，不允许任意启动宿主命令。

## 4. 运行状态、检查点与重复效果

| 状态 | 进入依据 | 恢复或退出条件 |
|---|---|---|
| 已受理 / 待调度 | 输入、目标和预算准入完成，任务已持久保存 | 可信 Worker 取得有效租约 |
| 执行中 | 当前租约有效，正在执行可确定步骤 | 下一步、人工等待、取消或终止 |
| 待人工 | 已保存等待对象、当前事实及决策要求 | 当前有权主体批准/拒绝，或到期取消 |
| 恢复检查 | 重新获取原检查点及版本 | 依赖存在，当前授权与资源有效，旧效果已核对 |
| 结果待核实 | 外部操作可能生效但没有可确认结果 | 查询外部状态、用户核实或使用已证明安全的幂等重试 |
| 完成 / 失败 / 取消 | 持久记录了终态与依据 | 重新运行应创建新运行/分支，不能覆盖历史事实 |

检查点至少记录图/Agent 版本、已完成节点、待执行节点、变量与产物引用、分支/循环、消息引用、上下文摘要版本、工具效果、人工等待、预算用量和插件版本。检查点格式本身要有版本与兼容策略；对象存储中被引用的文件和插件包需受引用生命周期保护。

恢复不是简单把“最后一条消息”再次发给模型。[Spring AI Alibaba 的检查点文档](https://www.java2ai.com/docs/frameworks/graph-core/core/persistence/) 提供可借用的基础机制，本平台还需实现外部效果账本、租户键、权限复核和数据迁移。

| 操作类别 | 自动重试条件 | 不满足时的处理 |
|---|---|---|
| 查询与纯计算 | 预算允许、输入版本一致、未取消；如数据时点变化需记录 | 失败并展示原因，不伪造旧结果为本次事实 |
| 支持业务幂等键的写入 | 外部服务明确支持，同一业务意图复用相同键，并核对返回 | 转待核实，不能换新键盲目重发 |
| 无幂等保证的写入 | 仅在明确尚未发送或有可信无效果证据时重试 | 查询状态或人工决定，说明重复影响风险 |
| 模型调用 | 可以按错误类别重试，但每次都是新的计费尝试 | 记录未知/已消耗用量，受总预算限制 |
| 人工审批 | 审批请求唯一，重复点击只记录一次决定 | 版本/对象变化时重新生成明确审批事项 |

数据库事务和 Worker fencing 能防止过期进程写回平台状态，但无法独自阻止一个已发给第三方的操作生效；该限制必须体现在状态与恢复逻辑中。

## 5. Skill 渐进式披露

[Agent Skills 规范](https://agentskills.io/specification) 说明 SKILL.md 及可选脚本、参考资料和资源的包结构。PeachAgent 对此采用下列分层读取策略；分层名称是本平台设计，不宣称所有外部实现使用相同等级。

| 层级 | 提供给模型或执行器的内容 | 触发条件 | 记录内容 |
|---|---|---|---|
| L0：简介索引 | 名称、用途、来源、版本、适用环境摘要 | 任务发现候选时 | 检索候选、选择/不选择及实际 Token |
| L1：技能正文 | 被选 Skill 的主说明与执行步骤 | 明确相关后，读取固定版本 SKILL.md | 内容摘要、读取范围、采用的约束 |
| L2：按需资料 | 与当前步骤直接相关的参考、模板、样例 | 正文引用或任务确实需要，按授权读取 | 文件路径、片段位置、版本及未读取的可回读入口 |
| L3：受控执行 | 指定脚本和必要输入，通过隔离实例执行 | 获得当前有效授权，满足环境和能力限制 | 版本、参数摘要、动作、产物、用量和失败 |

不能在启动时把所有 Skill 正文、引用目录和脚本都放进系统提示。相同内容按版本/摘要去重，记录已读取片段，但跨租户和权限变化不能复用不适当缓存。Skill 的 allowed-tools 等元数据可以作为能力申请或兼容说明，不能直接给它真实授权。

评测同时关注正确 Skill 是否进入候选、是否选对、正文/引用是否按需读取、是否误读无关秘密、脚本是否被正确授权，以及任务结果与消耗。只统计加载文件数或节省 Token 不能证明披露策略有效。

## 6. AGENTS.md 与规则作用范围

规则发现从用户选定的项目根和获准子目录出发，记录原文件名、规范化路径、版本、摘要和适用范围。默认识别 AGENTS.md；对已有 agent.md、其他命名或导入规则提供显式映射，不能因为文件名相似就在全宿主扫描。符号链接和相对路径需要校验仍在获准工作区内。

普通项目约定按目录范围应用，较具体目录规则仅影响其子范围。同层冲突或与当前任务冲突时展示来源及处理结论。当前用户明确修改普通格式或工作偏好时优先采用其要求；平台强制权限、租户边界、预算和安全约束不可被项目文件、Skill 或检索文本覆盖。

工具结果、检索资料和插件说明中的“系统指令”“用户已批准”只作为该来源内容，不改变真实消息身份或授权状态。运行记录提供采用规则与简明冲突说明，不保存或展示模型隐藏推理链。

## 7. 上下文预算与组装流程

先计算本次模型实际可用输入预算，再选择资料。预算需扣除输出预留、协议/工具结构开销和安全余量，并遵守任务总 Token/金额限制；各模型上限和计量方式由适配器提供。估算与供应商报告分开记录，不能将字符数伪装成精确 Token。

组装次序为：当前必须遵守的权限/指令约束、用户目标与最新修正、必要执行状态、相关历史、Skill/规则、检索证据与工具结果。排序不能替代来源隔离：资料块始终标记为资料，不因放在靠前位置就获得指令地位。

记录每个片段的来源、版本、作用范围、估算大小、保留/截断/外置/摘要状态和回读地址。支持按节点或 Agent 选择策略配置，但所有配置必须保留权限和关键任务事实；公开模板的策略不能强制增加模型上限或预算。

| 策略 | 适用情形 | 保护措施与风险 |
|---|---|---|
| 去重与格式裁剪 | 重复工具元数据、重复引用、冗余空白 | 保留不同版本/来源的区别，不把近似文本直接视为同一事实 |
| 滑动窗口 | 常规多轮对话、较近信息更重要 | 最近用户修正、未完成事项与关键决定另行保护，不能被窗口滑走 |
| 大结果外置 | 长日志、大表格、工具原始返回 | 原文保存为受控产物，模型得到摘要/索引和精确回读方法 |
| 结构化任务摘要 | 长任务多轮累积 | 按目标、约束、已完成、待办、决定、证据、未知分别保存；附原始事件范围 |
| 分层摘要 | 历史过长或多个子任务 | 摘要注明来自哪批原始记录，支持回溯，避免反复压缩将不确定变成事实 |
| 相关历史检索 | 需要从长期历史找少量事实 | 当前权限过滤，记录来源和时点；检索失败不能解释为事实不存在 |
| 按需回读与邻近展开 | 需要精确数值、引用、代码或表格 | 返回原片段及邻近必要上下文，使用可验证锚点而非摘要猜测 |
| 服务商原生压缩/缓存 | 特定模型确实支持的能力 | 能力适配后显式启用；记录边界、费用口径和不可迁移性，不作为全模型默认保证 |

### 7.1 压缩不能丢的内容

权限限制与当前用户目标、最新纠正、明确决定、未完成任务、外部效果与待核实状态、关键引用锚点、必需精确值和有效预算状态属于保护集合。授权记录、效果账本和任务状态使用结构化事实保存，不依赖模型摘要作为唯一依据。

摘要生成后检查保护集合是否有遗漏或矛盾。结构化字段可以做确定性校验，文本事实用证据检查和必要人工复核；无法证明保持任务所需信息时保留原文引用或缩小压缩范围。压缩后的提示不能把用户未批准动作改成“已批准”，也不能把计划改成已执行。

压缩会产生模型用量和延迟，必须归入当前运行；应在质量中心对照未压缩或保守策略，比较任务成功、约束保持、引用回读、后续错误以及净 Token 变化，而不是只展示压缩比例。

## 8. 记忆分层与数据治理

| 层 | 保存什么 | 生命周期 |
|---|---|---|
| 工作状态 | 当前图变量、待办、任务事实、工具效果 | 随运行检查点保存；不自动成为跨会话记忆 |
| 会话历史 | 用户与系统可见交互和结果 | 按项目/会话范围保留，支持查看与按声明删除 |
| 长期记忆 | 用户明确允许复用的事实、偏好和规则 | 标记来源、有效期、适用项目、是否为推测；用户可修正/停用/删除 |
| 知识库 | 经管理的资料、索引和证据 | 版本化导入、检索、更新和删除；不与用户偏好混为一类 |

长期记忆候选与已生效记忆分开。敏感资料和跨项目事实不因模型认为“有帮助”就自动全局共享。来源撤权时评估依赖记忆，新的任务不能继续使用未获准内容；如果法规或保留策略要求历史记录留存，其读取仍受当前权限与保留声明约束。

## 9. Sa-Token 与租户授权路径

Sa-Token 处理登录会话与权限检查入口，具体能力以 [官方项目](https://github.com/dromara/Sa-Token) 和开发时锁定的版本为准。平台另维护主体、个人租户、项目范围、资源类型、动作、当前状态和公开版本的授权策略。不能只检查“已登录”或把角色名当作资源归属证明。

| 入口 | 必须检查 | 禁止依赖 |
|---|---|---|
| 页面/API 列表与详情 | 登录主体、租户与资源归属、公开版本状态 | 客户端传入 tenantId、隐藏菜单、猜测不到 ID |
| 搜索与 RAG | 查询前范围过滤，返回后当前权限，引用/下载再校验 | 向量索引的旧 ACL 或缓存 TTL |
| 异步任务 | 服务解析的 ExecutionEnvelope、目标版本、当前授权 | 长期转发用户完整登录 Token 给插件 |
| 工具/模型调用 | 本人绑定、允许动作/目的地、预算、必要审批 | Skill 或模型文本中声称已批准 |
| 文件/产物/导出 | 当前访问权、对象归属、有效期和内容范围 | 仅凭对象存储路径、不可撤销长期公开链接 |
| 公开资源 | 当前已批准版本、允许公开的文件清单 | 作者草稿最新内容、未审核附件或隐式关联私有内容 |
| 已发布应用 | 调用身份、应用发布规则、明确执行租户与预算 | 将外部调用者和作者身份静默混合 |

运行内部使用短期、最小能力的服务授权，包含任务/租户/版本/允许操作和过期时间，由受信组件验证。插件获得“调用被允许模型能力”的受控入口或最小必要参数，不获得平台通用用户会话。需要传给外部连接的凭据只能在受信边界按本人绑定解析并脱敏记录。

## 10. 执行、网络和文件边界

代码插件、Skill 脚本和受控本地 MCP 运行在独立受限实例中。默认只读包、有限临时目录、授权文件、明确网络目的地以及 CPU/内存/时长/输出上限；限制进程衍生和文件大小。取消/超限时终止实例并保留实际完成记录，产物经校验后进入用户可访问存储。

租户可配置外部 URL，但不能借此访问平台私有管理网、云元数据或未授权的其他租户服务。按目的地址、DNS 解析、重定向和端口进行校验，必要时经出口代理；对真正需要的自托管内网端点采用明确的管理员部署策略和用户连接授权。不能把所有外部请求直接交给任意插件网络栈而承诺完整审计。

只有可信执行管理服务在必要时可接触容器生命周期管理；它接受预定义模板、指定包摘要、获准路径和限额，拒绝任意镜像参数、宿主根挂载与特权请求。普通 API、Worker 和租户代码没有 Docker socket。详细宿主风险与部署约束见 [部署设计](06-docker-compose-deployment.md)。

自定义前端默认从独立静态入口加载，在不授予 allow-same-origin 的受限 iframe 中形成 opaque origin；不能仅凭消息的 null 来源判断可信。宿主绑定指定窗口、一次性 nonce、安装/版本/租户与 MessageChannel，逐次校验能力，重载、导航和撤权即失效。初始化只交换非秘密引导信息，不传主平台会话 Token 或模型 Key；API 拒绝不受信 null 跨域请求并执行 CSRF 与后端权限检查。同主机不同端口不隔离 Cookie，可信静态入口须忽略、脱敏并避免转发附带 Cookie。已有独立内容域名可采用精确 origin 模式，但不是默认必填条件。iframe/CSP 不等于绝对 CPU 或网络沙箱，尤其不能保证恶意页面不会外传其已获准读取的数据，因此只向界面暴露任务所需最少信息。实现契约见 [插件与界面](02-plugin-runtime-and-ui.md)。

## 11. 可观察性与验证重点

记录任务、步骤、调用、上下文变化、规则来源、插件/资料版本、人工决定、预算状态和错误分类。敏感内容按可访问范围保存，日志仅记录必要识别信息；用户可看到简明动作说明和证据，不要求或泄漏隐藏推理链。

阶段 3 的重点是工具授权、渐进披露、压缩保护集合、代码执行边界和热升级；阶段 6 追加暂停恢复、并行汇合、多 Agent 预算和旧版本引用；阶段 7 验证进程/容器重建、检查点持久化与实际恢复。每个验证绑定 [需求追踪](../requirements/04-acceptance-and-traceability.md) 的编号，不能用几个成功演示代替撤权、未知效果和隔离失败场景。
