# 开发 Issue 填写模板

> 本文件是手工填写模板。复制正文到 GitHub Issue，替换所有尖括号占位内容；没有发生的检查和验收保持未完成状态。
>
> 适用：功能、缺陷、文档任务。总规划 Issue 使用持续追踪清单，不使用本模板冒充已经拆分完的全部工作。

## 填写要求

以下正文的“任务归属、背景、范围、验收标准、依赖、完成证据”必填。尚不适用的字段写明原因，不留含义不明的空白。Issue 标题建议为 `[阶段编号][类型] 用户可观察的交付结果`。

一项任务只包含一个可独立验收的目标。需求过大时先拆分；如果只覆盖某项需求的一部分，明确该部分及其余 Issue 的去向。

## 验收标准

使用可实际执行和观察的描述，不能只写“功能正常”“体验良好”。

- [ ] `<验收项编号>`：在 `<前置条件>` 下，用户 `<执行操作>` 后，得到 `<可观察结果>`。
- [ ] `<验收项编号>`：遇到 `<异常或边界>` 时，系统 `<必须表现>`，且不会 `<禁止发生的结果>`。
- [ ] `<验收项编号>`：在 `<适用权限或预算>` 下，行为符合 `<对应要求>`；不适用时说明原因。

## 关闭前核对

- [ ] 对应 PR 已合并到 `main`，合并结果已确认。
- [ ] 本 Issue 的全部必需验收项已完成，且有证据。
- [ ] 相关需求文档和验收映射已更新。
- [ ] 总规划 Issue 已更新；尚未完成的其他需求保持原状态。
- [ ] 存在范围调整时，明确记录负责人决定和剩余工作的去向。
