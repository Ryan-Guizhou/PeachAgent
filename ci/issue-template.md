# 开发 Issue 模板

> 版本：v0.2 · 更新：2026-11-23
>
> 供 AI 或开发者按已确认依据填写。尖括号须替换；未执行的验收不勾选。本文件不触发自动创建 Issue。

## 任务归属

| 项目 | 必填内容 |
|---|---|
| 稳定任务编号 | `<阶段任务编号，重复拆分时据此查找已有 Issue>` |
| 总规划 | `Refs #1` |
| 所属阶段 | `<1—7 及阶段名称>` |
| 类型 | `<功能 / 缺陷 / 文档 / 部署交付>` |
| 需求与验收 | `<稳定需求编号、验收项编号、文档链接和采用版本>` |
| 设计依据 | `<适用技术文档、已确认设计决定；不适用写原因>` |
| 当前状态 | `<待开发 / 开发中 / 阻塞 / 待验收；记录真实状态>` |
| 来源与历史 | `<新建原因、替代或拆分的已有任务；没有则写无>` |

## 用户结果与背景

`<用户遇到什么问题，本 Issue 完成后能够完成什么；不要只写某模块 CRUD。>`

缺陷额外填写复现条件、操作、预期与实际结果、影响范围。需求变化任务说明原行为、变更依据和旧验收结论的适用范围。

## 范围与衔接

- 范围内：`<明确功能、异常和输出>`。
- 范围外：`<不在本任务的内容及后续归属；不能排除必需验收项>`。
- 涉及模块／扩展：`<相关技术边界；插件任务说明配置、代码、前端中哪部分>`。
- 与现有能力衔接：`<调用、数据、版本或界面的协作要求>`。
- 适用共性要求：`<租户隔离、BYOK、公共版本审批、预算、恢复等需求编号；不适用说明原因>`。

## 验收条件

- [ ] `<验收编号>`：给定 `<条件和输入>`，执行 `<操作>`，应得到 `<可核验结果>`。
- [ ] `<验收编号>`：遇到 `<失败或边界>`，系统 `<必须行为>`，且不会 `<禁止结果>`。
- [ ] `<验收编号>`：按 `<适用权限／凭证／预算／版本>` 验证 `<结果>`。

## 依赖与并行

| 前置任务或决定 | 真实阻塞条件 | 当前证据 | 满足后可开始的范围 |
|---|---|---|---|
| `<关联 Issue 或明确无依赖>` | `<需要哪个结果，不写笼统“等全量 CI”>` | `<当前状态>` | `<范围>` |

可并行的独立任务：`<任务及共享文件／接口协调约束；没有则说明>`。

## 完成证据

| 证据 | 交付要求 | 实际记录 |
|---|---|---|
| 变更 | 对应 PR、已验证提交、合并后的 main 提交 | `<完成后填写>` |
| 构建 | 真实目录、命令、结果；纯文档说明不适用 | `<完成后填写>` |
| 功能 | 正常及必要异常场景、输入与实际结果 | `<完成后填写>` |
| 衔接 | 受影响的前期功能或插件版本验证 | `<适用时填写>` |
| 部署 | 对部署交付任务给出实际目标环境和运行证据 | `<适用时填写>` |
| 文档 | 需求、设计、使用说明与追踪变更 | `<完成后填写>` |

## 问题与关闭条件

遗留问题和新事项：`<关联记录；当前必需范围未完成时不能关闭>`。

- [ ] 一份对应 PR 已合并 main，合并结果已核对。
- [ ] 必需验收全部满足，证据与实际交付一致。
- [ ] 需求追踪及总规划已更新，其他未完成项保持真实状态。
- [ ] 范围调整或延期有明确决定和去向，旧记录未被覆盖。

规则见 [AI 执行指南](ai-execution-guide.md)与[开发流程](README.md)。
