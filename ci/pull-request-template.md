# Pull Request 填写模板

> 本文件是手工填写模板。复制到 PR 正文并替换尖括号内容。只勾选已经完成的事项，保留真实失败或未验证结果。
>
> 一项开发 Issue 对应一份 PR，目标分支为 `main`。

Refs #<总规划Issue编号>

- 所属阶段：`<阶段编号与名称>`
- 需求编号：`<本 PR 实际覆盖的需求编号>`
- 验收项编号：`<对应的具体验收项>`

## 验证记录

被验证的提交：`<实际提交 SHA>`

| 检查 | 实际执行内容 | 结果 | 证据 |
|---|---|---|---|
| 变更复查 | `<检查范围和结论>` | `<通过 / 失败 / 未执行>` | `<记录或链接>` |
| 编译或构建 | `<工作目录、仓库真实命令和必要环境>` | `<真实结果；仅文档可写不适用及原因>` | `<日志摘要或链接>` |
| 主要用户场景 | `<输入、操作、预期与实际结果>` | `<真实结果>` | `<记录或链接>` |
| 必需异常与边界 | `<与此次改动相关的场景>` | `<真实结果；不适用需说明>` | `<记录或链接>` |
| 文档一致性 | `<链接、需求映射、图表、项目状态等检查>` | `<真实结果>` | `<记录或链接>` |

没有执行的检查不能写“通过”。代码变更不得以“环境问题”“后续补测”或文档检查替代构建通过。纯文档且无可编译内容时，明确写“编译不适用”，不得写“编译通过”。

## 合并前核对

- [ ] 变更符合关联 Issue 范围，没有未经记录的需求扩展。
- [ ] 变更已检查，没有尚未修复的明显错误。
- [ ] 包含代码时，实际编译或构建通过；仅文档时写明不适用原因。
- [ ] 本 Issue 必需验收项全部满足，证据对应当前提交。
- [ ] 没有未解决的合并冲突，冲突处理后已重新复查。
- [ ] 相关文档、需求映射和阶段状态与事实一致。
- [ ] 没有敏感数据、密钥或无关临时文件。
- [ ] 总规划 Issue 只被关联，不会因本 PR 自动关闭。
