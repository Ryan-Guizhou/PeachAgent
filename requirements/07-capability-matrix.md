# 能力完整性矩阵

> 版本：v0.2 · 更新：2026-11-23 · 状态：完整版本承诺范围的索引；不是实现进度或功能通过率。

本矩阵用于避免“计划中出现过，但详细需求与交付没有包含”的缺口。内置能力必须随平台交付，不允许要求用户自己开发插件才能完成基本路径；扩展点允许用户增加业务能力，不代表平台默认具备所有外部服务或算法。阶段列表示首次提供及完整收口时间。

## 1. Studio 与资源开发

| 能力 | 内置必须提供 | 可扩展范围与明确边界 | 阶段 / 需求依据 |
|---|---|---|---|
| 个人空间和项目 | 个人租户、多项目、项目资料管理、账号状态 | 不以企业组织或套餐作为功能入口 | 1，6 管理收口；[P1](phases/phase-01-project-and-chat.md)、[P6](phases/phase-06-publishing-and-operations.md) |
| BYOK 模型 | 多连接、能力说明、验证、参数、停用和本人凭证绑定 | 新供应商可适配；不隐式使用平台公用 Key | 1；PA-P1-003、PA-P1-004 |
| 对话与 Prompt | 流式交互、历史、变量模板、版本、调试 | 可共享模板；自动优化在质量中心验证 | 1，5，6；PA-P1-005、PA-P1-006、PA-P1-007、PA-P5-010 |
| 工作流画布 | 拖拽、连线、参数、变量、校验、版本、调试、导入导出 | 自定义节点必须遵守统一输入输出、运行与授权规则 | 2；[P2](phases/phase-02-visual-workflow.md) |
| 复杂编排 | 条件、子流程、循环、并行汇合、人工介入和错误处理 | 不支持的图提前拒绝；不承诺任意递归无限执行 | 2 基础，6 完整；[P2](phases/phase-02-visual-workflow.md)、[P6](phases/phase-06-publishing-and-operations.md) |
| Agent 设计 | 指导、模型、工具范围、执行模式、完成标准 | 可调用工作流和子 Agent，范围继承而不放大权限 | 3，6 协作；PA-P3-001、PA-P3-002、PA-P3-013 |
| MCP | 连接、发现、能力选择、授权、调用、变化和失效提示 | 远程与受控本地连接按兼容能力提供；公共模板不附带作者授权 | 3，6 增强；PA-P3-003 至 PA-P3-005、PA-P6-007 |
| Skill | 导入、编辑、版本、简介索引、正文/资料按需读取、脚本授权 | 来源可扩展；附属内容不能自授权限 | 3；PA-P3-006、PA-P3-007、PA-P3-015 |
| 项目规则 | AGENTS.md 等来源读取、目录作用范围、采用记录与冲突说明 | 用户明确偏好可覆盖普通建议；平台权限和预算不被文档覆盖 | 3；PA-P3-008、PA-P3-009 |
| 插件开发 | 清单、示例、调试、打包、版本、安装和诊断 | 工具、节点、模型连接、知识处理、评测器及界面扩展 | 1–6；[插件专题](topics/01-plugin-system.md) |
| 两类插件界面 | 统一表单、受控自定义配置/调试/结果/扩展页面 | 自定义界面不能读取主平台会话凭证或覆盖审核/授权 | 2–6；PA-P2-015 至 PA-P2-017、[插件专题](topics/01-plugin-system.md) |

## 2. Runtime、上下文与记忆

| 能力 | 内置必须提供 | 边界与完成依据 | 阶段 / 需求依据 |
|---|---|---|---|
| 实际运行与观察 | 工作流与 Agent 统一记录、步骤状态、结果、错误、产物和用量 | 模型宣称完成不等于操作完成 | 1–3；PA-COM-005、PA-COM-012、PA-P3-014 |
| 取消、失败和重试 | 取消停止新动作，部分结果、结果未知、重复影响处理 | 不承诺外部写入天然恰好执行一次或取消退款 | 1–6；PA-COM-005、PA-COM-006 |
| 长任务与恢复 | 关闭页面后可回看，持久等待、恢复核验、人工决定 | 恢复保留原版本，当前撤权仍生效 | 6；PA-P6-003、PA-P6-004 |
| 动态代码插件 | 安装、启用、升级、降级、停用和卸载 | 不重启全部 Runtime；受影响实例可替换；旧引用不能静默迁移 | 3，6/7 联验；PA-P3-015、PA-P3-016、[插件专题](topics/01-plugin-system.md) |
| 受控代码和脚本 | 基础代码隔离、授权文件/网络、资源限制、产物管理 | 不能等阶段 6 才补基础安全边界 | 3 基础，6 强化；PA-P3-015、PA-P6-006 |
| 上下文装配 | 来源、容量、采用/未采用内容可解释，输出预算预留 | 资料、工具结果与授权规则区分 | 3；PA-P3-010 |
| 压缩策略 | 去重、窗口、结构化摘要、结果外置与按需回读、分层整理 | 保留目标、约束、待办、决定和证据引用；不能只以省 Token 判好坏 | 3，5 评测；PA-P3-011、[P5](phases/phase-05-quality-prompt-cost.md) |
| 记忆 | 工作中状态、会话历史、明确授权长期记忆、查看/改正/删除 | 记忆有范围和来源；与知识库区分 | 3；PA-P3-012 |
| 多 Agent | 分工、任务传递、并行/汇合、预算继承与错误终止 | 子 Agent 不自动获得父任务未授予的资料和工具 | 6；[P6](phases/phase-06-publishing-and-operations.md) |

## 3. 知识、RAG 与质量

| 能力 | 内置必须提供 | 可扩展范围与评价依据 | 阶段 / 需求依据 |
|---|---|---|---|
| 知识导入 | 文本及常见文档、基础扫描件/表格、处理预览、错误定位 | 复杂格式通过解析插件扩展，支持格式清单必须真实 | 4 文本基础，6 扫描/表格收口；PA-P4-001 至 PA-P4-005、PA-P6-011 |
| 知识生命周期 | 当前版本、更新失败保留可用版、撤权、删除和引用来源 | 旧索引和缓存不能绕过当前访问范围 | 4；PA-P4-004、PA-P4-012 |
| 切分与候选检索 | 结构分段、关键词/语义/混合、过滤、去重、可调候选数 | 语言/语料适配；方案都需对照验证，不能保证总是提升 | 4；PA-P4-005 至 PA-P4-008 |
| 查询理解与证据组合 | 查询改写、多个查询、问题拆解、相邻/父级证据补充 | 用户控制开销；记录实际检索语句和证据变化 | 4，6 增强；[P4](phases/phase-04-knowledge-and-rag.md)、PA-P6-011 |
| 重排与最终上下文 | 候选排序、证据选择、去重、上下文预算与引用 | 重排不能找回未进入候选的证据；输出排序改善需独立记录 | 4；PA-P4-008、PA-P4-009 |
| RAG 调试 | 原文→处理→候选→排序→上下文→回答全过程 | 区分解析缺失、过滤、召回、排序、截断和生成错误 | 4；PA-P4-010、PA-P4-011 |
| 数据集 | 任务、答案/证据、无答案、多证据、权限案例、开发/检验划分 | 未完整标注需显式说明；跨切分比较使用稳定原文单位 | 5；PA-P5-001 至 PA-P5-003 |
| RAG 指标 | 候选/最终结果的 Recall、Hit、排序与上下文覆盖分开 | 固定语料/样本/权限/K，展示逐题变化、退化和成本 | 5；PA-P5-004 至 PA-P5-009 |
| 项目与 Agent 评测 | 业务任务成功、工具行为、答案/引用、可靠性、时长、费用 | 不用单一大模型评分代表全部质量；人工可复核 | 5；[P5](phases/phase-05-quality-prompt-cost.md) |
| Skill/压缩/插件评测 | 选择和读取是否正确，关键事实是否保留，插件契约和权限是否满足 | 改进需要效果、稳定性和开销共同解释 | 5；[P5](phases/phase-05-quality-prompt-cost.md) |
| Prompt 优化 | 基线、候选、差异、开发集、独立检验、人工采用与回退 | 不在保留集上反复优化；预算不足可停并保留基线 | 5；PA-P5-010 |
| 高级知识研究 | 平台预留扩展点 | 全量 GraphRAG、专用训练、完整视频/音频理解不列为首版默认完成条件 | 后续研究；当前基础扫描件、表格、多资料仍必做 |

## 4. Operations 与部署

| 能力 | 内置必须提供 | 边界与完成依据 | 阶段 / 需求依据 |
|---|---|---|---|
| 身份与授权 | Sa-Token、个人租户归属、当前权限校验、管理员分权 | 登录成功不等于任意资源访问；导出/搜索/插件/任务均继承范围 | 1–7；PA-COM-001、PA-COM-002 |
| Token 面板 | 个人、项目、应用、运行、模型、时间、来源分类和明细 | 报告值/估算/未知区分，缓存与推理 Token 子项不重复相加 | 1 基础，5 完整，6 发布来源；[P1](phases/phase-01-project-and-chat.md)、[P5](phases/phase-05-quality-prompt-cost.md) |
| 预算与资源限制 | 调用、Token、时间、并发和适用金额预算，子任务继承 | 并发额度受控；已发出请求的未知费用不伪装成精确封顶 | 1–6；PA-COM-004 |
| 公共资源仓库 | 应用、插件、Skill、MCP、Prompt 分类，版本、检索、详情、安装/复制 | 所有人可提交，管理员按版本审核，批准后所有正常用户可见 | 6；[公共仓库专题](topics/02-public-repositories.md) |
| 公开版本治理 | 驳回/修改/重新审核、下架、举报、安装影响和可追溯记录 | 审核不携带作者 Key，不自动信任可变外部服务 | 6；[公共仓库专题](topics/02-public-repositories.md) |
| 应用发布 | Web/API/Webhook、版本与依赖、访问方式、执行身份、用量和停用/回退 | 公共模板与在线执行入口分开；对外调用有认证、限制与记录 | 6；[P6](phases/phase-06-publishing-and-operations.md) |
| 基本运营 | 账号状态、平台健康、任务异常、配额、私有数据生命周期 | 管理员不是默认全数据读者；操作可追溯 | 6；[P6](phases/phase-06-publishing-and-operations.md) |
| Docker Compose | 正式镜像、配置样例、初始化、预设挂载、健康状态、一条启动命令 | 仅填数据库/中间件密码；用户模型 Key 在登录后配置 | 7；[P7](phases/phase-07-docker-compose-deployment.md) |
| 持久化与恢复 | 数据、插件/界面包、密钥、产物等保存，备份与新环境恢复、升级方案 | 挂载不等于备份，容器重建不等于恢复验证，回退需考虑数据兼容 | 7；[P7](phases/phase-07-docker-compose-deployment.md) |

## 5. 完成判定

AI 拆分任务时逐行检查对应详细需求和专题是否已有 Issue。发现矩阵与正文不一致时，以用户已经确认的目标为约束补齐文档，不能靠省略一行解决冲突。功能验收结果进入 [追踪表](04-acceptance-and-traceability.md) 和总 Issue；文档行数、提交数和 PR 数量不能作为产品完成比例。
