# 阶段 7：Docker Compose 一键部署与完整交付

> 版本：v0.2 · 更新：2026-11-23
>
> 状态：已确认交付方向下的需求细化；产品功能、部署包和验收结果尚未实现。
>
> 路线位置：阶段 1—6 完成完整平台，本阶段将全部已确认能力交付为可部署、可验证、可维护的单主机版本。
>
> 本文只规定部署者与使用者获得的结果；配置、服务、端口、目录和启动设计见技术文档。

## 1. 背景与目标

平台不能只在开发者电脑上运行，也不能把安装数据库、编辑多个服务地址、手写初始化内容和补挂载的工作留给使用者。用户已经明确：正式交付只考虑 Docker、Docker Compose；部署者自行配置数据库和中间件密码，其余必要服务、初始化及挂载由交付包准备好。

本阶段目标是：在公布的单主机 Linux 环境准备好 Docker Engine 与 Compose 插件，取得正式交付包并填写必要密码后，通过一次约定启动操作完成平台准备。用户随后登录界面，配置自己的模型和工具 Key，即可使用前六阶段的全部能力。部署完成不代表已经提供共享模型凭证，也不保证外部供应商始终可用。

## 2. 范围与前置条件

| 内容 | 本阶段要求 |
|---|---|
| 正式目标 | 单主机 Linux，Docker Engine 与 Compose 插件；发布说明给出实际验证的环境和机器条件 |
| 操作者必填 | 数据库和中间件秘密；不要求自行确定服务拓扑、容器地址、数据库建表或数据挂载 |
| 平台自行准备 | 必需服务、初始化、默认目录和端口、健康检查、必要技术密钥及持久化、诊断和维护入口 |
| 部署后个人配置 | 各用户在 UI 配置自己的模型与工具凭证，费用和调用归属不混淆 |
| 完整范围 | 六阶段产品、动态插件及自定义前端、个人租户、公共资源审批均在正式部署版本中验收 |
| 非本期目标 | Kubernetes、多主机调度、多区域容灾、商业计费、让部署者自行维护镜像构建平台 |

前置条件是：平台及依赖的可获取镜像和交付文件已提供；宿主机器具备公布的资源、磁盘、网络和操作权限。不能将“一次启动”宣传为零前置或适用于任意机器。Windows Docker Desktop 可以提供开发体验说明，不作为另一个未经验证的正式交付平台。

## 3. 角色与场景

| 角色 | 场景 | 期望结果 |
|---|---|---|
| 部署负责人 | 在新服务器安装平台 | 填必要密码后按一个入口启动，不临时补服务或挂载 |
| 首个管理员 | 初始化平台并管理公共资源 | 安全建立账号，能审核指定资源版本，未审核版本不公开 |
| 个人用户 | 使用全部平台能力 | 登录个人租户，在界面配置自己的 Key，资料和凭证与他人隔离 |
| 扩展开发者 | 安装升级带代码和前端的插件 | 无需修改整个平台部署文件或重启全部运行服务 |
| 运维负责人 | 重启、备份、恢复和升级 | 有明确操作与证据，数据、凭证及版本关系不会被静默破坏 |

## 4. 详细需求

### PA-P7-001 支持范围与前置检查

- **场景与前置条件：**部署者准备一台用于安装平台的服务器。
- **要求：**交付说明列明支持的操作系统与 CPU 架构、Docker 和 Compose 范围、已验证的 CPU、内存、磁盘及数据规模。启动前检查工具是否可用、必要镜像能否取得、密码是否填写、端口是否占用、目录是否可写及空间是否满足已知要求。
- **异常与边界：**不满足条件时清楚说明具体问题和处理方式，不继续产生难以解释的半完成状态；未测试环境不能标为已支持。检查不能擅自清除原目录、修改无关宿主设置或开放更多端口。
- **验收 PA-P7-001-A1：**在一个受支持新环境中检查通过；人为缺少 Compose、阻断镜像获取或占用入口时，分别给出可理解结果。
- **验收 PA-P7-001-A2：**对磁盘不足、目录不可写和未填写密码，启动在造成不可恢复更改前拒绝或明确停止，不删除原有资料。

### PA-P7-002 完整交付包与一次启动入口

- **场景与前置条件：**部署者已满足公布条件，取得与目标版本一致的交付包。
- **要求：**交付包包含必需部署定义、默认配置、秘密填写示例、启动和维护入口、初始化资料、健康检查以及使用说明。填完必要密码后，一次启动操作完成目录准备、依赖启动、初始化和就绪检查；用户无需另装数据库或手写服务地址、建表内容、挂载配置。
- **异常与边界：**镜像和文件缺失、版本不匹配或初始化失败时，应说明完成到哪里、如何继续；不得把仅部分容器启动标为平台可用。首次拉取镜像仍受网络条件影响。
- **验收 PA-P7-002-A1：**由没有项目源码开发环境的操作者按正式说明部署，除前置条件和必要密码外不需临时补配置，能进入平台。
- **验收 PA-P7-002-A2：**故意遗漏一个必要交付文件时能够检测并定位，不能继续给出整体启动成功结论。

### PA-P7-003 区分中间件密码、平台秘密与个人 Key

- **场景与前置条件：**部署者填写安装秘密，个人用户随后配置自己的外部服务。
- **要求：**说明哪些数据库和中间件密码必须由部署者设置；平台内部需要的密钥和服务身份可在首次启动安全生成并持久保留。模型、工具及其他外部能力的个人凭证在部署后由所属用户通过 UI 配置，不作为管理员替所有人填写的安装参数。
- **异常与边界：**不能交付公开通用密码、把空密码当默认成功或将个人 Key 写入共享配置。秘密在状态输出和诊断资料中隐藏；重启不能生成不兼容的新密钥使既有个人凭证失效。
- **验收 PA-P7-003-A1：**只填写规定的中间件密码即可完成平台启动；未填写任何模型 Key 时仍能访问平台并进入个人配置入口。
- **验收 PA-P7-003-A2：**重启后原有秘密和个人凭证关系保持有效，普通日志、公共资源及导出中没有完整秘密。

### PA-P7-004 首次管理员引导与重复初始化

- **场景与前置条件：**空数据目录上的平台第一次启动。
- **要求：**提供仅能由有权部署者取得的一次性管理员建立方式；不公开固定初始管理员密码。建立管理员后引导失效，普通用户不能通过重复初始化取得管理员身份。再次启动识别既有安装状态，保留账号、设置与版本记录。
- **异常与边界：**初始化中断后可以识别已经完成和仍待完成的步骤；不能因为缺少某个标记就清空数据库重来。引导丢失、过期或已使用时，有明确且受权限控制的处理说明。
- **验收 PA-P7-004-A1：**首次管理员建立成功后，原引导无法再次建立管理员，普通访问者看不到初始化秘密。
- **验收 PA-P7-004-A2：**重复启动及一次可恢复的初始化中断，都不会重置已存在密码、账号或资料。

### PA-P7-005 个人租户和部署后的 BYOK

- **场景与前置条件：**平台已有管理员，两名个人用户准备使用全部功能。
- **要求：**每位用户拥有自己的租户范围，在 UI 中按服务要求维护自己的模型与工具凭证；基础对话、工作流、Agent、知识处理、评测和插件调用按所属用户授权取用凭证。缺少 Key 时说明缺失能力，不影响其他已经满足条件的页面与操作。
- **异常与边界：**公共应用、插件、Skill、MCP 或 Prompt 的版本可见，不代表使用发布者的凭证；不能自动借用管理员或其他用户 Key。故障与余额不足仍归属于实际服务和用户，不能伪装为免费使用。
- **验收 PA-P7-005-A1：**两名用户分别保存测试凭证并运行任务，调用归属、费用和记录正确，彼此无法查看或使用对方秘密。
- **验收 PA-P7-005-A2：**一名用户未配置凭证时，使用公共资源得到明确配置指引，没有调用另一用户或管理员的外部账号。

### PA-P7-006 默认持久化与数据生命周期

- **场景与前置条件：**平台已运行并产生账号、资料、插件及任务结果。
- **要求：**数据库、必要运行状态、搜索内容、对象资料、插件包、自定义前端产物、任务暂存与正式输出、审计日志、平台密钥和备份均有预先配置的位置与管理规则。区分必须保留的数据、可重建内容和到期可清理内容，使用者无需补挂载才能避免重启丢失资料。
- **异常与边界：**普通停止、重启和替换应用版本不删除正式数据；清理暂存不能同时删除已交付产物。平台管理员与个人用户访问范围明确，个人插件不能取得整台服务器的资料目录。
- **验收 PA-P7-006-A1：**产生各类代表性数据后重启，能找回账号、凭证关系、知识、插件与正式输出，内容和权限保持一致。
- **验收 PA-P7-006-A2：**执行暂存与日志清理，只影响已说明且可清理范围；正式资料、平台密钥和备份保持有效。

### PA-P7-007 启动就绪与依赖故障

- **场景与前置条件：**启动过程包含多个依赖服务，某一服务可能延迟就绪或连接失败。
- **要求：**区分容器已启动、依赖可用、初始化成功和平台就绪。只有必要条件满足才显示整体可用；关键依赖失败时指出受影响能力与处理建议。可独立使用的能力不因无关外部模型未配置而全部不可用。
- **异常与边界：**不能只因进程存在就显示所有功能健康；外部模型不可用与平台基础设施故障分开说明。恢复后应重新判断就绪，不继续显示过期错误或假成功。
- **验收 PA-P7-007-A1：**延迟数据库或对象服务就绪，平台等待必要条件或清楚失败，不在未完成初始化时开放正常业务使用。
- **验收 PA-P7-007-A2：**依赖恢复后，状态和实际操作一致；无个人模型 Key 时，系统管理和凭证配置仍可访问。

### PA-P7-008 启停与中断后的真实状态

- **场景与前置条件：**维护者需要停止、再次启动或在主机重启后继续使用。
- **要求：**提供清楚的启停与状态操作；停止前说明进行中的任务如何结束、等待或进入待核实状态。再次启动保持既有安装和个人配置，恢复可安全继续的状态，明确已完成、未完成与结果不确定的任务。
- **异常与边界：**不能在重新启动后盲目重复外部写入、发送消息或其他副作用；未确定结果不能显示成功。重启不重置预算、版本引用或审批结论来绕过限制。
- **验收 PA-P7-008-A1：**完成正常停止和再次启动后，用户继续使用原账号和配置，历史结果保持可查。
- **验收 PA-P7-008-A2：**中断一个可能已产生外部影响的任务，重启后保留待核实事实，不自动重复操作。

### PA-P7-009 状态诊断、日志与资源提示

- **场景与前置条件：**部署者发现无法访问、任务停滞或磁盘消耗增加。
- **要求：**提供查看版本、服务状态、失败原因、任务关联和资源使用情况的入口；常见错误有针对性建议。日志和审计可按已声明方式保留、查看与清理；诊断资料脱敏，个人任务正文仅对有权人员可见。
- **异常与边界：**磁盘、内存或执行额度不足时说明影响，不能无限累积日志和临时文件直至拖垮宿主。无法确认的根因标为待核实，不由模型编造故障结论。
- **验收 PA-P7-009-A1：**对密码错误、依赖未就绪和空间不足分别定位问题，诊断内容没有完整凭证。
- **验收 PA-P7-009-A2：**按说明导出诊断信息并清理可清理日志，能够保留必要审计且不破坏业务资料。

### PA-P7-010 网络、文件与执行权限边界

- **场景与前置条件：**平台允许多名个人用户以及代码插件和任务执行。
- **要求：**默认仅提供平台 Web、自定义前端所需静态入口与确有需要的业务入口，内部数据服务和管理入口不直接向所有访问者开放。默认自定义前端应可使用，不要求部署者额外配置域名或修改主机映射。凭证提交和登录使用受保护连接，说明入口证书的信任方式。个人任务只能访问被授权的资料、网络与资源，不能取得平台秘密或宿主控制能力。
- **异常与边界：**容器化不被宣传为可以绝对隔离任意恶意代码。需要的隔离与越界验证不满足时，该交付不能宣称完整验收；不能靠临时开放全部权限来让示例通过。
- **验收 PA-P7-010-A1：**从外部检查只能访问声明的主站与插件界面等必要入口，无额外域名配置也能使用自定义前端，不能直接访问数据库、搜索后台、对象管理页或执行管理能力。
- **验收 PA-P7-010-A2：**让测试插件尝试越权读取、跨租户访问和超额执行，操作被限制，正常租户仍可使用；个人 Key 不经未保护连接提交。

### PA-P7-011 部署后动态安装与升级插件

- **场景与前置条件：**用户准备安装带配置、代码或自定义前端的插件，或升级已有插件版本。
- **要求：**通过产品约定的安装与审批路径完成获取、验证、授权、启用、升级、禁用与移除；部署包已包含必要执行能力、前端产物管理和持久化条件，不要求管理员手工修改整套部署文件。无需重启全部 Runtime 即可采用新插件版本；旧任务和新任务的版本归属可解释。
- **异常与边界：**安装或升级失败应保留可用旧版本或明确停止受影响能力；不能同时破坏所有租户。公共版本审批只决定可见范围，安装和执行仍受个人授权与 BYOK 限制。
- **验收 PA-P7-011-A1：**在正式部署包中安装带自定义页面及代码能力的插件并升级，不重启全部 Runtime；新旧运行与前端版本可核对。
- **验收 PA-P7-011-A2：**制造无效包或不兼容版本，安装失败有原因和恢复结果，其他租户及无关能力不受无说明影响。

### PA-P7-012 一致备份与可验证恢复

- **场景与前置条件：**维护者需要在故障或迁移前保存完整可恢复状态。
- **要求：**提供可执行的完整备份与恢复流程，说明业务暂停范围、备份时间点、涵盖数据及所需秘密。备份覆盖互相关联的业务记录、对象资料、知识版本、插件与前端产物、必要审计和解密凭证所需信息；在空环境恢复后核对用户、权限、Key 可用关系、资料、插件和关键任务。
- **异常与边界：**持久化目录本身不是备份；备份与原数据放在同一故障设备也不能声称具备独立恢复保障。缺少密钥、内容不完整或版本不匹配时清楚拒绝或标明不能恢复范围，不以文件存在判断成功。
- **验收 PA-P7-012-A1：**在隔离空环境恢复一份完整备份，两名用户的资料和授权正确，已保存个人凭证仍可用于其有权执行的测试任务。
- **验收 PA-P7-012-A2：**移除备份中的密钥或一类必要资料后，恢复检查指出缺失，不能显示完整恢复成功。

### PA-P7-013 版本升级与兼容恢复

- **场景与前置条件：**维护者取得下一版平台交付包。
- **要求：**升级前说明兼容范围、数据变化、插件影响、备份与停机要求；检查目标版本和恢复条件后执行。成功后保留账号、个人 Key、资料与批准版本的正确关系，并验证核心用户路径。升级中断有明确状态和继续或恢复方法。
- **异常与边界：**数据已经变化时，不能仅替换旧应用版本就宣称已安全回退。无兼容恢复条件或未完成必要备份时应明确阻止风险操作。插件迁移失败不能被隐藏为整个升级成功。
- **验收 PA-P7-013-A1：**从实际支持的上一版升级，已有用户、资料、插件和关键路径正常，记录对应版本及证据。
- **验收 PA-P7-013-A2：**在升级失败样例中按文档恢复到匹配的数据与应用状态；未经验证的旧版本组合不会被自动当作可用结果。

### PA-P7-014 前六阶段全功能部署验收

- **场景与前置条件：**部署包完成启动，负责人准备判断整个项目是否达到交付目标。
- **要求：**在正式部署环境逐项核对阶段 1—6 的全部确认需求，并完成个人租户与 BYOK、可视化工作流、Agent/MCP/Skill/规则/上下文、RAG、质量评测、Prompt 优化、预算、多 Agent 和完整插件等实际路径。应用、插件、Skill、MCP、Prompt 的公共版本经管理员审批后可见，私有资料和凭证不随之公开。
- **异常与边界：**不允许仅挑选几条演示隐藏缺失能力；构建通过、容器健康或首页可打开都不能代替完整功能验收。当前未实现的功能应明确列为阻塞，不用“后续可选”改写既定范围。
- **验收 PA-P7-014-A1：**每个前六阶段需求都有正式部署环境中的实际结果或能够证明同一交付内容的有效证据，未验证项明确列出。
- **验收 PA-P7-014-A2：**以两名用户和一名管理员完成全部资源类型的提交、审批、公开使用和隔离验证，并关联总规划中的交付记录。

### PA-P7-015 使用说明、维护与交付结论

- **场景与前置条件：**平台准备交给没有参与开发的人长期使用。
- **要求：**说明安装条件、必填密码、首次管理员引导、个人 Key 配置、默认数据位置、访问与证书、启停、故障定位、备份恢复、升级和安全清理。给出验证过的环境、数据规模及已知单主机限制；正式产物可获取且与文档版本一致。
- **异常与边界：**删除正式数据、卸载或重置安装必须明确影响，不作为普通清理默认动作。没有实际部署和恢复证据时不能声称“已可上线”；不以另建复杂发布平台作为当前交付前置。
- **验收 PA-P7-015-A1：**由独立操作者按说明完成安装、个人配置、使用、重启和一次备份恢复，无需开发者临场补步骤。
- **验收 PA-P7-015-A2：**交付报告列出全部阶段结果、环境和未完成项；任一必需能力未通过时，整体结论仍为未完成。

## 5. 信息、权限与交付约束

部署者保管平台与中间件秘密，不代表可以把个人模型 Key 发布给其他用户。公共资源的可见、安装、执行和调用计费分别遵守审批、租户权限与个人授权。日志、备份和诊断也属于需要保护的资料。

所有阶段继承[共性要求](../03-cross-cutting-requirements.md)。正式部署的容量数字须由真实样例验证后公布，本版不虚构吞吐量、机器最低配置或恢复时间承诺。

## 8. 实施前需固定的验证资料

正式支持的宿主发行版、架构、Docker/Compose 版本与镜像摘要；实际机器和数据规模；验收用个人 BYOK 服务；证书信任与公网定制说明；默认保留、清理、备份目标及可接受维护窗口。它们是落实既定部署目标所需的验证记录，不重新询问是否采用 Docker Compose 或是否只配置必要密码。
