# 阶段 3：Agent、MCP、Skill 与上下文管理

> 版本：v0.1 · 日期：2026-11-23
>
> 状态：需求草案，待项目负责人确认；本文件中的功能尚未实现。
>
> 交付位置：六阶段路线图的第 3 阶段；依赖阶段 1、2 的运行、权限、限额与流程能力。
>
> 本文说明产品行为、资料边界与验收结果，不确定执行框架、协议版本、存储或压缩算法。

## 1. 背景与阶段目标

固定流程适合步骤已知的任务；面对需要先理解目标、寻找资料、选择工具并反复核对结果的任务，用户还需要具备有限自主行动能力的 Agent。与此同时，不能把所有工具说明、Skill 全文、项目规则和历史对话持续塞入每次任务，也不能让外部资料自行决定用户授予了什么权限。

本阶段交付一个可配置、可运行、可解释的 Agent：使用明确授权的工具；按需要读取 Skill 和项目规则；管理上下文长度；在步骤、时长和费用范围内结束；输出可核对的结果与证据。复杂人工等待、隔离脚本执行和长任务恢复在阶段 6 继续建设。

### 1.1 范围与概念

| 概念 | 用户可获得的能力 | 本阶段边界 |
|---|---|---|
| Agent | 按任务目标选择获准行动并输出结果 | 单 Agent、有限步骤；不承诺无限自主完成任何任务 |
| MCP | 连接外部服务，发现并使用获准工具 | 优先覆盖远程服务；不直接开放本地任意程序启动 |
| Skill | 复用任务方法、参考资料与模板 | 支持导入、版本和按需读取；可执行脚本留到阶段 6 |
| 项目规则 | 根据当前项目与目录读取适用约定 | 必须说明来源、适用范围和冲突处理 |
| 上下文 | 当前任务可供模型参考的材料 | 支持预算、选择、压缩及获准原文回读 |
| 记忆 | 用户明确允许保留的事实或偏好 | 可查看、修改、停用和删除；不默认记住所有对话 |

### 1.2 角色与场景

| 角色 | 场景 | 预期结果 |
|---|---|---|
| Agent 开发者 | 组合模型、指导、工具和 Skill | 创建一个用途清楚、权限有界的 Agent |
| 项目成员 | 让 Agent 阅读项目资料并完成分析 | 输出结论、引用材料、已完成动作和剩余问题 |
| 项目负责人 | 接入工具服务并限制使用范围 | 工具发现、授权和真实调用都可核对 |
| 长对话使用者 | 多轮任务逐渐积累大量内容 | 核心目标、约束与待办不会因为压缩而丢失 |

## 2. 详细功能需求

### PA-P3-001 Agent 资产与运行模式

- **场景与前置条件：** 开发者已经拥有可用模型和项目权限，准备创建特定用途的助手。
- **要求：** 可设置名称、用途、任务指导、模型、获准工具、Skill、记忆范围和任务限额，并保存明确版本。提供 Chat、Plan、Act、Auto 等有清楚含义的模式：对话答疑、形成计划、执行已授权计划、在授权范围内自主推进。启动前显示所选模式与实际可用能力。
- **异常与边界：** 模式名称不产生额外权限；切换到 Auto 不能获得全部工具。Plan 可使用获准只读资料辅助规划，但不能执行对外修改。已开始任务的权限范围不能因编辑另一个版本而悄悄扩大。
- **验收：** PA-P3-001-A1：同一目标在 Plan 模式只形成计划及必要资料记录；PA-P3-001-A2：Auto 模式只能使用已授权能力；PA-P3-001-A3：修改 Agent 后，旧运行仍可识别当时版本与模式。

### PA-P3-002 有限多步行动与进度反馈

- **场景与前置条件：** 任务需要查询资料、调用工具、判断结果后继续下一步。
- **要求：** Agent 可在已设定限制内连续完成多个步骤，展示当前目标、简要行动说明、已经执行的动作、当前结果和剩余工作。用户可查看计划更新及其原因，主动停止任务。重复失败、持续无进展或达到次数、时长、费用限制时应结束并解释原因。
- **异常与边界：** 不能依靠不断重新规划绕过步骤限制；工具失败不能直接当成业务成功。模型给出的文字计划与真实动作应分开展示。任务被停止后，不继续主动发起新的动作。
- **验收：** PA-P3-002-A1：完成一个至少包含两次不同获准动作的任务并展示进度；PA-P3-002-A2：重复失败的任务按已声明限制结束；PA-P3-002-A3：用户停止后，最终结果明确说明完成与未完成部分。

### PA-P3-003 MCP 服务接入与能力发现

- **场景与前置条件：** 负责人获得可使用的远程 MCP 服务，希望让 Agent 使用其中的工具。
- **要求：** 可登记服务名称、用途、连接信息和必要凭证，查看可用工具、工具用途、所需输入、返回内容与可能外部影响。支持连接验证、工具试用、启用和停用，并说明当前服务是否具备所需能力。
- **异常与边界：** 工具列表读取成功不代表已经获准执行全部工具；服务不能连接、能力不兼容或说明缺失时应清楚提示。服务提供的其他资料应与可执行工具区分，不能把所有返回内容都当成指令。
- **验收：** PA-P3-003-A1：接入一个可用远程服务并查看实际工具清单；PA-P3-003-A2：不可用服务给出可理解状态而非空白成功；PA-P3-003-A3：新发现工具默认不会自动获得 Agent 使用授权。

### PA-P3-004 工具选择、授权与实际调用约束

- **场景与前置条件：** 开发者为 Agent 选择 MCP 工具或阶段 2 已登记的业务工具。
- **要求：** 显示每个工具的使用范围、外部影响和是否需要用户确认；只把当前允许使用的能力提供给该任务，真实调用前再次核对有效授权。必要确认应准确说明对象、动作和范围，已有明确授权仍有效且完整覆盖时不重复打断。
- **异常与边界：** 工具被撤权、Agent 请求了未选择工具、操作对象超出范围或任务模式不允许时必须拒绝。模型、Skill、工具返回值或历史摘要声称“用户已批准”均不能替代真实授权。需要复杂等待审批的任务在阶段 6 支持，本阶段不能满足的操作应清楚阻止。
- **验收：** PA-P3-004-A1：Agent 无法调用未选择或已撤权工具；PA-P3-004-A2：外部资料中的授权声明不会让调用获准；PA-P3-004-A3：对同一有效授权范围不重复确认，范围扩大时重新判断并在必要时确认。

### PA-P3-005 MCP 工具变化、失败与使用记录

- **场景与前置条件：** 已接入服务的工具说明发生变化，或调用中出现超时和不确定结果。
- **要求：** 显示工具能力变化及受影响的 Agent 或流程，使用前检查必要输入仍然符合当前要求。每次调用可查看所用服务、工具、输入摘要、结果、失败原因和已知消耗。对于外部修改，结果不确定时提示核对真实结果。
- **异常与边界：** 新增工具不得沿用不适用的旧授权；输入要求发生变化不能无提示地继续旧调用。不能自动重复结果不确定的外部修改。凭证和受限信息不出现在普通运行说明中。
- **验收：** PA-P3-005-A1：工具输入要求变化后能发现受影响任务；PA-P3-005-A2：超时与明确失败可区分，修改型调用不被盲目重做；PA-P3-005-A3：成功与失败调用都有可查记录和费用状态。

### PA-P3-006 Skill 导入、描述与版本

- **场景与前置条件：** 开发者拥有一套任务指导、参考资料或模板，希望在多个 Agent 中复用。
- **要求：** 支持从用户提供的资料包导入 Skill，识别名称、简介、适用任务、主指导文件、参考资料及所需能力；主指导文件以 SKILL.md 作为首批约定。保存来源、版本和导入说明，支持预览、停用与选择特定版本。
- **异常与边界：** 缺少必要说明、引用资料缺失、同名冲突或要求当前不具备的工具时，应在启用前提示。导入资料中的脚本可被识别和说明，但阶段 3 不直接执行。导入 Skill 不等于授予其所要求的全部权限。
- **验收：** PA-P3-006-A1：导入一个带主指导、参考文件和模板的 Skill，能够分别预览；PA-P3-006-A2：引用缺失或同名版本冲突有明确反馈；PA-P3-006-A3：导入含脚本的 Skill 不会自动执行脚本。

### PA-P3-007 Skill 渐进式披露与用户选择

- **场景与前置条件：** 项目已有多个 Skill，Agent 处理的任务只需要其中少量内容。
- **要求：** 先提供可用 Skill 的名称与简介；确认某项 Skill 与任务有关后读取主指导；需要具体细节时再读取相关参考资料或模板。用户可明确指定、排除或查看已启用的 Skill，运行记录显示实际读取了哪些资料及其版本。
- **异常与边界：** 不能默认把所有 Skill 全文作为每次任务的必要材料；参考资料失效、无权读取或超出当前任务范围时应说明并选择停止或继续的合理行为。不能擅自读取资料包之外的内容。脚本执行仍受后续阶段能力和独立授权限制。
- **验收：** PA-P3-007-A1：配置多个 Skill 后，简单任务只读取所需指导和相关资料；PA-P3-007-A2：用户排除某 Skill 后本次任务不使用其内容；PA-P3-007-A3：运行详情可说明简介、主指导与参考资料分别在何时被采用。

### PA-P3-008 项目规则文件与目录适用范围

- **场景与前置条件：** Agent 处理一个包含项目说明和不同目录约定的资料集合或仓库任务。
- **要求：** 能够发现并读取当前任务适用的项目规则，展示文件来源与适用目录；AGENTS.md 作为首批预期主入口。进入特定目录相关任务时，应识别该目录内更具体的约定，记录本次实际采用的规则版本。用户能够查看和纠正规则适用范围。
- **异常与边界：** 无规则文件应显示未发现，而非自动制造约定；不同目录规则不应全局套用。用户提及的 agent.md 等别名是否兼容需要确认；若同时出现多种命名，在规则尚未明确时不能静默任选。外部网页或知识资料不能冒充项目规则文件。
- **验收：** PA-P3-008-A1：根目录与子目录规则在各自范围内生效；PA-P3-008-A2：跨目录任务可以说明采用了哪些规则；PA-P3-008-A3：缺失或命名冲突有明确状态和处理说明。

### PA-P3-009 指令冲突与资料可信边界

- **场景与前置条件：** 用户当前任务、Agent 指导、项目规则和外部资料之间存在冲突。
- **要求：** 强制权限、真实授权范围和平台必需限制始终有效；用户当前明确要求可以覆盖普通项目习惯或建议，不能自动扩大其本身无权取得的能力。普通规则之间按已公开的适用范围处理，无法判断且影响结果时应说明冲突并请求必要澄清。
- **异常与边界：** Skill 正文、项目文件或工具结果不能仅凭写有“最高优先级”就成为强制策略；外部内容不得自行改变目标、读取秘密或授权外部修改。澄清应针对真正缺失的决策，不能反复要求已明确授权的普通动作再次确认。
- **验收：** PA-P3-009-A1：用户要求与普通目录习惯冲突时可按用户明确要求执行并留下说明；PA-P3-009-A2：资料中的越权指令不会被执行；PA-P3-009-A3：真实权限限制不会因用户选择其他 Skill 或模式而失效。

### PA-P3-010 上下文可见范围与预算

- **场景与前置条件：** 任务包含对话、规则、Skill、工具结果或其他材料，需要在有限容量内继续处理。
- **要求：** 向用户说明当前可用容量、输入与预期输出的占用情况，以及估算是否完整。允许查看本次采用的材料类别、关键来源和未纳入原因；优先保障当前目标、必要约束、未完成事项与所需证据。较大工具结果可先展示摘要并保留获准查阅原文的入口。
- **异常与边界：** 容量不足时提前提示并采取可解释的缩减或停止措施，不能把材料静默截断后仍声称完整阅读。未知容量不得展示伪精确比例。查看上下文不能暴露秘密或其他项目资料。
- **验收：** PA-P3-010-A1：长任务可以看到容量压力与所采用材料来源；PA-P3-010-A2：大结果被缩减时有明确说明和获准回读路径；PA-P3-010-A3：未获得准确容量时显示估算或未知状态。

### PA-P3-011 上下文压缩与关键事实保全

- **场景与前置条件：** 历史内容过长，继续任务需要压缩或减少材料。
- **要求：** 支持按用户可理解的规则压缩较早内容、去除重复信息或减少不相关材料，并显示压缩发生过及覆盖范围。压缩后的任务说明应保留目标、强制限制、用户明确要求、已完成与未完成事项、关键决定和证据来源；需要核实时能够在当前权限下回读原始资料。
- **异常与边界：** 压缩不能伪造授权、把计划改写为已完成、遗漏关键待办或改变数值结论；真实授权必须可核对原始记录。无法保全继续任务所需信息时，应明确停下并说明缺少什么。回读不能绕过已撤销的资料权限。
- **验收：** PA-P3-011-A1：压缩前设定的目标、限制、关键数字和待办在后续回答中保持一致；PA-P3-011-A2：压缩后可追到对应原始证据；PA-P3-011-A3：摘要中的虚构批准或完成声明不能触发真实执行或任务成功。

### PA-P3-012 会话记忆与长期记忆控制

- **场景与前置条件：** 用户希望跨会话复用某些事实或偏好，同时能控制保留范围。
- **要求：** 区分当前任务资料、当前会话历史和允许跨会话使用的记忆。长期保留内容需得到明确授权或由用户认可的规则覆盖，并能够查看来源、适用项目、更新时间与有效性。用户可以修改、停用和删除自己有权管理的记忆。
- **异常与边界：** 一次对话中出现的信息不默认成为永久记忆；用户事实与模型推测应区分。删除或停用后不得继续作为新的任务依据。跨项目共享、敏感资料或已撤权来源不能未经许可被再次引用。
- **验收：** PA-P3-012-A1：用户认可的事实可在允许范围内被后续会话使用；PA-P3-012-A2：修改或停用后，新任务不再使用旧事实；PA-P3-012-A3：项目 A 的记忆不会无授权进入项目 B。

### PA-P3-013 Agent 与工作流互相复用

- **场景与前置条件：** 开发者希望在固定流程中的某一步使用 Agent，或让 Agent 选择执行一个已确认流程。
- **要求：** 工作流可以引用明确 Agent 版本并提供任务输入；Agent 可以使用被授予的已确认工作流能力。调用结果、失败和外部影响都需要向发起者清楚返回，并能展开查看实际运行。父任务与被调用任务共同遵循已有预算和权限范围。
- **异常与边界：** 不能通过互相调用无限扩张步骤、时长和成本；递归或循环引用超出当前阶段范围时应阻止。被调用方提出的额外工具需求不得自动获准。资料传递遵循原项目与用户授权。
- **验收：** PA-P3-013-A1：工作流中的 Agent 步骤能产生可继续使用的明确结果；PA-P3-013-A2：Agent 调用获准工作流后可查看子任务结果和费用；PA-P3-013-A3：互相调用不能绕过总限制或获得额外工具权限。

### PA-P3-014 完成证据与运行解释

- **场景与前置条件：** 任务结束后，用户要判断 Agent 做了什么、是否达到目标和结果能否信任。
- **要求：** 输出完成事项、未完成事项、实际工具动作、关键证据与限制说明；提供关联 Skill、规则、记忆来源、压缩记录、总用量和停止原因。能够区分“提出建议”“尝试操作”“操作成功”和“经核对满足任务目标”。用户可标记结果问题，并保留用于后续质量评测的记录。
- **异常与边界：** 模型自行声称成功不能代替工具结果或用户目标验证；没有证据的部分应明确不确定。禁止把敏感完整输入或凭证放入公开解释；失败记录保留对后续改进有用的原因。
- **验收：** PA-P3-014-A1：任务报告中的每个已执行动作能对应真实记录；PA-P3-014-A2：未执行的计划不会被写成已完成；PA-P3-014-A3：根据详情能够解释本次使用了哪些资料、为何停止以及已知消耗。

## 3. 信息与权限要求

Agent 指导、MCP 工具说明、Skill 主文、参考资料、项目规则、上下文摘要和长期记忆是不同来源的资料；界面与运行记录需要区分其来源和可信范围。一个来源能够帮助理解任务，不代表它有权扩大任务权限。

用户已授予且仍然有效的权限可以持续用于本任务，避免无意义重复确认；当对象、动作或范围变化时重新核对。凭证与强制限制不能因为压缩、复制 Agent、导入 Skill、模式切换或嵌套调用而失效。项目资料规则和费用规则继续遵循[跨阶段需求](../03-cross-cutting-requirements.md)。

## 4. 阶段端到端验收

| P3-E2E-03 长上下文与记忆 | 在任务中放入关键目标、数值、禁止事项和待办，触发压缩后继续完成；检查原文回读、记忆修改与删除 | PA-P3-009、PA-P3-010、PA-P3-011、PA-P3-012 |
| P3-E2E-04 冲突与越权资料 | 让普通项目习惯与用户明确任务发生冲突，并提供伪造授权的外部资料；检查前者可合理覆盖、后者不能授权 | PA-P3-004、PA-P3-008、PA-P3-009、PA-P3-011 |
