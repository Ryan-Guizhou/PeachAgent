# 阶段 1：项目基础与首个对话闭环

> 版本：v0.1 · 日期：2026-11-23
>
> 状态：需求草案，待项目负责人确认；本文件中的功能尚未实现。
>
> 交付位置：六阶段路线图的第 1 阶段；阶段 1—5 构成首个完整核心版本。
>
> 本文仅规定用户需要获得的能力与验收结果，技术方案在需求确认后另行制定。

## 1. 背景与阶段目标

PeachAgent 后续的工作流、Agent、知识库与质量评测，都需要先有一个可以实际使用的项目环境。本阶段首先解决“进入项目、配置可用模型、完成一次多轮对话、查到结果与花费”的完整路径，避免只建立资源列表而无法完成真实任务。

完成本阶段后，项目负责人应能向开发者提供一个明确的使用入口；开发者能够知道当前项目缺少哪些配置、一次任务为什么失败、是否还在消耗资源，以及历史结果对应哪一次运行。模型产生回答只代表运行结束，不能自动证明用户任务已经达成。

### 1.1 范围

| 本阶段包含 | 后续阶段提供 |
|---|---|
| 项目、基本成员权限、模型配置、对话试用、Prompt 模板、运行记录、最小用量与预算控制 | 阶段 2 的拖拽工作流；阶段 3 的 MCP、Skill、项目规则与上下文压缩；阶段 4 的知识检索；阶段 5 的质量实验与 Prompt 优化 |
| 完成、失败、取消等用户可理解的运行状态 | 阶段 6 的长任务恢复、复杂人工等待及多 Agent 协作 |

本阶段不包含企业组织体系、商业结算、供应商余额管理、自动选择最便宜模型、自动部署或应用市场。基础预算保护从首次付费运行开始具备，不能推迟到质量中心建成后再补。

### 1.2 角色与使用场景

| 角色 | 场景 | 预期结果 |
|---|---|---|
| 项目负责人 | 建立项目，提供模型资源与使用限额 | 项目成员可以开始工作，凭证和用量受控 |
| 项目开发者 | 选择模型和 Prompt，进行多轮试用 | 得到可查阅的回答、错误信息与本次用量 |
| 项目开发者 | 对话失败、长时间无响应或输出不符合预期 | 能停止、查看原因，并明确选择是否重新运行 |
| 项目负责人 | 检查阶段交付 | 可以用同一套场景核对功能、权限和成本行为 |

## 2. 详细功能需求

### PA-P1-001 项目创建、选择与归档

- **场景与前置条件：** 具有项目创建权限的用户进入工作台，准备建立一个新的应用项目。
- **要求：** 用户可填写项目名称、用途说明并创建项目；工作台显示当前项目，允许切换到有权访问的其他项目。项目名称允许修改，项目内既有资产和运行归属保持不变。归档项目应保留历史资料，并明确限制继续发起任务。
- **异常与边界：** 缺少必填信息时说明具体问题；没有可访问项目时提供创建或联系负责人的指引。名称相同的项目必须有足够的区分信息，不能误进入其他项目。
- **验收：** PA-P1-001-A1：创建两个项目后，分别进入时可以明确辨识当前项目；PA-P1-001-A2：修改名称不改变旧运行的归属；PA-P1-001-A3：归档后仍能查阅有权访问的历史记录，且不能直接发起新任务。

### PA-P1-002 基本成员身份与权限

- **场景与前置条件：** 项目负责人需要让其他成员使用项目，同时控制谁可以管理资源与限额。
- **要求：** 至少区分“项目负责人”和“项目成员”两种职责。负责人可管理成员、模型资源授权和项目限额；成员可使用获准资源完成任务。资源页面、详情、历史记录与导出内容均遵循同一访问范围。
- **异常与边界：** 被移除的成员不能继续读取项目资料或发起新任务；已打开页面不能成为绕过权限的途径。不能无提示地移除最后一位负责人。跨项目引用未经授权时应拒绝并说明原因。
- **验收：** PA-P1-002-A1：成员不能修改负责人专属设置；PA-P1-002-A2：移除成员后，原有入口和历史记录入口均不能继续访问项目资料；PA-P1-002-A3：项目 A 的成员不能读取项目 B 的会话、Prompt 或凭证。

### PA-P1-003 模型资源与凭证管理

- **场景与前置条件：** 负责人拥有可合法使用的模型服务，准备将其提供给项目成员。
- **要求：** 可登记模型资源名称、服务来源、适用能力和必要的连接信息；凭证以保密方式维护。负责人可以更新、停用资源并指定可使用范围，成员能够看到资源用途和可用状态。资源说明与实际可用能力应保持一致。
- **异常与边界：** 不允许在会话、公开分享内容、运行详情或普通导出中显示完整凭证。停用资源时提示受到影响的使用入口；历史记录仍保留当时所用资源名称和版本信息。
- **验收：** PA-P1-003-A1：负责人配置一个模型后，获准成员可选择使用；PA-P1-003-A2：凭证更新后，普通成员不能读取完整凭证；PA-P1-003-A3：停用模型后新任务无法使用，历史任务仍可查阅。

### PA-P1-004 模型可用性验证与错误说明

- **场景与前置条件：** 完成模型配置的负责人需要确认资源是否能工作。
- **要求：** 提供一次明确的连接或试用验证，并展示成功、失败或结果不确定状态。可能产生模型费用的验证需要事前提示，产生的用量应能查到。错误说明应帮助区分凭证无效、资源不可用、访问受限、超时和输入不支持等问题。
- **异常与边界：** 验证失败不应显示为已就绪；不能以一次验证成功保证未来所有调用成功。错误详情不得暴露凭证，暂时无法判断的情况应标为未知并给出下一步操作。
- **验收：** PA-P1-004-A1：有效和无效配置分别产生可理解的结果；PA-P1-004-A2：付费试用在发起前有费用提示且结果中可查看用量；PA-P1-004-A3：失败记录中不出现完整敏感凭证。

### PA-P1-005 新建会话与连续对话

- **场景与前置条件：** 成员处于一个可用项目中，拥有至少一个可用模型的使用权限。
- **要求：** 可新建会话、选择模型、输入问题并接收回答；继续提问时能围绕当前会话进行交流。新会话应与其他会话分开。界面显示当前模型、所用 Prompt 以及是否正在生成内容。
- **异常与边界：** 空白输入、超过已公开限制的内容和缺少可用模型时提供明确反馈。重复点击发送不能悄悄创建重复任务。模型切换后应说明后续回答使用的新资源，不能改写历史回答的来源。
- **验收：** PA-P1-005-A1：同一会话完成两轮有关联的问答，历史顺序正确；PA-P1-005-A2：新会话不会无提示引用另一会话内容；PA-P1-005-A3：发送过程中重复点击不会产生无法辨识的重复任务或重复计费记录。

### PA-P1-006 实时反馈、停止与重试

- **场景与前置条件：** 用户已提交问题，希望看到进度，或在不再需要结果时停止运行。
- **要求：** 支持实时显示可用输出及运行进度；没有逐步输出能力时应清楚显示等待状态。用户可请求停止，并看到停止请求、最终取消或无法及时停止的结果。失败后保留已产生内容与错误原因，重新运行必须是用户可辨识的新尝试。
- **异常与边界：** 关闭页面或暂时断开连接不能自动标记任务成功。停止不保证收回已发生费用，应显示已知用量和待确认部分。重试不能覆盖原失败记录。
- **验收：** PA-P1-006-A1：生成过程中可看到输出或明确等待状态；PA-P1-006-A2：停止后显示最终结果及可能已产生费用；PA-P1-006-A3：同一问题失败后重试，能够分别查看两次尝试及各自用量。

### PA-P1-007 Prompt 模板与使用预览

- **场景与前置条件：** 开发者需要重复使用相同任务指导，只修改其中的业务输入。
- **要求：** 可创建、编辑、复制并保存 Prompt 模板，定义用户需要填写的内容，预览实际用于本次任务的指导文字。可以保存明确版本并选择一个版本用于会话。模型配置和 Prompt 内容应可分别识别。
- **异常与边界：** 缺少必填内容时不能带着未完成占位内容直接发起付费调用；预览需要保护敏感信息。模板被修改后，历史运行仍能识别当时实际使用的内容。自动优化候选与质量比较在阶段 5 提供。
- **验收：** PA-P1-007-A1：同一模板填写两组业务输入，可分别看到对应预览；PA-P1-007-A2：缺失必填项时指出具体位置；PA-P1-007-A3：修改模板后，既有运行的 Prompt 来源仍能回溯。

### PA-P1-008 运行历史与结果查阅

- **场景与前置条件：** 成员需要重新查看一次对话结果，负责人需要理解任务是否正常结束。
- **要求：** 可按项目、会话、时间和状态找到运行记录，查看输入、输出、所用资源、开始与结束时间、失败原因和关联用量。用户应能辨认准备中、进行中、成功、失败、已取消等状态。返回历史页面后仍可找到已完成结果。
- **异常与边界：** 只有部分输出时不得伪装成完整成功；无法确认结果的任务须显示待核实状态。敏感资料仅对有权查看的成员可见。删除和保留范围应遵循项目已明确的资料管理规则。
- **验收：** PA-P1-008-A1：成功、失败、取消各产生可区分记录；PA-P1-008-A2：刷新或重新进入项目后仍能找到已结束任务；PA-P1-008-A3：根据记录可以辨识该结果对应的模型、Prompt 与实际输入。

### PA-P1-009 用量与费用状态

- **场景与前置条件：** 一次模型验证或对话产生了资源使用，用户需要知道代价。
- **要求：** 至少展示单次任务与项目累计的已知模型用量、估算金额、币种及统计范围；明确区分供应商报告的用量、平台估算金额、待确认用量和无法计算的费用。估算采用的价格及适用时间可查阅，模型试用和失败调用不能被遗漏。
- **异常与边界：** 未知价格不等于零元，缺失用量不等于没有消耗；不同币种不得直接相加并标成一种币种。平台估算与供应商最终账单可能不同，不能将估算宣传为已结算金额。
- **验收：** PA-P1-009-A1：成功与失败的付费调用均能进入已知用量统计；PA-P1-009-A2：缺少价格时明确显示“费用未知”；PA-P1-009-A3：项目汇总可以说明包含哪些任务、哪些数据尚不完整。

### PA-P1-010 首次运行前的限额保护

- **场景与前置条件：** 负责人希望限制单个任务和项目的持续消耗。
- **要求：** 在首次可产生费用的运行前即可设置或确认任务限额，包括模型调用次数、任务时长以及可计算时的费用预算；项目可设置累计费用提醒和限制。发起前显示本次适用限制，达到限制后不得继续发起新的受限动作。同时进行的任务共同受项目剩余额度约束，判断是否可以新增付费动作时要考虑已发起但尚未确认最终费用的消耗，不能将同一份剩余额度重复承诺给多个任务。后续工作流、Agent 与评测任务同样受所属项目限额约束。
- **异常与边界：** 已发出的调用可能仍产生费用，系统应解释其范围；无法取得价格时不得承诺精确金额封顶，应阻止依赖金额保证的任务，或由有权用户明确选择有次数、时长等限制的例外。普通成员不能通过新建会话绕过项目限额。
- **验收：** PA-P1-010-A1：达到调用次数或时长限制后，任务不再发起下一次模型调用；PA-P1-010-A2：在单次最大费用可确定、剩余项目预算只够一次调用的样例中，同时发起两个任务，不能各自获得同一笔剩余预算的承诺，超出共同预算的新增付费动作在执行前被提示并阻止；PA-P1-010-A3：未知费用例外有明确授权记录与非金额限制，且不显示为零成本保障。

### PA-P1-011 工作台与首次使用引导

- **场景与前置条件：** 首次进入平台的用户不清楚下一步操作，或已使用用户需要定位最近任务。
- **要求：** 工作台展示当前项目、资源准备情况、最近运行及已知用量；缺少模型、权限或必要配置时，直接说明阻塞原因和处理入口。各阶段尚未交付的能力应以规划状态呈现，不能让用户误认为已可使用。
- **异常与边界：** 没有数据时展示可执行的引导，不用虚构统计填充；加载失败应与无数据区分。权限不足时不应提供可以绕过限制的操作入口。
- **验收：** PA-P1-011-A1：空项目用户可以从工作台完成模型准备并发起首个会话；PA-P1-011-A2：资源被停用后能从工作台看到阻塞原因；PA-P1-011-A3：无运行数据时不出现虚构成功率或费用。

### PA-P1-012 结果复用与任务反馈

- **场景与前置条件：** 用户得到回答后，需要将结果用于工作，并指出它是否解决了问题。
- **要求：** 可复制回答或导出有权访问的会话结果，保留必要来源与时间信息；支持标记结果有用、未解决或存在问题，并填写原因。运行是否正常结束、业务目标是否有明确验收证据支持、用户是否认可结果应分别表达。
- **异常与边界：** 导出不得包含隐藏凭证、其他项目内容或无权访问的记录；用户反馈不能直接改写历史回答。没有用户反馈时不能计为用户认可，业务任务是否成功则按明确的验收要求与客观证据判断。
- **验收：** PA-P1-012-A1：复制或导出的结果与所选运行一致；PA-P1-012-A2：运行正常结束但用户标为未解决的任务，分别保留运行结果、业务验收结论与用户反馈；PA-P1-012-A3：无反馈任务不会被自动算作用户认可结果，但满足明确业务验收且有客观证据的任务可以独立判定为业务成功。

### PA-P1-013 资源变更与历史可解释性

- **场景与前置条件：** 负责人更新模型、模板或项目设置时，需要避免历史记录失去解释依据。
- **要求：** 成员可以辨识一个资源是草稿、可用还是停用，以及本次运行实际采用的已确认配置。修改后续使用的资源时，既有运行显示的来源与限额保持可追溯。删除受引用资源前需要说明影响，并提供保留历史说明的处理方式。
- **异常与边界：** 不能把新价格、新 Prompt 或新资源名称无说明地当成旧任务的原始配置；确实无法恢复的信息应显示缺失，不应补写为当前值。
- **验收：** PA-P1-013-A1：修改 Prompt 或模型配置后仍能解释修改前任务；PA-P1-013-A2：删除存在引用的资源前可看到受影响范围；PA-P1-013-A3：原始信息缺失时明确显示，不制造不存在的历史证据。

## 3. 信息、权限与质量要求

项目资料、会话内容、Prompt、模型凭证、运行记录与反馈分别有清楚的归属。授权范围变化应及时影响后续访问；历史可追溯不能成为永久保留敏感资料的理由。资料导出、清理与访问控制同时遵循[跨阶段需求](../03-cross-cutting-requirements.md)。

本阶段不预设缺乏实测依据的性能数字。验收时记录首个可见响应等待时间、任务总耗时、失败原因和成本完整程度，形成以后比较的起点。实际支持的输入长度、并发范围和保留期限需在实施前确认并向用户展示。

## 4. 阶段端到端验收

| 场景 | 操作与核对结果 | 对应需求 |
|---|---|---|
| P1-E2E-01 首次成功任务 | 负责人建项目并配置模型；成员确认限额，选模板完成两轮问答；重新进入后查到回答、来源与费用状态 | PA-P1-001、PA-P1-003、PA-P1-005、PA-P1-007、PA-P1-008、PA-P1-009、PA-P1-010、PA-P1-011 |
| P1-E2E-02 失败与停止 | 用不可用配置验证错误；运行中请求停止；显式重试后能区分各次结果、费用和任务反馈 | PA-P1-004、PA-P1-006、PA-P1-008、PA-P1-009、PA-P1-012 |
| P1-E2E-03 权限与变更 | 成员不能读取其他项目；凭证不随导出泄露；资源修改不改变历史依据；归档后不能继续运行 | PA-P1-001、PA-P1-002、PA-P1-003、PA-P1-012、PA-P1-013 |
| P1-E2E-04 限额边界 | 低限额任务不能无限调用；未知价格明确呈现；新建会话与同时发起多个任务均不能绕过项目已设限额，剩余预算不能被重复承诺 | PA-P1-009、PA-P1-010 |

上述场景通过、所有需求验收项有结果、已知缺陷和范围调整有记录后，才能申请阶段核对。没有执行证据的功能仍保持未完成，核对方式见[验收与追踪](../04-acceptance-and-traceability.md)。

## 5. 候选 Issue 拆分
