# 阶段 1：项目基础与首个对话闭环

> 版本：v0.2 · 日期：2026-11-23
>
> 状态：基于用户已确认边界的需求基线；本文件中的功能尚未实现。
>
> 交付位置：第 1 阶段；阶段 1—6 完成完整平台，阶段 7 专门交付 Docker / Compose 部署与上线验收。
>
> 本文仅规定用户需要获得的能力与验收结果；用户已授权同步编写总体架构，具体实现另行开发。

## 1. 背景与阶段目标

PeachAgent 后续的工作流、Agent、知识库与质量评测，都需要先有一个可以实际使用的项目环境。本阶段首先解决“进入项目、配置可用模型、完成一次多轮对话、查到结果与花费”的完整路径，避免只建立资源列表而无法完成真实任务。

完成本阶段后，个人用户应能独立进入自己的租户并建立多个项目；用户能够知道当前项目缺少哪些配置、一次任务为什么失败、是否还在消耗资源，以及历史结果对应哪一次运行。模型产生回答只代表运行结束，不能自动证明用户任务已经达成。

### 1.1 范围

| 本阶段包含 | 后续阶段提供 |
|---|---|
| 个人账号与租户、项目、BYOK 模型配置、对话试用、Prompt 模板、运行记录、最小用量与预算控制 | 阶段 2 的拖拽工作流；阶段 3 的 MCP、Skill、项目规则与上下文压缩；阶段 4 的知识检索；阶段 5 的质量实验与 Prompt 优化 |
| 完成、失败、取消等用户可理解的运行状态 | 阶段 6 的长任务恢复、复杂人工等待及多 Agent 协作 |

每个个人账号对应一个个人租户，同一租户可创建多个项目；所有产品功能向个人用户开放，功能开放不授予其他租户的数据或平台管理权限。模型及外部工具凭证全部由使用者自行配置（BYOK），平台不提供公共模型额度。身份与权限采用用户指定的 Sa-Token，本文件只规定可观察行为。插件开发入口和声明约定在本阶段建立；自定义界面、动态执行、知识与评测扩展依次在阶段 2—5 交付，阶段 6 完成公共发布联动。

本阶段不包含企业组织体系、商业结算、供应商余额管理或自动选择最便宜模型。基础预算与 Token 面板从首次付费运行开始具备。阶段 6 的人工等待、多 Agent 等能力属于完整平台的必交付内容；正式部署交付归入阶段 7。

### 1.2 角色与使用场景

| 角色 | 场景 | 预期结果 |
|---|---|---|
| 个人用户作为配置者 | 建立项目，配置本人模型与使用限额 | 能开始使用，凭证和用量受控 |
| 个人用户作为使用者 | 选择模型和 Prompt，进行多轮试用 | 得到可查阅的回答、错误信息与本次用量 |
| 个人用户 | 对话失败、长时间无响应或输出不符合预期 | 能停止、查看原因，并明确选择是否重新运行 |
| 项目交付核对者 | 检查阶段交付 | 可以用同一套场景核对功能、权限和成本行为 |

## 2. 详细功能需求

### PA-P1-001 个人租户中的项目创建、选择与归档

- **场景与前置条件：** 个人用户已进入自己的租户，准备为不同任务建立项目。
- **要求：** 可在本人租户内创建多个项目，填写名称和用途，随时辨认当前租户及项目。项目名称可修改，已有资产、运行与用量归属保持不变。归档项目保留本人有权查看的历史资料，并限制继续发起新任务。
- **异常与边界：** 重名项目需要足够区分信息；没有项目时直接引导创建。复制链接或修改访问对象不能进入另一人的私有租户；从公共仓库获取的内容进入本人的项目，不能等同于加入作者的项目。
- **验收：** PA-P1-001-A1：同一账号创建两个项目并可辨认切换后的资源和用量归属；PA-P1-001-A2：修改名称不改变历史运行归属；PA-P1-001-A3：归档后历史按声明范围保留且无法直接发起新任务。

### PA-P1-002 个人身份、租户归属与访问权限

- **场景与前置条件：** 个人用户管理自己的资料，平台维护者需要维护服务而非取得用户业务数据。
- **要求：** 一个个人账号拥有一个个人租户，可管理本人项目、模型、工具、插件和资料，并使用全部已交付功能。平台管理身份与个人使用身份分开；公共资源的发现、下载和明确授权共享按相应规则进行，不以企业成员或部门体系作为前置条件。
- **异常与边界：** 全部功能可用不等于跨租户访问、平台管理员权限或无限用量；普通用户不能修改平台全局限制。已停用账号或撤销的访问授权不能借已打开页面继续取得数据。平台管理身份不自动成为读取私人任务和凭证的授权。
- **验收：** PA-P1-002-A1：个人用户可使用已交付的各类能力，无须企业成员身份或功能套餐授权；PA-P1-002-A2：甲用户不能通过列表、搜索、直接链接、运行和导出取得乙用户私有资料；PA-P1-002-A3：账号停用或明确共享授权撤回后，新的访问与执行请求受到相应限制。

### PA-P1-003 自备模型与外部凭证管理

- **场景与前置条件：** 个人用户持有自己有权使用的模型服务凭证，准备在本人项目中使用。
- **要求：** 可登记模型资源名称、服务来源、能力和必要连接信息；凭证归本人租户管理，能够更新、停用并选择可使用的本人项目。模型及后续 MCP、工具凭证均由实际使用者自行配置。引用公共应用或插件时，提示绑定自己的资源和凭证。
- **异常与边界：** 平台不提供公共模型或自动使用作者、其他用户的凭证。配置和使用过程中不在对话、模型输入、分享包、普通运行详情或导出中回显完整秘密；凭证停用后不能继续发起新的受限调用。
- **验收：** PA-P1-003-A1：甲乙用户分别配置自己的模型凭证，运行只能使用各自明确绑定的资源；PA-P1-003-A2：复制公共配置后缺少个人凭证时提示补齐，不使用发布者凭证；PA-P1-003-A3：停用个人模型后新调用被阻止，旧运行保留可解释的资源和用量记录。

### PA-P1-004 模型可用性验证与错误说明

- **场景与前置条件：** 完成模型配置的个人用户需要确认资源是否能工作。
- **要求：** 提供一次明确的连接或试用验证，并展示成功、失败或结果不确定状态。可能产生模型费用的验证需要事前提示，产生的用量应能查到。错误说明应帮助区分凭证无效、资源不可用、访问受限、超时和输入不支持等问题。
- **异常与边界：** 验证失败不应显示为已就绪；不能以一次验证成功保证未来所有调用成功。错误详情不得暴露凭证，暂时无法判断的情况应标为未知并给出下一步操作。
- **验收：** PA-P1-004-A1：有效和无效配置分别产生可理解的结果；PA-P1-004-A2：付费试用在发起前有费用提示且结果中可查看用量；PA-P1-004-A3：失败记录中不出现完整敏感凭证。

### PA-P1-005 新建会话与连续对话

- **场景与前置条件：** 用户处于一个可用项目中，拥有至少一个可用模型的使用权限。
- **要求：** 可新建会话、选择模型、输入问题并接收回答；继续提问时能围绕当前会话进行交流。新会话应与其他会话分开。界面显示当前模型、所用 Prompt 以及是否正在生成内容。
- **异常与边界：** 空白输入、超过已公开限制的内容和缺少可用模型时提供明确反馈。重复点击发送不能悄悄创建重复任务。模型切换后应说明后续回答使用的新资源，不能改写历史回答的来源。
- **验收：** PA-P1-005-A1：同一会话完成两轮有关联的问答，历史顺序正确；PA-P1-005-A2：新会话不会无提示引用另一会话内容；PA-P1-005-A3：发送过程中重复点击不会产生无法辨识的重复任务或重复计费记录。

### PA-P1-006 实时反馈、停止与重试

- **场景与前置条件：** 用户已提交问题，希望看到进度，或在不再需要结果时停止运行。
- **要求：** 支持实时显示可用输出及运行进度；没有逐步输出能力时应清楚显示等待状态。用户可请求停止，并看到停止请求、最终取消或无法及时停止的结果。失败后保留已产生内容与错误原因，重新运行必须是用户可辨识的新尝试。
- **异常与边界：** 关闭页面或暂时断开连接不能自动标记任务成功。停止不保证收回已发生费用，应显示已知用量和待确认部分。重试不能覆盖原失败记录。
- **验收：** PA-P1-006-A1：生成过程中可看到输出或明确等待状态；PA-P1-006-A2：停止后显示最终结果及可能已产生费用；PA-P1-006-A3：同一问题失败后重试，能够分别查看两次尝试及各自用量。

### PA-P1-007 Prompt 模板与使用预览

- **场景与前置条件：** 用户需要重复使用相同任务指导，只修改其中的业务输入。
- **要求：** 可创建、编辑、复制并保存 Prompt 模板，定义用户需要填写的内容，预览实际用于本次任务的指导文字。可以保存明确版本并选择一个版本用于会话。模型配置和 Prompt 内容应可分别识别。
- **异常与边界：** 缺少必填内容时不能带着未完成占位内容直接发起付费调用；预览需要保护敏感信息。模板被修改后，历史运行仍能识别当时实际使用的内容。自动优化候选与质量比较在阶段 5 提供。
- **验收：** PA-P1-007-A1：同一模板填写两组业务输入，可分别看到对应预览；PA-P1-007-A2：缺失必填项时指出具体位置；PA-P1-007-A3：修改模板后，既有运行的 Prompt 来源仍能回溯。

### PA-P1-008 运行历史与结果查阅

- **场景与前置条件：** 用户需要重新查看一次对话结果，个人用户需要理解任务是否正常结束。
- **要求：** 可按项目、会话、时间和状态找到运行记录，查看输入、输出、所用资源、开始与结束时间、失败原因和关联用量。用户应能辨认准备中、进行中、成功、失败、已取消等状态。返回历史页面后仍可找到已完成结果。
- **异常与边界：** 只有部分输出时不得伪装成完整成功；无法确认结果的任务须显示待核实状态。敏感资料仅对有权查看的用户可见。删除和保留范围应遵循项目已明确的资料管理规则。
- **验收：** PA-P1-008-A1：成功、失败、取消各产生可区分记录；PA-P1-008-A2：刷新或重新进入项目后仍能找到已结束任务；PA-P1-008-A3：根据记录可以辨识该结果对应的模型、Prompt 与实际输入。

### PA-P1-009 用量与费用状态

- **场景与前置条件：** 本人模型验证、对话或后续 AI 功能产生资源使用，用户需要知道代价。
- **要求：** 显示单次任务、项目及个人租户范围的模型用量、估算金额、币种和统计范围。区分供应商报告用量、平台估算、待确认和未知费用；价格依据与适用时间可查。失败、取消、重试和付费验证均计入实际发生的已知用量。
- **异常与边界：** BYOK 不等于没有消耗；未知价格不等于零元，缺失用量不等于未使用。不同币种不得直接相加；估算金额不冒充用户模型服务的最终账单。Token 统计与不按 Token 计量的工具开销分别呈现。
- **验收：** PA-P1-009-A1：成功与失败的模型调用都能进入本人的用量统计；PA-P1-009-A2：缺少价格时显示已知 Token 与费用未知，不显示免费；PA-P1-009-A3：项目与租户汇总可说明覆盖任务、价格依据和不完整数据。

### PA-P1-010 首次运行前的限额保护

- **场景与前置条件：** 个人用户希望限制单个任务和项目的持续消耗。
- **要求：** 在首次可产生费用的运行前即可设置或确认任务限额，包括模型调用次数、任务时长以及可计算时的费用预算；项目可设置累计费用提醒和限制。发起前显示本次适用限制，达到限制后不得继续发起新的受限动作。同时进行的任务共同受项目剩余额度约束，判断是否可以新增付费动作时要考虑已发起但尚未确认最终费用的消耗，不能将同一份剩余额度重复承诺给多个任务。同一租户下的各项目还共同受个人租户总体限额约束。后续工作流、Agent、RAG、评测与优化任务继承这些限制。
- **异常与边界：** 已发出的调用可能仍产生费用，系统应解释其范围；无法取得价格时不得承诺精确金额封顶，应阻止依赖金额保证的任务，或由有权用户明确选择有次数、时长等限制的例外。普通用户不能通过新建会话、项目或并发任务绕过本人租户的已设总体限额。
- **验收：** PA-P1-010-A1：达到调用次数或时长限制后，任务不再发起下一次模型调用；PA-P1-010-A2：在单次最大费用可确定、剩余项目预算只够一次调用的样例中，同时发起两个任务，不能各自获得同一笔剩余预算的承诺，超出共同预算的新增付费动作在执行前被提示并阻止；PA-P1-010-A3：未知费用例外有明确授权记录与非金额限制，且不显示为零成本保障。

### PA-P1-011 工作台与首次使用引导

- **场景与前置条件：** 首次进入平台的用户不清楚下一步操作，或已使用用户需要定位最近任务。
- **要求：** 工作台展示当前项目、资源准备情况、最近运行及已知用量；缺少模型、权限或必要配置时，直接说明阻塞原因和处理入口。各阶段尚未交付的能力应以规划状态呈现，不能让用户误认为已可使用。
- **异常与边界：** 没有数据时展示可执行的引导，不用虚构统计填充；加载失败应与无数据区分。权限不足时不应提供可以绕过限制的操作入口。
- **验收：** PA-P1-011-A1：空项目用户可以从工作台完成模型准备并发起首个会话；PA-P1-011-A2：资源被停用后能从工作台看到阻塞原因；PA-P1-011-A3：无运行数据时不出现虚构成功率或费用。

### PA-P1-012 结果复用与任务反馈

- **场景与前置条件：** 用户得到回答后，需要将结果用于工作，并指出它是否解决了问题。
- **要求：** 可复制回答或导出有权访问的会话结果，保留必要来源与时间信息；支持标记结果有用、未解决或存在问题，并填写原因。运行是否正常结束、业务目标是否有明确验收证据支持、用户是否认可结果应分别表达。
- **异常与边界：** 导出不得包含隐藏凭证、其他项目内容或无权访问的记录；用户反馈不能直接改写历史回答。没有用户反馈时不能计为用户认可，业务任务是否成功则按明确的验收要求与客观证据判断。
- **验收：** PA-P1-012-A1：复制或导出的结果与所选运行一致；PA-P1-012-A2：运行正常结束但用户标为未解决的任务，分别保留运行结果、业务验收结论与用户反馈；PA-P1-012-A3：无反馈任务不会被自动算作用户认可结果，但满足明确业务验收且有客观证据的任务可以独立判定为业务成功。

### PA-P1-013 资源变更与历史可解释性

- **场景与前置条件：** 个人用户更新模型、模板或项目设置时，需要避免历史记录失去解释依据。
- **要求：** 用户可以辨识一个资源是草稿、可用还是停用，以及本次运行实际采用的已确认配置。修改后续使用的资源时，既有运行显示的来源与限额保持可追溯。删除受引用资源前需要说明影响，并提供保留历史说明的处理方式。
- **异常与边界：** 不能把新价格、新 Prompt 或新资源名称无说明地当成旧任务的原始配置；确实无法恢复的信息应显示缺失，不应补写为当前值。
- **验收：** PA-P1-013-A1：修改 Prompt 或模型配置后仍能解释修改前任务；PA-P1-013-A2：删除存在引用的资源前可看到受影响范围；PA-P1-013-A3：原始信息缺失时明确显示，不制造不存在的历史证据。

### PA-P1-014 个人账号进入与租户初始化

- **场景与前置条件：** 新用户首次使用平台，或既有用户重新登录。
- **要求：** 提供清楚的账号创建或开通、登录、退出、凭证恢复与账号状态提示；成功开通时建立唯一的个人租户，重复进入不创建重复租户。首次引导包含创建项目、配置本人模型、设置初始限制，并说明没有凭证时仍可阅读和编辑非付费内容。
- **异常与边界：** 账号标识冲突、凭证错误、账号停用或恢复失败应有明确结果；退出后原会话不能继续操作私有内容。账号停用、注销申请与资料保留的影响需要向用户说明，不能无说明删除全部资料。
- **验收：** PA-P1-014-A1：新用户完成账号开通和首次登录，获得一个个人租户；再次登录不产生第二个租户；PA-P1-014-A2：退出后原有登录状态不能继续读取私有资源；PA-P1-014-A3：未配置模型时可完成项目和草稿准备，付费调用入口明确提示自行配置凭证。

### PA-P1-015 插件开发入口与声明准备

- **场景与前置条件：** 个人用户准备开发自己的配置插件、执行插件或自定义界面扩展。
- **要求：** 所有个人用户可进入“我的插件/插件开发”入口，创建归属本人的插件草稿，填写身份、用途、版本、能力类型、输入输出、配置项、凭证需求、权限、依赖和界面扩展位置；可查阅对应 SDK、模板及逐阶段可用能力说明。插件能力与 MCP、Skill、Prompt 的登记方式分别说明。
- **异常与边界：** 不完整声明可以保存为草稿，但不得伪装成已安装可执行插件。声明需要的权限或凭证不等于已经获得；新插件的代码和界面不能被带入所有用户项目。阶段 1 建立约定与入口，阶段 2、3 分别完成可安装界面和动态执行的真实闭环。
- **验收：** PA-P1-015-A1：用户可以创建含输入输出与界面位置说明的插件草稿，并检查缺失项；PA-P1-015-A2：甲用户不能修改或直接安装乙用户未公开的插件草稿；PA-P1-015-A3：入口明确显示配置、代码和自定义界面能力的交付阶段及示例，不把资源注册描述成代码插件已运行。

### PA-P1-016 统一 Token 面板与任务来源

- **场景与前置条件：** 用户希望理解自己的模型消耗，而非只看单条对话费用。
- **要求：** 提供统一 Token 面板，按时间、模型、个人项目、任务及功能来源查看消耗；来源至少区分对话、Agent、RAG、评测、优化。每类功能随所在阶段上线即进入同一面板；未交付能力标为未开放，已开放但无记录标为无使用记录。可查看输入、输出及供应商实际提供的缓存、推理等用量分类，说明估算与已报告数据。
- **异常与边界：** 分类数据缺失不能补造；供应商分类存在包含关系时不得重复相加。同一次模型调用被父任务、子任务、插件或实验引用，明细与汇总只计一次；不用 Token 计量的消耗另列。公共应用或插件的使用只记录使用者自己的调用，不可看到作者或其他使用者的私有消耗。
- **验收：** PA-P1-016-A1：阶段 1 的模型验证和对话记录可按项目与模型核对，后续每类功能上线时都有对应来源；PA-P1-016-A2：父任务包含子任务的样例中，汇总没有重复计算同一次模型调用；PA-P1-016-A3：未知分类明确标注，甲乙用户面板互不暴露私有明细。

## 3. 信息、权限与质量要求

个人租户、项目、会话内容、Prompt、模型凭证、运行记录与反馈分别有清楚的归属；项目是本人租户内的组织单元，公共内容的下载或使用不改变私有资料的归属。授权范围变化应及时影响后续访问；历史可追溯不能成为永久保留敏感资料的理由。资料导出、清理与访问控制同时遵循[跨阶段需求](../03-cross-cutting-requirements.md)。

本阶段不预设缺乏实测依据的性能数字。验收时记录首个可见响应等待时间、任务总耗时、失败原因和成本完整程度，形成以后比较的起点。实际支持的输入长度、并发范围和保留期限需在实施前确认并向用户展示。

## 4. 阶段端到端验收

| 场景 | 操作与核对结果 | 对应需求 |
|---|---|---|
| P1-E2E-01 首次成功任务 | 个人用户创建租户内项目并配置自己的模型；确认限额，选模板完成两轮问答；重新进入后查到回答、来源与费用状态 | PA-P1-001、PA-P1-003、PA-P1-005、PA-P1-007、PA-P1-008、PA-P1-009、PA-P1-010、PA-P1-011 |
| P1-E2E-02 失败与停止 | 用不可用配置验证错误；运行中请求停止；显式重试后能区分各次结果、费用和任务反馈 | PA-P1-004、PA-P1-006、PA-P1-008、PA-P1-009、PA-P1-012 |
| P1-E2E-03 权限与变更 | 用户不能读取其他租户私有项目；凭证不随导出泄露；资源修改不改变历史依据；归档后不能继续运行 | PA-P1-001、PA-P1-002、PA-P1-003、PA-P1-012、PA-P1-013 |
| P1-E2E-04 限额边界 | 低限额任务不能无限调用；未知价格明确呈现；新建会话与同时发起多个任务均不能绕过项目已设限额，剩余预算不能被重复承诺 | PA-P1-009、PA-P1-010 |
| P1-E2E-05 个人进入与插件准备 | 两个账号各自初始化一个租户；创建多个项目与私人插件草稿；退出后检查访问，Token 面板只显示本人记录 | PA-P1-002、PA-P1-014、PA-P1-015、PA-P1-016 |

上述场景通过、所有需求验收项有结果、已知缺陷和范围调整有记录后，才能申请阶段核对。没有执行证据的功能仍保持未完成，核对方式见[验收与追踪](../04-acceptance-and-traceability.md)。
