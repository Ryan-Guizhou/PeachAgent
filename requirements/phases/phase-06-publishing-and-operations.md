# 阶段 6：高级协作、应用发布与运营需求

> 版本：v0.2 · 日期：2026-11-23
>
> 状态：基于已确认产品边界的详细需求规划；本阶段全部条目属于必交付范围，待实施，尚未实现。
>
> 所属路线：阶段 1—6 完成完整 Agent 开发平台，阶段 7 完成 Docker/Compose 部署与上线验收。
>
> 文档边界：规定增强能力的使用结果与限制，不确定技术实现。

## 1. 背景与目标

在单个 Agent、基础工作流、知识问答和质量比较能够稳定完成任务后，平台还必须能够处理长任务、人工确认、多个 Agent 分工和受控文件操作，并把已经验证的应用交给真实用户使用。发布后的身份、执行租户、配额、版本、运行状态和维护责任需要清楚可查。

本阶段同时补齐 Runtime 的高级能力和 Operations 的发布运营闭环。个人用户以租户身份使用全部功能，可以私用资源、发布应用、提交公共资源；管理员负责公共内容的审核与平台运营。阶段 6 完成后，Studio、Runtime、Quality、Operations 四个域均有真实可用的用户路径；不能以“未来可扩展”代替已承诺能力。

产品功能完成和部署完成分别验收：本阶段要求应用可发布、可访问、可观察、可回退，阶段 7 在约定部署环境完成安装、初始化、备份恢复、升级及上线验证。本阶段任务可以逐项拆分开发，但不得再把原 PA-P6-001—PA-P6-012 视为可任意跳过的能力池。

## 2. 范围与启用条件

| 范围 | 内容 |
|---|---|
| 必交付运行能力 | 工作流并行与循环、人工介入、长任务恢复、多 Agent 协作、隔离执行、产物管理、动态插件、记忆增强、扫描文本/表格/跨文档知识能力与模型选择 |
| 必交付运营能力 | 应用发布、Web/API/Webhook 使用、版本回退、用户与租户管理、公共仓库、配额与运行观测、必要告警、导出删除与保留规则 |
| 启用前提 | 对应前序能力已验收；权限、预算、运行记录和质量判断能够覆盖新增路径 |
| 外部服务边界 | 模型与外部工具由用户自行配置连接与凭据；无平台共享模型池、平台供给免费额度或作者凭据自动共享 |
| 本次范围外 | 商业支付结算、多区域容灾、全量音视频理解、GraphRAG 等研究能力和无边界自主执行；普通公共仓库与应用发布不在排除范围内 |

每项能力的授权、异常、停止和验收条件都属于交付范围。插件详细规则见[插件专题](../topics/01-plugin-system.md)，公共资源详细规则见[公共仓库专题](../topics/02-public-repositories.md)；本阶段负责把它们接入完整用户旅程，避免在多份文档重复定义不同细则。

## 3. 角色与典型场景

| 角色 | 场景 | 期望结果 |
|---|---|---|
| 流程设计者 | 同时查询多份资料再形成结论 | 看清每条分支的结果和汇总依据 |
| 业务确认人 | 长任务中需要确认一次外部修改 | 能看见准确内容并允许、拒绝或要求修改 |
| 应用开发者 | 让多个 Agent 分工完成一项任务 | 分工、依赖、总费用和最终责任清楚 |
| 研发使用者 | 让 Agent 修改项目文件并验证 | 改动、验证结果与产物可审查，执行范围受限 |
| 知识维护者 | 文本能力无法解决图表或多资料问题 | 针对已知失败开展有证据的能力增强 |
| 个人用户 / 租户负责人 | 发布自己的应用或采用公共资源 | 使用全部功能，并清楚知道执行身份与自有服务消耗 |
| 公共仓库管理员 | 审核一个具体资源版本 | 只有审核通过的精确版本对正常用户可见和可采用 |
| 平台运营人员 | 定位失败、限额、异常任务与内容风险 | 能看状态与影响范围，不默认读取用户凭据和私有正文 |

## 4. 详细功能需求

### PA-P6-001：组织并行工作并明确汇总条件

- **使用场景**：流程中的多项工作相互独立，可同时执行后形成结果。
- **行为要求**：设计者可配置并行分支、分支名称、各自输入和需要的结果；明确等待所有被选中分支、允许部分成功或获得首个满足条件结果等汇总规则。运行时分别展示进度、费用、失败与是否参与最终结论。
- **边界与异常**：未被选中的分支不应成为永久等待条件。不同分支给出冲突结果时，按已确认规则处理或交由用户决定，不能静默覆盖。停止任务后不再发起新分支，已在执行的操作显示实际状态。
- **验收 PA-P6-001-A1**：包含成功、失败和未选中分支的任务能按声明的规则完成或停止，不出现原因不明的等待。
- **验收 PA-P6-001-A2**：两个分支产出冲突结论时，用户能查看来源、处理规则和最终选择。

### PA-P6-002：执行有明确边界的循环与批量任务

- **使用场景**：需要逐项处理一批资料，或按条件多次改进结果。
- **行为要求**：开始前明确待处理对象、结束条件、最大轮次、时间及费用限制；显示每轮输入、结果、进度和停止原因。用户可选择失败后停止或继续其他独立项目，并能查看未处理范围。
- **边界与异常**：模型反复生成相同动作、条件始终不满足或输入规模过大时，仍受硬性限制约束。具有外部影响的操作不能因循环、重试或批量重跑而被无提示重复执行。
- **验收 PA-P6-002-A1**：结束条件始终不满足时，任务在确认的限制内停止，保留各轮结果。
- **验收 PA-P6-002-A2**：批量任务部分失败后，完成、失败、未处理数量对齐；继续操作明确列出将再次处理的项目。

### PA-P6-003：支持可审查的人工介入

- **使用场景**：任务进行到需要确认的文件修改、数据写入或对外操作。
- **行为要求**：展示拟执行动作、对象、关键参数、变更内容、预计影响和费用，指明有权处理的人员。确认人可批准、拒绝或要求修改；等待期间可离开页面，重新进入仍能看到真实状态。批准范围必须具体，不能把一次确认扩大为无限授权。
- **边界与异常**：确认过期、批准后执行前撤回、关键内容变更或确认人权限失效时，应重新检查是否还能执行。已完成的外部动作无法仅靠撤回确认自动撤销，应如实显示并提供可行的后续处理信息。超时与重复确认不会造成重复操作。
- **验收 PA-P6-003-A1**：拒绝后不执行对应动作；要求修改后，修改后的动作必须重新展示，不能沿用旧确认。
- **验收 PA-P6-003-A2**：批准内容在执行前被改变或权限被撤销时，原批准不能使变更后的动作继续执行。

### PA-P6-004：中断后恢复可理解的长任务

- **使用场景**：任务因人工等待、暂时失败或中断而暂停，需要继续未完成工作。
- **行为要求**：恢复前展示原任务目标、已完成与待完成步骤、采用的 Agent、工作流、插件、Skill、Prompt 和资料版本、已发生外部影响、累计开销及剩余额度。用户可继续原任务，或明确创建采用新配置的新任务；两者的关系清楚可查。正常插件升级保留旧任务所需版本，停用或撤权仍在恢复时生效。
- **边界与异常**：恢复时重新检查当前权限和资源可用性，不能恢复已经撤回的授权。已完成的外部写入不得盲目重放；执行结果不明时先核对或交由用户判断。原版本不可用、证据缺失或状态不一致时停止并说明，不能凭摘要猜测为已完成。
- **验收 PA-P6-004-A1**：中断后恢复，已确认完成的外部动作不会重复发生，未完成步骤使用原先确认的版本和额度。
- **验收 PA-P6-004-A2**：用户选择新版本继续时，生成清楚关联的新任务，旧运行记录不被改写。

### PA-P6-005：让多个 Agent 按明确职责协作

- **使用场景**：一个任务需要资料查找、方案编写、结果检查等不同角色分工。
- **行为要求**：设置各 Agent 的职责、输入、可用资源、成果要求、依赖关系和负责汇总者；展示任务委派、进度、交付物与汇总依据。下属任务共享明确的总预算，并可进一步设置更严格限制。最终任务必须根据可核验成果判断是否完成。
- **边界与异常**：被委派的 Agent 不得获得超出原任务授权的工具和资料。Agent 之间的消息和结果不能充当用户批准。循环委派、重复工作、冲突意见和某个 Agent 失败时，需要显式停止条件或处理规则。
- **验收 PA-P6-005-A1**：多个 Agent 完成分工任务后，用户可从最终结论回到各自贡献、工具操作和费用。
- **验收 PA-P6-005-A2**：某 Agent 尝试使用未授权工具或再次委派以扩大权限时被拒绝，失败原因可见且总预算不被重置。

### PA-P6-006：提供范围明确的任务执行空间

- **使用场景与已有基础**：阶段 3 已为基础代码插件和 Skill 脚本建立受控执行与隔离；本阶段使同一边界覆盖复杂研发任务、多 Agent 分工及人工等待后的继续执行，不能把基础隔离推迟至本阶段。
- **行为要求**：复杂任务开始前明确可访问的文件范围、可修改内容、允许的外部访问、运行时长和资源额度；用户可查看当前授权。子任务和恢复操作只能在指定范围内执行，产生的变更与验证结果能够检查。停止或到期后，新增执行被阻止，已产生文件按保留规则处理。
- **边界与异常**：项目之间的文件与凭据不可互相访问，任务不能取得平台管理能力。文件访问越界、外部访问不在允许范围、资源超限或执行异常时，应停止相关操作并说明。缺少满足这些条件的执行能力时，不开放任意脚本运行。
- **验收 PA-P6-006-A1**：多个子任务在各自获准范围完成文件修改和验证，人工等待后继续执行仍可检查改动、授权范围和验证结果。
- **验收 PA-P6-006-A2**：委派或恢复后尝试读取其他项目文件、访问未获准位置或超额执行时仍被限制，凭据不出现在任务输出中。

### PA-P6-007：受控使用 Skill 脚本和本地 MCP 能力

- **使用场景与已有基础**：承接阶段 3 已开放的受控 Skill 脚本能力，将其与本地 MCP、复杂审批、任务恢复及应用发布连接起来。
- **行为要求**：启用前展示来源、版本、说明、所需文件与外部访问范围、预计操作影响以及依赖是否满足。用户明确授予对应使用权限后才能执行；委派与恢复仍核对当前授权。Skill 的文字指导、资料阅读、脚本执行和工具启用应分别可见，能够单独禁用执行部分，并追溯应用实际采用的版本。
- **边界与异常**：导入 Skill、安装扩展或发现工具不等于同意执行。正文和工具输出无法自行扩大授权。执行依赖不满足、版本已停用或受控执行空间不可用时，给出可操作说明并停止执行部分。
- **验收 PA-P6-007-A1**：同一个 Skill 可以仅阅读指导而不运行脚本；授予特定操作权限后只允许该范围的执行。
- **验收 PA-P6-007-A2**：本地 MCP 能力缺失或被撤权时不自动转为无限制执行，界面显示受影响步骤及原因。

### PA-P6-008：交付可追溯且可核验的任务产物

- **使用场景**：任务输出文档、代码修改、数据文件或分析报告，需要交付使用。
- **行为要求**：产物有名称、版本、所属任务、创建者或负责 Agent、生成依据和可访问范围。对修改既有文件的任务展示变更内容，对验证活动展示实际检查结果。用户可预览、下载、比较、采用或拒绝产物；采用不应抹去原始版本和生成记录。
- **边界与异常**：文件未生成、仅有计划、验证未执行或结果失败时，不能宣称交付完成。下载链接失效、文件缺失或权限变化应给出真实状态。产物中可能包含受限来源内容，导出前继续遵守对应权限。
- **验收 PA-P6-008-A1**：从任务结果能打开实际文件，并核对其内容、变更与声称完成的检查一致。
- **验收 PA-P6-008-A2**：验证失败的代码修改仍可作为待处理产物查看，但不会被标记为已验证可用。

### PA-P6-009：动态复用后端与前端插件能力

- **使用场景**：用户自行开发或采用插件，为平台增加后端能力和自定义前端界面，并在自己的租户使用。
- **行为要求**：按插件专题完成创建、试用、打包、安装、配置、授权、启用、升级、停用与卸载；支持插件定义的后端能力及受控前端界面。展示来源、精确版本、依赖、权限、使用范围和受影响应用。动态安装或升级不能要求重启整个平台或全部 Runtime，允许独立插件执行实例按约定替换。
- **边界与异常**：安装不等于执行授权，公开审核不等于可信执行。正常升级保持在途任务使用原版本，新增任务采用明确选定的新版本；停用和撤权仍应限制后续调用。升级失败不得破坏原可用版本，卸载必须处理未完成任务和依赖，不能静默删除历史依据。
- **验收 PA-P6-009-A1**：安装含后端能力与自定义界面的插件，完成配置和实际使用；无关应用和 Runtime 继续运行，界面不能越权读取其他租户资料。
- **验收 PA-P6-009-A2**：插件存在运行中及待恢复任务时完成升级、失败回退和停用验证，新旧版本、任务影响及权限结果符合插件专题，并保留完整记录。

### PA-P6-010：复核记忆候选并处理过期与冲突

- **使用场景与已有基础**：阶段 3 的 PA-P3-012 已提供获准的跨会话记忆、来源查看、修改、停用、删除和项目隔离。本阶段在该基础上处理新提取的候选事实、过期提示，以及旧记忆与其他事实或当前指示的冲突，不延后阶段 3 的基础能力。
- **行为要求**：用户可复核候选事实的内容、来源、适用范围、确认状态和有效期，决定是否将其纳入已有记忆。使用记忆前发现事实过期或相互矛盾时，展示相关来源和待确认问题，允许用户纠正其适用性。当前明确指示与普通旧偏好冲突时，应采用当前指示，并说明旧偏好在本次任务中不适用。
- **边界与异常**：未经允许不得把敏感内容或推测作为已确认事实长期保存。无法消除的冲突保持待确认，不能静默合成为新事实；过期提示不能被当作用户已同意延长有效期。当前指示对普通偏好的覆盖不扩大工具、资料或执行权限，既有撤权和删除规则继续生效。
- **验收 PA-P6-010-A1**：产生未经确认的候选事实后，用户能够检查来源和适用范围；未通过复核的候选不会被当作已确认记忆用于后续任务，接受或拒绝的结果可查。
- **验收 PA-P6-010-A2**：准备过期、相互矛盾及与当前指示冲突的记忆样本，分别验证过期提示、冲突待确认和当前指示优先；处理过程不自动扩大权限或恢复已停用内容。

### PA-P6-011：交付扫描文本、表格与跨文档知识能力

- **使用场景**：用户的知识包含清晰扫描文本、带行列含义的表格，以及需要多份资料共同证明的问题。
- **行为要求**：三类能力均必须交付：扫描文字提取与人工检查、保留行列标题和必要单元格关系的表格知识、跨文档多证据问答。用户能检查提取结果、来源位置、缺失或低可信内容，保存版本并对照阶段 5 的人工核验样本。使用外部模型或处理服务时，采用本租户配置并记录用量。
- **边界与异常**：不保证识别任意手写体、损坏扫描件或复杂图像语义；无法可靠读取时明确指出，不补造原文。多文档答案缺少必要资料时不能宣称证据齐全。GraphRAG、全量音视频及任意多模态理解留作后续研究，不影响三项已承诺能力的验收。
- **验收 PA-P6-011-A1**：分别用扫描文本、表格和跨文档问题样本完成原文核对与问答，逐项验证文字、行列含义、引用和必要证据覆盖，三类均有实际运行证据。
- **验收 PA-P6-011-A2**：对失败、低可信及缺少必要文档的样本，结果如实说明局限；对照报告包含改善、回归、Token、时间和费用，不自动替换已采用的知识配置。

### PA-P6-012：依据任务选择模型并说明切换

- **使用场景**：不同任务对质量、速度、输入内容和费用有不同要求，或原模型暂时不可用。
- **行为要求**：用户可在自己配置并获准使用的模型连接中设置允许范围、任务要求、费用及质量约束，选择固定模型或经确认的选择规则。任务记录说明实际采用的模型、连接所属租户、选择或切换原因、结果变化与费用。规则变更形成可比较的版本并接受质量中心验证；平台不提供候补共享模型池。
- **边界与异常**：替代模型不满足资料使用范围、输入能力或费用限制时不能悄悄切换。切换可能影响答案和任务结果时应显式说明；对已经产生外部影响的步骤，不得仅因模型切换自动重新执行。
- **验收 PA-P6-012-A1**：原模型不可用时，只采用获准且满足约束的替代选择，并保留切换原因；没有可用选择时清楚失败。
- **验收 PA-P6-012-A2**：在同一批任务上比较选择规则前后的质量、费用和耗时，能够判断其适用范围与回归情况。

### PA-P6-013：将已验证的配置发布为应用版本

- **使用场景**：个人用户完成 Agent 或工作流调试，希望形成可稳定使用的应用。
- **行为要求**：应用有名称、用途、输入要求、结果说明、负责人、所属租户和版本；发布前检查所引用的 Agent、流程、Prompt、Skill、插件、知识配置及本租户必要凭据是否可用。用户能从草稿形成确定版本，检查、启用、停止发布，并查看发布历史与关联评测证据。修改草稿不改变已经发布的版本。
- **边界与异常**：缺少必需配置、依赖停用、引用未审核公共版本或范围不清的凭据时，不得宣称应用已可运行。发布应用供调用与提交应用模板到公共仓库是两个动作；后者还需要管理员审核且不默认开放前者的运行入口。
- **验收 PA-P6-013-A1**：从已验证的流程创建应用并发布，实际运行记录能追溯精确配置；修改草稿后旧入口仍使用原版本。
- **验收 PA-P6-013-A2**：缺少用户模型凭据或必需插件时，发布检查指出缺项；仅提交公共仓库不会让应用自动产生公开可调用入口。

### PA-P6-014：通过 Web 与 API 受控使用应用

- **使用场景**：应用负责人希望自己、受邀使用者或外部系统调用已发布应用。
- **行为要求**：提供 Web 使用入口与 API 调用方式，负责人明确访问范围、访问凭据或身份要求、允许输入、结果查看范围、单次限制和总配额。每个入口必须明确执行租户、费用归属、模型与工具凭据归属；调用记录同时区分访问者和实际执行主体。可停用入口或撤销访问凭据。
- **边界与异常**：公共仓库中的模板可见不等于原作者托管应用免费或无限调用。采用模板后，使用者在自己的租户配置自己的模型与工具；如负责人主动开放托管调用，则由该应用声明的执行租户承担已确认的调用消耗，访问者不能因此访问作者私有配置、凭据或全部资料。浏览器传入的租户标识不能自行决定执行身份。
- **验收 PA-P6-014-A1**：Web 和 API 分别完成获准调用，并查看正确执行租户与费用归属；错误凭据、超额或越权访问被拒绝。
- **验收 PA-P6-014-A2**：用户乙采用用户甲公开模板后，只能使用乙自己配置的服务；直接访问甲未开放入口或请求甲的凭据、运行正文均不能成功。

### PA-P6-015：提供有边界的 Webhook 触发与结果通知

- **使用场景**：外部系统需要根据事件启动应用，或在任务完成后接收结果状态。
- **行为要求**：可为已发布应用登记允许的触发来源、访问校验、事件内容范围、执行租户和配额；为结果通知设置获准接收目标、内容和失败处理。用户能查看事件是否接受、关联任务、通知状态、失败原因与再次发送记录，重复事件应能辨识。
- **边界与异常**：无有效校验的事件不启动任务；同一事件重发不能不受控制地重复有外部影响的动作。通知失败不能伪装任务失败或反复重跑整个任务；再次通知与再次执行业务操作要分开。接收地址变更和敏感结果外发需要相应权限，事件内容不能充当新的用户授权。
- **验收 PA-P6-015-A1**：合法事件触发一次任务，重复或无效事件有明确记录，执行租户、任务及费用可追溯。
- **验收 PA-P6-015-A2**：结果通知失败后可受控重发；重发不会再次执行任务或把其他租户的结果发送给该地址。

### PA-P6-016：切换、回退与下线应用版本

- **使用场景**：新应用版本出现质量回归，负责人需要恢复之前的可用版本或停止使用。
- **行为要求**：展示可用版本及其依赖、配置和评测差异；用户选择新请求使用的版本，切换或回退前检查目标仍可用且获准使用。既有运行保留当时版本和结果，下线后阻止新的调用。对仍在运行或等待确认的任务，显示处理方式与影响范围。
- **边界与异常**：版本回退不恢复已撤销的权限、凭据或已经停用的插件，也不撤销已完成外部操作。目标依赖不可用时明确拒绝或先完成修复，不能静默换成当前依赖。公共仓库的下架与应用运行下线要分别呈现，不能混为一个成功状态。
- **验收 PA-P6-016-A1**：新旧请求在切换前后分别使用预期版本，旧任务记录不被改写，回退后新请求可以使用已验证旧版。
- **验收 PA-P6-016-A2**：目标版本引用已撤权或停用资源时不能回退成可执行状态；下线入口后新请求被拒绝，既有任务可查。

### PA-P6-017：运营个人租户与平台用户

- **使用场景**：个人注册使用完整平台，平台管理员需要处理账号状态、租户异常和授权问题。
- **行为要求**：每个个人用户有自己的租户及完整功能入口，可管理其应用、资源、凭据、配额和私有记录。平台管理员可以按职责查看账号与租户状态、处理停用或恢复、查看必要操作记录；应用访问者、租户负责人和平台管理员的身份与权限明确区分。配置或使用外部服务时须指向用户自己的连接。
- **边界与异常**：个人租户不因缺少团队或商业套餐而失去功能；也不能越过授权访问其他租户。平台管理员的内容审核职责不默认包含读取用户模型密钥和全部私有对话。账号停用影响新增登录与操作、托管入口及未完成任务的方式必须清楚展示，恢复账号不恢复已明确撤销的单独授权。
- **验收 PA-P6-017-A1**：两个个人用户均能访问全部功能，但不能读取、调用或导出对方私有资源、凭据和用量。
- **验收 PA-P6-017-A2**：管理员按授权停用用户后，新操作与应用入口按规则受限；审计中可查对象、操作者、理由和影响，凭据不泄漏。

### PA-P6-018：接入统一的公共资源仓库

- **使用场景**：用户希望将私用成果提交公开，或采用其他用户经审核的资源。
- **行为要求**：公共仓库统一容纳应用、插件、Skill、MCP 和 Prompt 模板；任何正常个人用户均可私用并提交公开。管理员审核精确版本，通过后所有正常用户可见、检索和采用；采用仍需在自己的租户完成配置与授权。审核、重审、撤回、下架、通知和使用影响遵守公共仓库专题。
- **边界与异常**：私人草稿、待审核及未通过版本不能经直链、搜索、预览、导出等入口公开。应用模板不携带作者密钥；MCP 资源发布连接说明与参数模板，不意味着外部服务免费或可由所有用户直接连接。插件前端和 Skill 脚本也不会因公开审核而获得执行授权。
- **验收 PA-P6-018-A1**：五类资源均完成“私用 → 提交 → 审核 → 正常用户查找 → 在本人租户采用”的旅程，未审核版本始终不可公开读取。
- **验收 PA-P6-018-A2**：资源更新、撤回或风险下架后，目录与各种读取入口状态一致，已采用用户获知影响，作者私有原件和凭据不会被公开副本修改或泄漏。

### PA-P6-019：观察应用调用并执行租户配额

- **使用场景**：用户和运营人员需要解释某个已发布应用的失败、限额和 Token 消耗。
- **行为要求**：按当前权限查看应用入口、版本、运行、节点或子任务、工具调用、审批、Token 与停止原因；通过统一任务关系定位一次完整业务调用。租户、应用和单任务额度共同约束 Web、API、Webhook 及后台恢复任务；提醒和停止状态清楚可见，沿用阶段 5 统一用量口径。
- **边界与异常**：入口切换、委派、重试或恢复不能重置总额度；父子任务和通知重发不得重复累计同一模型请求。额度不表示平台代购服务，未知价格和迟到用量保持可见。运行追踪默认脱敏且不暴露其他租户内容。
- **验收 PA-P6-019-A1**：通过三种入口调用同一应用，可追到正确版本、执行租户、子任务和统一 Token 面板，汇总无重复。
- **验收 PA-P6-019-A2**：达到租户或应用停止额度后，新增调用受到限制；运行记录说明限制来源，用户不能换入口绕过。

### PA-P6-020：提供必要状态检查与运营告警

- **使用场景**：模型凭据失效、插件不可用、任务长期无进展或预算接近限制，需要及时处理。
- **行为要求**：用户可查看自己配置的服务连接、应用和插件状态、失败任务与受影响范围；对于连续失败、无进展、额度告警和已知公共资源风险，提供站内提醒和处理入口。平台管理员看到必要的整体健康与故障范围，区分自身运行问题和用户外部服务问题。
- **边界与异常**：未检测不显示健康，检测失败不冒充具体业务已失败；状态与提醒带时间，重复故障合理合并，恢复可辨识。提示信息不包含密钥或不应展示的请求正文，管理员不能凭告警任意查看用户私有内容。
- **验收 PA-P6-020-A1**：模拟失效连接、插件异常及任务无进展，用户能找到受影响应用与建议操作，未受影响功能仍可使用。
- **验收 PA-P6-020-A2**：恢复后状态与通知更新，另一个租户看不到这些私有故障详情，平台健康页面不展示明文凭据。

### PA-P6-021：按范围导出、保留与删除运营数据

- **使用场景**：用户整理项目、停用应用或删除账号，需要知道哪些资料会保留、导出或删除。
- **行为要求**：提供自己有权管理的资源、运行内容和用量记录的保留说明及导出/删除操作；操作前展示影响范围、仍被依赖的内容、公开副本和已采用副本的区别。敏感凭据不进入普通导出，删除进度与失败可追踪；必要审计信息按明确规则保留，并限定访问范围。
- **边界与异常**：删除私有源不应无提示改写已审核公共版本；需要撤回公开内容时走公共仓库流程。已被其他用户合法取得的副本不能宣称远程彻底删除；发现敏感泄漏可按风险流程停止访问并通知。备份中的保留和恢复后删除要求由阶段 7 验证，不能只删除页面列表就宣称数据全部清除。
- **验收 PA-P6-021-A1**：执行一次含运行内容、依赖应用和公开版本的删除请求，能看清各对象的处理状态及剩余责任，当前可用入口不再提供已删除私有正文。
- **验收 PA-P6-021-A2**：普通导出不包含凭据或其他租户数据；部分删除失败有明确记录，并能供阶段 7 恢复演练核对。

## 5. 权限、责任与完成判定

任务发起人、确认人、各 Agent 与工具的操作范围必须清楚。委派、恢复、循环、安装和记忆都不会产生额外授权；已经撤回的权限不能因使用旧任务信息重新生效。一个任务的全部分支、子任务和重试共同计入其适用预算。

权限校验按照已确认的 Sa-Token 方案由技术文档落实；需求层必须证明当前用户、租户、资源、操作和凭据归属一致。公共仓库审核决定可公开展示哪些内容，应用发布决定谁可以调用哪个运行版本，两者均不能隐式共享作者密钥。用户自己的外部服务计费与平台内估算、额度必须分开表述。

完成判定以可访问的实际成果、可核查的执行结果和需求验收为依据。计划、工具调用成功或模型的完成声明本身均不足以证明整个任务已完成。其余要求见[跨阶段要求](../03-cross-cutting-requirements.md)。

| P6-T15 | 数据导出删除可核对 | PA-P6-021 | P6-T10—P6-T14；依赖、公开副本、删除进度与阶段 7 恢复检查输入 |

## 8. 实施前需细化的参数

- 各项必交付能力的首批真实样本、并发与规模边界；不能以参数尚待细化推迟确认的功能范围。
- 有外部影响的动作种类、确认责任人、确认有效期、允许恢复的条件和结果不明时的处理责任。
- 任务执行空间允许的文件、外部访问、运行资源、产物保留和清理规则。
- 可接受的扩展来源、更新影响处理方式，以及记忆候选复核责任、过期提示与冲突处理规则。
- 扫描文本、表格、跨文档样本和模型选择规则的业务质量条件。
- 公开应用的默认访问方式、单任务额度、Webhook 通知重试范围和数据保留期限，均在明确执行租户与自有凭据前提下确定。
