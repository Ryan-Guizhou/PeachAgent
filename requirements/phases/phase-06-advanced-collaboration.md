# 阶段 6：协作、长任务与受控扩展需求

> 版本：v0.1 · 日期：2026-11-23
>
> 状态：后续需求草案，待项目负责人按实际需要选择并确认；本文功能尚未实现。
>
> 所属路线：阶段 1—5 完成首个完整核心版本后，按明确业务问题推进增强能力。
>
> 文档边界：规定增强能力的使用结果与限制，不确定技术实现。

## 1. 背景与目标

在单个 Agent、基础工作流、知识问答和质量比较能够稳定完成任务后，平台可能需要处理更长的工作、多人确认、多个 Agent 分工，以及在受控环境中生成和验证文件。此时需要让用户清楚看到任务归属、执行边界、恢复依据与最终产物，防止能力增加后任务变得不可理解。

本阶段是后续能力池，不要求把所有能力作为一个不可拆分的大版本交付。每次启动一个增强任务，都应说明要解决的实际问题、依赖的已完成能力、验收样本以及预算。高级知识处理和模型选择尤其需要阶段 5 的失败案例与对照结果作为投入依据。

## 2. 范围与启用条件

| 范围 | 内容 |
|---|---|
| 可选增强 | 工作流并行与循环、人工介入、长任务恢复、多 Agent 协作、隔离执行、产物管理、扩展包、记忆增强、高级知识处理与模型选择 |
| 启用前提 | 对应前序能力已验收；权限、预算、运行记录和质量判断能够覆盖新增路径 |
| 首个核心版本边界 | 阶段 1—5 的完成不依赖本阶段所有功能完成；早期仍可完成有限步骤和无脚本的受控任务 |
| 持续排除 | 商业插件交易、完整商业结算、多区域运营、复杂发布治理、无边界自主执行 |

选定某项增强后，该项需求中的授权、异常、停止和验收条件随之生效，不能仅实现顺利执行路径。

## 3. 角色与典型场景

| 角色 | 场景 | 期望结果 |
|---|---|---|
| 流程设计者 | 同时查询多份资料再形成结论 | 看清每条分支的结果和汇总依据 |
| 业务确认人 | 长任务中需要确认一次外部修改 | 能看见准确内容并允许、拒绝或要求修改 |
| 应用开发者 | 让多个 Agent 分工完成一项任务 | 分工、依赖、总费用和最终责任清楚 |
| 研发使用者 | 让 Agent 修改项目文件并验证 | 改动、验证结果与产物可审查，执行范围受限 |
| 知识维护者 | 文本能力无法解决图表或多资料问题 | 针对已知失败开展有证据的能力增强 |

## 4. 详细功能需求

### PA-P6-001：组织并行工作并明确汇总条件

- **使用场景**：流程中的多项工作相互独立，可同时执行后形成结果。
- **行为要求**：设计者可配置并行分支、分支名称、各自输入和需要的结果；明确等待所有被选中分支、允许部分成功或获得首个满足条件结果等汇总规则。运行时分别展示进度、费用、失败与是否参与最终结论。
- **边界与异常**：未被选中的分支不应成为永久等待条件。不同分支给出冲突结果时，按已确认规则处理或交由用户决定，不能静默覆盖。停止任务后不再发起新分支，已在执行的操作显示实际状态。
- **验收 PA-P6-001-A1**：包含成功、失败和未选中分支的任务能按声明的规则完成或停止，不出现原因不明的等待。
- **验收 PA-P6-001-A2**：两个分支产出冲突结论时，用户能查看来源、处理规则和最终选择。

### PA-P6-002：执行有明确边界的循环与批量任务

- **使用场景**：需要逐项处理一批资料，或按条件多次改进结果。
- **行为要求**：开始前明确待处理对象、结束条件、最大轮次、时间及费用限制；显示每轮输入、结果、进度和停止原因。用户可选择失败后停止或继续其他独立项目，并能查看未处理范围。
- **边界与异常**：模型反复生成相同动作、条件始终不满足或输入规模过大时，仍受硬性限制约束。具有外部影响的操作不能因循环、重试或批量重跑而被无提示重复执行。
- **验收 PA-P6-002-A1**：结束条件始终不满足时，任务在确认的限制内停止，保留各轮结果。
- **验收 PA-P6-002-A2**：批量任务部分失败后，完成、失败、未处理数量对齐；继续操作明确列出将再次处理的项目。

### PA-P6-003：支持可审查的人工介入

- **使用场景**：任务进行到需要确认的文件修改、数据写入或对外操作。
- **行为要求**：展示拟执行动作、对象、关键参数、变更内容、预计影响和费用，指明有权处理的人员。确认人可批准、拒绝或要求修改；等待期间可离开页面，重新进入仍能看到真实状态。批准范围必须具体，不能把一次确认扩大为无限授权。
- **边界与异常**：确认过期、批准后执行前撤回、关键内容变更或确认人权限失效时，应重新检查是否还能执行。已完成的外部动作无法仅靠撤回确认自动撤销，应如实显示并提供可行的后续处理信息。超时与重复确认不会造成重复操作。
- **验收 PA-P6-003-A1**：拒绝后不执行对应动作；要求修改后，修改后的动作必须重新展示，不能沿用旧确认。
- **验收 PA-P6-003-A2**：批准内容在执行前被改变或权限被撤销时，原批准不能使变更后的动作继续执行。

### PA-P6-004：中断后恢复可理解的长任务

- **使用场景**：任务因人工等待、暂时失败或中断而暂停，需要继续未完成工作。
- **行为要求**：恢复前展示原任务目标、已完成与待完成步骤、采用的 Agent、工作流、Skill、Prompt 和资料版本、已发生外部影响、累计开销及剩余额度。用户可继续原任务，或明确创建采用新配置的新任务；两者的关系清楚可查。
- **边界与异常**：恢复时重新检查当前权限和资源可用性，不能恢复已经撤回的授权。已完成的外部写入不得盲目重放；执行结果不明时先核对或交由用户判断。原版本不可用、证据缺失或状态不一致时停止并说明，不能凭摘要猜测为已完成。
- **验收 PA-P6-004-A1**：中断后恢复，已确认完成的外部动作不会重复发生，未完成步骤使用原先确认的版本和额度。
- **验收 PA-P6-004-A2**：用户选择新版本继续时，生成清楚关联的新任务，旧运行记录不被改写。

### PA-P6-005：让多个 Agent 按明确职责协作

- **使用场景**：一个任务需要资料查找、方案编写、结果检查等不同角色分工。
- **行为要求**：设置各 Agent 的职责、输入、可用资源、成果要求、依赖关系和负责汇总者；展示任务委派、进度、交付物与汇总依据。下属任务共享明确的总预算，并可进一步设置更严格限制。最终任务必须根据可核验成果判断是否完成。
- **边界与异常**：被委派的 Agent 不得获得超出原任务授权的工具和资料。Agent 之间的消息和结果不能充当用户批准。循环委派、重复工作、冲突意见和某个 Agent 失败时，需要显式停止条件或处理规则。
- **验收 PA-P6-005-A1**：多个 Agent 完成分工任务后，用户可从最终结论回到各自贡献、工具操作和费用。
- **验收 PA-P6-005-A2**：某 Agent 尝试使用未授权工具或再次委派以扩大权限时被拒绝，失败原因可见且总预算不被重置。

### PA-P6-006：提供范围明确的任务执行空间

- **使用场景**：研发任务需要读取、修改文件或执行必要的验证活动。
- **行为要求**：开始前明确可访问的文件范围、可修改内容、允许的外部访问、运行时长和资源额度；用户可查看当前授权。任务只能在指定范围内操作，产生的变更与验证结果能够检查。停止或到期后，新增执行被阻止，已产生文件按保留规则处理。
- **边界与异常**：项目之间的文件与凭据不可互相访问，任务不能取得平台管理能力。文件访问越界、外部访问不在允许范围、资源超限或执行异常时，应停止相关操作并说明。缺少满足这些条件的执行能力时，不开放任意脚本运行。
- **验收 PA-P6-006-A1**：在允许范围内完成一项文件修改和验证，能够检查改动、命令意图与验证结果。
- **验收 PA-P6-006-A2**：尝试读取其他项目文件、访问未获准位置或超额执行时被限制，凭据不出现在任务输出中。

### PA-P6-007：受控使用 Skill 脚本和本地 MCP 能力

- **使用场景**：已确认的 Skill 或本地工具需要执行辅助程序才能完成任务。
- **行为要求**：启用前展示来源、版本、说明、所需文件与外部访问范围、预计操作影响以及依赖是否满足。用户明确授予对应使用权限后才能执行。Skill 的文字指导、资料阅读、脚本执行和工具启用应分别可见，能够单独禁用执行部分。
- **边界与异常**：导入 Skill、安装扩展或发现工具不等于同意执行。正文和工具输出无法自行扩大授权。执行依赖不满足、版本已停用或受控执行空间不可用时，给出可操作说明并停止执行部分。
- **验收 PA-P6-007-A1**：同一个 Skill 可以仅阅读指导而不运行脚本；授予特定操作权限后只允许该范围的执行。
- **验收 PA-P6-007-A2**：本地 MCP 能力缺失或被撤权时不自动转为无限制执行，界面显示受影响步骤及原因。

### PA-P6-008：交付可追溯且可核验的任务产物

- **使用场景**：任务输出文档、代码修改、数据文件或分析报告，需要交付使用。
- **行为要求**：产物有名称、版本、所属任务、创建者或负责 Agent、生成依据和可访问范围。对修改既有文件的任务展示变更内容，对验证活动展示实际检查结果。用户可预览、下载、比较、采用或拒绝产物；采用不应抹去原始版本和生成记录。
- **边界与异常**：文件未生成、仅有计划、验证未执行或结果失败时，不能宣称交付完成。下载链接失效、文件缺失或权限变化应给出真实状态。产物中可能包含受限来源内容，导出前继续遵守对应权限。
- **验收 PA-P6-008-A1**：从任务结果能打开实际文件，并核对其内容、变更与声称完成的检查一致。
- **验收 PA-P6-008-A2**：验证失败的代码修改仍可作为待处理产物查看，但不会被标记为已验证可用。

### PA-P6-009：复用并管理有来源的扩展包

- **使用场景**：团队希望复用经过验证的工具、Skill、Prompt 或流程组合。
- **行为要求**：扩展说明包含来源、版本、能力清单、适用条件、依赖、所需权限及与已有资源的关系。安装前可查看将新增或更新什么；安装、更新、禁用和移除均显示影响范围。应用可明确选择继续使用原版本或采用新版本。
- **边界与异常**：来源不明、内容变更、依赖缺失或版本不适用时，不得静默启用。安装成功不等于获得所有权限；移除扩展不得无提示破坏已确认的应用。依赖的可执行能力仍须满足受控执行要求。
- **验收 PA-P6-009-A1**：导入一个复用包后，用户能检查新增资源、所需权限和依赖，未授权能力保持不可执行。
- **验收 PA-P6-009-A2**：更新或移除被使用的扩展时，影响的应用和版本明确展示，历史运行仍能说明当时采用内容。

### PA-P6-010：复核记忆候选并处理过期与冲突

- **使用场景与已有基础**：阶段 3 的 PA-P3-012 已提供获准的跨会话记忆、来源查看、修改、停用、删除和项目隔离。本阶段在该基础上处理新提取的候选事实、过期提示，以及旧记忆与其他事实或当前指示的冲突，不延后阶段 3 的基础能力。
- **行为要求**：用户可复核候选事实的内容、来源、适用范围、确认状态和有效期，决定是否将其纳入已有记忆。使用记忆前发现事实过期或相互矛盾时，展示相关来源和待确认问题，允许用户纠正其适用性。当前明确指示与普通旧偏好冲突时，应采用当前指示，并说明旧偏好在本次任务中不适用。
- **边界与异常**：未经允许不得把敏感内容或推测作为已确认事实长期保存。无法消除的冲突保持待确认，不能静默合成为新事实；过期提示不能被当作用户已同意延长有效期。当前指示对普通偏好的覆盖不扩大工具、资料或执行权限，既有撤权和删除规则继续生效。
- **验收 PA-P6-010-A1**：产生未经确认的候选事实后，用户能够检查来源和适用范围；未通过复核的候选不会被当作已确认记忆用于后续任务，接受或拒绝的结果可查。
- **验收 PA-P6-010-A2**：准备过期、相互矛盾及与当前指示冲突的记忆样本，分别验证过期提示、冲突待确认和当前指示优先；处理过程不自动扩大权限或恢复已停用内容。

### PA-P6-011：针对已知失败增强知识处理与检索

- **使用场景**：质量中心确认文本问答无法处理扫描件、图表、表格关系或跨资料问题。
- **行为要求**：按已确认的错误类型选择增强范围，分别定义输入资料、期望证据、答案要求、预算和基线。可选择支持扫描资料、图文与表格证据、跨资料关系和需要多个证据的问答；对新增能力提供来源定位、处理结果检查和与原方案的对照。
- **边界与异常**：各类增强独立确认与验收，不把本条解释为必须一次支持所有资料和研究方向。无法可靠读取的图文内容应说明；推测关系不能被标为原文事实。新增能力不得降低权限隔离和引用要求。
- **验收 PA-P6-011-A1**：对选定的一类已知失败资料，使用人工核验样本对照前后方案，展示证据覆盖、答案、回归、耗时和费用。
- **验收 PA-P6-011-A2**：提升未被证据支持时，报告保留“无明显改善”或“证据不足”的结论，不自动替换原方案。

### PA-P6-012：依据任务选择模型并说明切换

- **使用场景**：不同任务对质量、速度、输入内容和费用有不同要求，或原模型暂时不可用。
- **行为要求**：用户可设置允许使用的模型范围、任务要求、费用及质量约束，选择固定模型或经确认的选择规则。任务记录说明实际采用的模型、选择或切换原因、结果变化与费用。规则变更形成可比较的版本并接受质量中心验证。
- **边界与异常**：替代模型不满足资料使用范围、输入能力或费用限制时不能悄悄切换。切换可能影响答案和任务结果时应显式说明；对已经产生外部影响的步骤，不得仅因模型切换自动重新执行。
- **验收 PA-P6-012-A1**：原模型不可用时，只采用获准且满足约束的替代选择，并保留切换原因；没有可用选择时清楚失败。
- **验收 PA-P6-012-A2**：在同一批任务上比较选择规则前后的质量、费用和耗时，能够判断其适用范围与回归情况。

## 5. 权限、责任与完成判定

任务发起人、确认人、各 Agent 与工具的操作范围必须清楚。委派、恢复、循环、安装和记忆都不会产生额外授权；已经撤回的权限不能因使用旧任务信息重新生效。一个任务的全部分支、子任务和重试共同计入其适用预算。

完成判定以可访问的实际成果、可核查的执行结果和需求验收为依据。计划、工具调用成功或模型的完成声明本身均不足以证明整个任务已完成。其余要求见[跨阶段要求](../03-cross-cutting-requirements.md)。

## 6. 分能力端到端验收

| 增强范围 | 必须演示的完整场景 | 需求范围 |
|---|---|---|
| 复杂流程 | 并行部分失败、冲突汇总、有界循环及停止后的结果查看 | PA-P6-001、PA-P6-002 |
| 人工介入与恢复 | 等待确认、修改后重审、拒绝、中断恢复及防止重复外部动作 | PA-P6-003、PA-P6-004 |
| Agent 协作 | 明确委派、贡献追溯、成员失败、权限与总费用限制 | PA-P6-005 |
| 受控研发任务 | 限定文件范围、执行检查、越界被阻止、真实产物与验证结果交付 | PA-P6-006、PA-P6-007、PA-P6-008 |
| 资源复用 | 安装不授信、更新影响检查、记忆候选复核、过期提示及冲突处理 | PA-P6-009、PA-P6-010 |
| 基于证据的增强 | 对实际错误类别试验高级知识能力或模型规则，展示改善及回归 | PA-P6-011、PA-P6-012 |

项目负责人应在总规划 Issue 中明确本期选定了哪些增强。未选择的增强保持“后续候选”，不得计入本期完成率的分母，也不得标为已经完成；删减或推迟已承诺范围需要记录原因与后续去向。

## 7. 候选 Issue 拆分

## 8. 待确认事项

- 核心版本完成后，首先需要解决的具体长任务或协作场景，以及本期选择的增强范围。
- 有外部影响的动作种类、确认责任人、确认有效期、允许恢复的条件和结果不明时的处理责任。
- 任务执行空间允许的文件、外部访问、运行资源、产物保留和清理规则。
- 可接受的扩展来源、更新影响处理方式，以及记忆候选复核责任、过期提示与冲突处理规则。
- 高级知识处理的首批资料与失败样本，模型选择规则需要满足的业务质量条件。
