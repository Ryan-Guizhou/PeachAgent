# 阶段 2：可视化工作流与可追踪执行

> 版本：v0.1 · 日期：2026-11-23
>
> 状态：需求草案，待项目负责人确认；本文件中的功能尚未实现。
>
> 交付位置：六阶段路线图的第 2 阶段；依赖阶段 1 的项目、模型、权限、用量与限额能力。
>
> 本文规定用户操作与执行结果，不确定画布产品、执行框架、接口形式或数据存储方案。

## 1. 背景与阶段目标

单次对话难以稳定表达“先取得资料、再判断条件、最后生成结果”的业务任务。用户需要将这些步骤组织为可理解的流程，知道数据如何传递，并在结果不符合预期时定位具体步骤。

本阶段完成“拖拽搭建—检查配置—保存可运行版本—输入样例—执行—查看分支与结果”的完整路径。编辑中的草稿与已执行的版本必须清楚区分，避免修改画布后无法解释已有结果。

### 1.1 范围

| 本阶段包含 | 交付边界 |
|---|---|
| 工作流管理、拖拽画布、基础节点、变量选取、条件分支、检查、版本、试运行、运行详情 | 只承诺本阶段已开放的节点和连接方式 |
| 经授权的外部业务工具调用、子流程、项目内复用入口 | 不开放任意脚本执行；工具操作遵循权限与费用限制 |
| Agent、MCP、知识检索节点的产品位置与可见状态 | 对应能力分别在阶段 3、4 到位后开放；阶段 2 不以空节点冒充交付 |
| 明确的取消、失败与重跑行为 | 并行、循环、长任务自动恢复和持久人工等待在阶段 6 提供 |

### 1.2 角色与使用场景

| 角色 | 场景 | 预期结果 |
|---|---|---|
| 应用开发者 | 将信息收集、条件判断、模型处理组织起来 | 不编写业务流程代码也能构建已支持的流程 |
| 业务使用者 | 向已确认流程提供输入 | 获得结果、状态与可理解的失败提示 |
| 流程维护者 | 修改流程并对比历史运行 | 能明确区分改动前后版本和行为 |
| 项目负责人 | 检查工具权限与资源消耗 | 外部操作和子流程不能绕过项目限制 |

## 2. 详细功能需求

### PA-P2-001 工作流创建、查找与复制

- **场景与前置条件：** 有项目编辑权限的成员准备创建一个重复使用的业务流程。
- **要求：** 可创建、命名、描述、查找、复制和归档工作流；列表区分草稿、可运行版本和归档状态。复制后形成独立流程，用户能看出复制来源与需要重新确认的资源授权。
- **异常与边界：** 无可用模型或工具不妨碍先保存草稿，但应明确阻止受影响流程进入可运行状态。复制不自动扩张访问范围，不得复制无权读取的内容或敏感凭证。
- **验收：** PA-P2-001-A1：创建与复制的流程可分别编辑且互不影响；PA-P2-001-A2：可以按名称与状态找到目标流程；PA-P2-001-A3：归档后新运行受限，已有运行仍按授权可查。

### PA-P2-002 拖拽画布与基础编辑

- **场景与前置条件：** 开发者进入流程草稿，希望直观看到任务步骤之间的关系。
- **要求：** 支持从节点列表拖入画布、移动、选中、配置、连接、删除、缩放和定位节点；提供撤销或等效的可恢复编辑体验。节点显示名称、用途与配置是否完整，未保存改动有清楚提示。
- **异常与边界：** 删除节点或连接会影响其他配置时，提示受到影响的内容；误操作不能无提示地使已保存版本丢失。暂时无法保存时保留可恢复的编辑内容并说明状态。
- **验收：** PA-P2-002-A1：用户通过拖拽搭建并调整一个包含分支的流程；PA-P2-002-A2：删除被引用节点时能看到影响且可撤销或恢复；PA-P2-002-A3：离开含未保存改动的画布前可辨识是否会丢失改动。

### PA-P2-003 基础节点与能力说明

- **场景与前置条件：** 开发者需要选择适合某一步任务的节点。
- **要求：** 本阶段至少提供开始、结束、模型调用、条件判断、数据整理、业务工具、Prompt 使用、结果回复和子流程九类能力。每类节点说明用途、所需输入、可产生的结果、可能费用及当前可用条件。数据整理满足字段选择、重命名、文字组合等常见操作。
- **异常与边界：** 不支持的行为不能通过空配置伪装为可用。数据整理不等于任意执行用户代码。未来 Agent、MCP 与知识检索能力显示所属阶段或暂不展示可用入口，不能造成交付误解。
- **验收：** PA-P2-003-A1：各基础节点均有可理解的配置说明与实际执行样例；PA-P2-003-A2：节点输入不足时能够发现；PA-P2-003-A3：未交付能力无法被发布为貌似可执行的步骤。

### PA-P2-004 任务输入与步骤间数据选取

- **场景与前置条件：** 一个步骤需要使用用户输入，或前面步骤已经产生的结果。
- **要求：** 用户可为流程定义业务输入说明、必填项和允许取值；配置节点时可选择可用的前序结果或固定值，并预览数据来源。系统应帮助用户辨识文字、数字、列表等常见内容要求，输出名称应足够明确。
- **异常与边界：** 引用不存在、已删除或本次可能未产生的结果时，不能默默当成空值继续执行。对可选值可由用户明确设置缺失时的处理方式。不能读取其他项目或未授权运行的数据。
- **验收：** PA-P2-004-A1：前一步结果能够被后一节点准确使用；PA-P2-004-A2：引用失效后能定位到具体节点与字段；PA-P2-004-A3：未选择分支产生不了数据时，后续行为符合预先声明的处理方式。

### PA-P2-005 条件分支与路径可解释性

- **场景与前置条件：** 业务输入或前序结果满足不同条件时，需要执行不同步骤。
- **要求：** 可配置清晰的条件、分支名称和未命中时的默认路径；说明多个条件同时满足时采用哪条路径。执行后展示实际选择的路径、判断依据与未执行步骤。分支汇合后只允许使用本次确实产生的数据。
- **异常与边界：** 缺少默认处理、条件不完整、比较内容不合适时应在运行前提示；未命中分支不能被误记为失败或成功执行。不能因为未执行分支一直没有结果而让任务无说明地等待。
- **验收：** PA-P2-005-A1：至少三组输入分别覆盖两条业务分支和默认路径；PA-P2-005-A2：运行详情显示选择原因与未执行步骤；PA-P2-005-A3：汇合后的结果没有混入另一条未执行路径的数据。

### PA-P2-006 运行前检查与问题定位

- **场景与前置条件：** 开发者准备保存可运行版本或发起试运行。
- **要求：** 提供主动检查，识别缺失开始或结束、不可到达步骤、缺少配置、无效变量、不可用资源、未授权工具和本阶段不支持的循环连接。问题应能定位到节点、连接或具体配置；必须修复的问题与建议优化项分开表达。
- **异常与边界：** 存在阻止正常执行的问题时，不得仍显示“检查通过”。检查通过只表示满足已验证条件，不能保证外部工具和模型永远可用。草稿允许保留未完成配置，但不能混同为可运行状态。
- **验收：** PA-P2-006-A1：人为加入无效连接和缺失配置后能准确定位；PA-P2-006-A2：修复前不能将阻塞问题流程保存为可运行版本；PA-P2-006-A3：草稿保存不丢失尚未完成的配置。

### PA-P2-007 草稿、可运行版本与变更说明

- **场景与前置条件：** 流程已完成检查，维护者希望让其他人稳定使用。
- **要求：** 草稿通过检查后，可保存一个具有明确标识的可运行版本，并填写变更说明。已有可运行版本保持可追溯；继续编辑形成新的草稿和后续版本。启动任务时明确本次采用哪个版本及其关联的已确定资源。
- **异常与边界：** 编辑草稿不能改变正在运行或已结束任务的流程含义。停用某个版本时，显示受影响的使用入口；重新选择旧版本不等于撤销它曾经对外产生的操作。
- **验收：** PA-P2-007-A1：两个版本运行后可以分别查看各自配置与结果；PA-P2-007-A2：编辑草稿期间旧版本的运行依据不变；PA-P2-007-A3：已停用版本不能从旧入口悄悄发起新任务。

### PA-P2-008 样例输入与试运行

- **场景与前置条件：** 开发者要判断流程能否处理实际业务样例。
- **要求：** 可输入、保存并复用有代表性的测试样例；试运行前展示将使用的版本、工具和限额。执行后可查看每个已执行步骤的输入、输出和判断结果，并能从失败节点返回配置位置。试运行产生的真实外部操作和费用必须有明确提示。
- **异常与边界：** “测试”字样不能被当成天然安全或免费；涉及外部写入的试运行仍须满足相同授权。历史样例中的敏感数据受项目权限保护，不得自动公开。
- **验收：** PA-P2-008-A1：同一样例可以在两个流程版本中分别运行并查看差异；PA-P2-008-A2：运行前能识别是否可能产生真实外部操作；PA-P2-008-A3：失败后可直接定位问题步骤及当次输入。

### PA-P2-009 节点进度、失败与取消

- **场景与前置条件：** 用户正在执行包含多个步骤的流程。
- **要求：** 展示流程及各步骤的等待、进行、成功、失败、未执行、取消等状态，区分整体失败与局部已有结果。用户可以请求停止，停止后的后续步骤不能继续被主动发起。提供发生错误的步骤、对后续结果的影响和可采取操作。
- **异常与边界：** 外部已完成操作可能无法撤销，必须清楚说明；取消不应删除已有事实和费用。阶段 2 不承诺从任意中间位置自动恢复，用户发起重跑前应看到重跑范围。
- **验收：** PA-P2-009-A1：成功、失败、未选中分支的步骤状态各自正确；PA-P2-009-A2：停止后不继续发起下一未执行步骤；PA-P2-009-A3：失败或取消后仍可查到已有结果、外部操作与费用。

### PA-P2-010 业务工具登记、试用与使用授权

- **场景与前置条件：** 负责人希望流程能查询外部业务信息，或在明确允许时执行业务操作。
- **要求：** 可以登记经许可的业务工具，说明用途、输入、结果、访问条件、可能费用以及是否会改变外部状态；能够进行受控试用并赋予指定项目或流程使用范围。调用前应再次判断当前用户和流程是否仍有权限。必要凭证对普通使用者保密。
- **异常与边界：** 登记工具不代表任何流程均获授权；工具被禁用、权限被撤回或输入不完整时必须阻止调用。工具返回的文字不能自动扩大工具或用户权限。
- **验收：** PA-P2-010-A1：获准流程可使用一个查询型工具并展示结果；PA-P2-010-A2：撤销授权后，原先已保存的流程也不能继续调用；PA-P2-010-A3：试用和历史记录中不会暴露完整凭证。

### PA-P2-011 外部操作确认与重复执行风险

- **场景与前置条件：** 流程包含发送消息、创建记录或修改外部资料等操作。
- **要求：** 用户能在执行前理解操作对象、范围与可能后果，并作出必要的明确确认；确认仅覆盖已说明范围。执行超时或结果不确定时，区分“已失败”与“可能已执行”，提示先核对结果。重跑必须说明哪些外部操作可能再次发生。
- **异常与边界：** 不能因为未收到成功结果就无条件重做外部写入；不能把一次确认用于未来不同对象或扩大范围的操作。模型生成的“用户已同意”不能代替真实确认。本阶段无法满足确认要求的操作应保持阻止状态。
- **验收：** PA-P2-011-A1：未经必要确认的外部修改被阻止；PA-P2-011-A2：模拟结果不确定后，不自动重复该操作；PA-P2-011-A3：用户重跑前看得到操作范围和重复风险。

### PA-P2-012 子流程复用与总限制

- **场景与前置条件：** 开发者要在多个流程中复用一个已确认的处理步骤组合。
- **要求：** 可以引用本项目有权使用的明确子流程版本，配置输入与结果的对应关系。运行详情能够展开查看子流程的状态与结果。子流程的模型调用、工具调用、时长和费用归入父任务的已声明限制。
- **异常与边界：** 不能以拆成子流程绕过项目或单次任务限额；出现递归引用、版本不存在或权限撤回时应阻止不受控运行。父流程停止后，不得继续主动发起新的子流程工作。子流程失败如何影响父流程须在配置中明确。
- **验收：** PA-P2-012-A1：两个父流程可以复用同一明确版本的子流程；PA-P2-012-A2：父任务限额达到后子流程不能继续追加调用；PA-P2-012-A3：无效或递归引用在运行前给出明确问题。

### PA-P2-013 面向业务使用者的运行入口

- **场景与前置条件：** 流程已通过验证，项目内其他获准用户需要反复使用。
- **要求：** 可为已确认版本提供易于访问的任务入口，清楚说明用途、必填输入、可能费用与输出内容；使用者无需编辑画布即可运行和查看自己有权访问的结果。维护者可以停用入口或切换到另一个明确版本，并保留变更说明。
- **异常与边界：** 提供入口不等于公开所有输入、流程细节或项目资料；未授权访问、版本停用和资源不足时应拒绝并提示原因。对外公开访问、商业发布和独立应用分发不在本阶段范围内。
- **验收：** PA-P2-013-A1：获准成员从入口填写业务输入并获得结果；PA-P2-013-A2：无权成员不能借入口读取其他人的受限结果；PA-P2-013-A3：入口版本变更后旧运行仍显示原版本。

### PA-P2-014 运行依据、诊断与成本追溯

- **场景与前置条件：** 维护者需要解释某个结果、判断某一步为何失败或消耗较高。
- **要求：** 每次运行保留可识别的流程版本、输入、节点执行顺序、分支选择、关联模型与工具、已知用量及错误说明。可从总费用定位到产生费用的步骤；子流程费用计入总额时应避免重复计数。必要的输入输出可按权限查阅。
- **异常与边界：** 大结果或被隐藏内容应明确标记并提供获准查阅路径，不能只显示截断内容却宣称完整。诊断信息不暴露秘密；无法获得的用量单独显示，不能默认忽略后仍声称总额完整。
- **验收：** PA-P2-014-A1：根据记录可说明最终结果经历了哪些步骤；PA-P2-014-A2：含子流程的总费用没有把同一笔消耗重复累加；PA-P2-014-A3：截断、受限与未知内容均有明确说明。

## 3. 信息与业务约束

工作流由项目管理；流程编辑权、版本使用权、工具授权与运行结果可见范围需要分别清楚表达。流程复制、运行入口和样例导出均不能扩大原授权。工具返回结果和模型输出只作为业务资料，不能改变用户授权或强制限制。

阶段 1 的预算与用量规则在本阶段继续有效，包含试运行、失败尝试、子流程和工具可能产生的费用。跨阶段约束以[通用需求](../03-cross-cutting-requirements.md)为准。节点类别与行为的变动应同步更新说明，不允许文档声称可用但画布中只有占位配置。

## 4. 阶段端到端验收

| 场景 | 操作与核对结果 | 对应需求 |
|---|---|---|
| P2-E2E-01 分支业务流程 | 拖拽创建“输入—查询工具—条件—模型/直接回复—结束”；保存版本，使用三组输入验证分支与结果 | PA-P2-001、PA-P2-002、PA-P2-003、PA-P2-004、PA-P2-005、PA-P2-006、PA-P2-007、PA-P2-008、PA-P2-010 |
| P2-E2E-02 历史与复用 | 用固定样例运行版本一，修改后形成版本二；从业务入口调用，并检查子流程版本和费用 | PA-P2-007、PA-P2-008、PA-P2-012、PA-P2-013、PA-P2-014 |
| P2-E2E-03 失败及副作用 | 撤回工具权限、制造结果不确定和主动取消，确认不会静默重复外部写入，也不继续追加后续步骤 | PA-P2-009、PA-P2-010、PA-P2-011、PA-P2-014 |
| P2-E2E-04 无效配置和限额 | 设置失效变量、递归子流程和低预算，检查定位提示、运行阻止与合计用量 | PA-P2-004、PA-P2-006、PA-P2-012、PA-P2-014 |

本阶段完成的标志是用户能独立搭建并运行一条有真实分支、受控工具与结果追溯的流程。节点数量和页面数量不作为替代验收依据。阶段核对见[验收与追踪](../04-acceptance-and-traceability.md)。
