# 阶段 5：质量中心、Prompt 优化与成本分析需求

> 版本：v0.2 · 日期：2026-11-23
>
> 状态：基于已确认产品边界的详细需求规划；待实施，本文功能尚未实现。
>
> 所属路线：阶段 1—6 完成完整产品能力，阶段 7 完成 Docker/Compose 部署交付；本阶段形成统一质量与用量闭环。
>
> 文档边界：规定如何形成可信的产品判断，不确定技术实现或预设提升幅度。

## 1. 背景与目标

用户需要回答三个问题：这个应用是否把任务做对了；某次 RAG 或 Prompt 调整是否真的改善结果；改善是否值得新增的时间与费用。仅看几个演示问题、一次模型评分或总调用量，无法支持可靠判断。

本阶段提供从样本、评测、对照、失败分析到候选优化的完整操作路径。产品应让负责人看见支持结论的逐题证据、适用条件和不确定性，避免把“分数增加”自动等同于“项目更好”。

## 2. 范围与前置条件

| 范围 | 内容 |
|---|---|
| 本阶段包含 | 评测数据集、指标说明、批量评测、配对比较、人工复核、失败分类、Prompt 候选优化、RAG/Skill/上下文/工具/插件/Agent 评测、质量看板、统一 Token 消费面板与费用分析 |
| 已有能力 | 阶段 1 已具备基础用量、估算状态及运行前限制；本阶段扩展分析和预算管理，不把首次成本控制推迟至此 |
| 前置条件 | 阶段 1—4 的可用应用、版本、运行证据和知识样本；可核验的业务任务及预期结果 |
| 本阶段不包含 | 自动替换正在使用的应用、商业收费结算、复杂发布管控、以一个排行榜覆盖所有业务、承诺固定质量提升 |

个人用户作为租户使用本阶段全部功能。评测、评分和候选生成所需模型及外部服务均由用户自行配置凭据；平台不提供公共模型池或免费调用额度。与阶段 6 才交付的协作、插件发布和高级知识能力相关的评价规则在本阶段形成，并在阶段 6 用真实成品完成联验，不能把预置样例当作相应产品功能已经实现。

## 3. 角色与典型场景

| 角色 | 场景 | 期望结果 |
|---|---|---|
| 质量维护者 | 将真实失败问题整理成样本 | 来源、标准证据、预期行为与核验状态清楚 |
| RAG 维护者 | 比较两套资料处理或检索配置 | 能区分找不到证据、排序不佳和回答错误 |
| 应用开发者 | 优化 Prompt | 候选改动有依据，并能发现回归 |
| 项目负责人 | 决定是否采用新版本 | 同时了解质量、耗时、费用、覆盖范围和风险 |
| 人工评审者 | 复核自动评分 | 看得见依据，能够纠正错误并留下理由 |

## 4. 详细功能需求

### PA-P5-001：维护具有来源与版本的数据集

- **使用场景**：维护者从真实任务、人工编写或获准的历史运行中积累问题。
- **行为要求**：可新建、导入、编辑、停用、查看数据集；每题记录问题、任务类型、来源、预期结果、证据、使用权限和核验状态。调整形成新版本，历史评测仍指向原版本。支持标记重复、过期、争议和不适用样本。
- **边界与异常**：含私人资料或项目限制内容的样本不得因进入评测而扩大可见范围；自动生成样本须标记来源，未经核验不得自动计入已确认基准。重复问题及近似重复应可被发现并复查。
- **验收 PA-P5-001-A1**：编辑一道已评测题目后，旧报告仍能查看当时题目和标准，新报告使用新版本。
- **验收 PA-P5-001-A2**：导入缺少预期结果或权限说明的样本时，系统明确标出缺项与不可进行的评测。

### PA-P5-002：标注可追溯的相关证据和任务结果

- **使用场景**：维护者需要判断检索是否完整、答案是否正确。
- **行为要求**：相关证据应定位到确定资料版本的原文段落、页码或等效稳定位置；允许一题包含多个必要证据、多个可接受答案和适用条件。分别标记“完整相关证据集合已确认”“仅已知部分证据”“无答案”“存在争议”。多步骤任务记录可观察的最终结果及必要操作约束。
- **边界与异常**：改变知识分段不能使标准证据无故失效；资料已变更或删除时提示样本需要重新核验。无法证明证据集合完整时，不能默认完整。人工判断冲突须保留争议与处理结果。
- **验收 PA-P5-002-A1**：调整分段后仍能用同一原文证据判断是否命中；替换资料版本时提示证据是否需要重标。
- **验收 PA-P5-002-A2**：一题需要两份资料才能作答时，只找到一份不会被标为完整证据覆盖。

### PA-P5-003：区分优化样本与独立检验样本

- **使用场景**：开发者多次调整 Prompt 或检索配置，希望保留独立检验结果。
- **行为要求**：数据集可区分用于开发和优化的样本、用于候选选择的验证样本、以及受限的最终检验样本；查看、修改和使用范围可控制。报告说明本次结果来自哪个用途的集合。最终检验题目及答案不得进入候选生成或日常优化提示。
- **边界与异常**：若检验样本被用于优化，应记录其独立性已失效，重新划定检验范围后才能继续宣称独立检验。存在相同或高度近似题目跨集合时，须提示复查；不能以换一个名称掩盖样本复用。
- **验收 PA-P5-003-A1**：生成 Prompt 候选时，可核查输入只包含获准的开发样本，没有最终检验题目和答案。
- **验收 PA-P5-003-A2**：将检验题移入优化集合后，相关报告明确提示该题不再构成独立检验证据。

### PA-P5-004：运行可追溯的批量评测

- **使用场景**：用户选择一版 Agent、工作流、Prompt 或知识检索配置进行评测。
- **行为要求**：开始前确认评测对象及版本、数据集版本、知识范围及版本、模型设置、评分规则、权限视图、样本数、将使用的本租户服务与预算。评测对象包括 Agent、工作流、Prompt、知识配置，也包括 Skill、上下文策略、工具与插件；运行中可看完成、失败、待评判数量并取消后续任务，结束后逐题保留输入、实际输出、引用、状态、耗时和用量费用。
- **边界与异常**：缺失关键配置时不能把结果标为可完整复现；受外部模型变化影响时应说明。服务失败与答案错误分开记录，不能把未完成题目从结果中静默删除。再次执行产生新记录，不覆盖旧记录。
- **验收 PA-P5-004-A1**：完成一批包含成功、失败和取消题目的评测后，数量能够对齐，逐题结果可复查。
- **验收 PA-P5-004-A2**：再次执行同一配置，保留独立报告及配置对照；不得保证随机输出逐字相同。

### PA-P5-005：正确呈现检索质量指标

- **使用场景**：用户判断是否找到了需要的证据，以及相关证据是否排在前面。
- **行为要求**：每项指标须展示名称、含义、计算范围、结果数量限制 K、有效样本数和不适用数量。默认区分下表的不同判断，不得把命中一条证据与找齐全部证据混为一谈。可补充前列结果的相关程度指标，但必须说明需要的标注条件。
- **边界与异常**：相关证据标注不完整时，只能报告“已标注证据的覆盖情况”，不得称为真实完整召回率。无答案题不计算有答案题的召回率，单独判断是否正确报告无答案。排序中的重复证据不能反复计为新增覆盖。
- **验收 PA-P5-005-A1**：已确认有四项相关证据、前五条仅命中其中两项时，显示命中为是、该题 Recall@5 为 50%；不能显示 100%。
- **验收 PA-P5-005-A2**：混入部分标注、无答案与多证据题目后，报告分别显示有效数量、适用范围和证据完整性判断。

| 指标或判断 | 本项目采用的含义 | 适用边界 |
|---|---|---|
| Hit@K | 前 K 条结果是否至少命中一项相关证据；集合统计为有效题目的命中比例 | 不能说明全部必要证据已齐全 |
| Recall@K | 前 K 条命中的不同相关证据数量，除以已确认完整相关证据集合的数量 | 分母必须有依据且大于零；部分标注另行命名 |
| MRR | 对有效题目取首项相关证据的排名倒数，再求平均；约定范围内未命中按零计 | 报告须说明是否只检查前 K 条，不能隐去截断范围 |
| 必要证据完整覆盖 | 回答该问题所需的全部必要证据是否找到 | 适用于跨段落、多文档或多条件问题；不可用 Hit@K 替代 |

### PA-P5-006：区分回答质量、引用质量和任务完成

- **使用场景**：检索已找到资料，但最终答案或实际操作仍可能出错。
- **行为要求**：分别评价答案正确性、对证据的忠实程度、关键结论的引用支持、回答完整性、要求的格式和任务最终结果。对工具任务同时记录调用结果与业务目标是否达成；模型声称“完成”不能直接作为成功依据。无答案题记录恰当拒答和误答，有答案题记录错误拒答。
- **边界与异常**：答案忠于一份过期资料，不代表对当前问题正确；工具调用成功也不代表目标完成。无法核验业务结果时标为待确认，不能计作已确认成功。
- **验收 PA-P5-006-A1**：为“证据正确但答案误读”“引用真实但不支持结论”“工具成功但结果错误”分别给出不同失败记录。
- **验收 PA-P5-006-A2**：未获得业务结果证据的任务保持待确认状态，成功率分母和待确认数量清晰可见。

### PA-P5-007：进行条件透明的配对比较

- **使用场景**：用户比较两版检索、Prompt 或 Agent 配置。
- **行为要求**：在相同题目上比较逐题结果，展示改进、回归、持平和无法比较的样本。记录是否固定语料与权限、K、模型、预算及评测规则；明确本次要考察的差异。展示整体结果、各问题类型、耗时与费用，并保留结论备注。
- **边界与异常**：同时改变多项条件时可作为整体方案比较，但不得把改善归因到某一个变化。单方运行失败不能静默剔除；小样本、随机波动或样本组成变化应提示结论限制。报告给出有效样本数和适用的不确定性说明，证据不足时允许结论为“尚不能确定”。
- **验收 PA-P5-007-A1**：一版提高部分题目同时损害另一类题目时，报告能直接筛选两组样本，不能只展示平均提升。
- **验收 PA-P5-007-A2**：两组 K 或语料范围不一致时明确显示差异，并限制“单一策略带来提升”的结论。

### PA-P5-008：使自动评分可检查和可纠正

- **使用场景**：需要模型辅助判断开放式答案，但评分本身也可能出错。
- **行为要求**：能客观核验的结果优先按明确规则判定；语义评价展示评分标准、所用评审者、版本、依据与费用。支持人工抽查、复核和纠正，保留原判断及修改理由。采用一批人工确认样本检查自动评审的一致性；对候选比较尽量隐藏会影响判断的版本身份。
- **边界与异常**：无理由评分、相互矛盾的评分和评审服务失败应分别标记。未经校准或明显偏离人工判断的评审结果不能作为自动选优的唯一依据；争议题可以保持未决。
- **验收 PA-P5-008-A1**：人工纠正错误评分后，报告展示原值、修正值、理由以及受影响汇总结果。
- **验收 PA-P5-008-A2**：自动评分与人工基准存在分歧时，用户能查看分歧样本和本次评分的可信范围。

### PA-P5-009：按失败原因沉淀改进依据

- **使用场景**：用户需要决定下一步修资料、改检索还是改回答要求。
- **行为要求**：支持按资料缺失或错误、文档处理问题、证据遗漏、排序问题、上下文裁减、答案误读、引用错误、工具失败、权限拦截、预算停止等原因分类；允许多原因和“未确定”。每项归因关联具体运行、证据、人工意见与后续任务。
- **边界与异常**：自动建议的原因应标为建议；没有证据不能认定某一组件必然有错。权限正确拦截、用户取消与普通质量失败分开呈现，避免为了分数而放宽权限。
- **验收 PA-P5-009-A1**：从“证据遗漏”分类进入具体样本，可看到期望原文、实际候选和采用配置。
- **验收 PA-P5-009-A2**：修正原因归类时保留记录，并能关联后续改进任务和再次评测结果。

### PA-P5-010：生成和验证 Prompt 优化候选

- **使用场景**：开发者基于失败案例改进 Prompt，而非凭印象直接替换。
- **行为要求**：选择基线版本、目标、允许变更范围、开发样本和预算；可生成少量候选，初次建议 2—3 个并允许调整。展示候选内容差异、改变理由及所针对问题。用一致条件比较候选后，由用户选择是否保存为新版本，保留基线及未采用候选的结果。
- **边界与异常**：候选不得修改平台强制限制、扩张工具权限或引入未授权资料；不得使用受限最终检验答案。预算不足时保留已完成结果，不自动覆盖现有版本。分数提升但关键任务回归时必须明显提示。
- **验收 PA-P5-010-A1**：完成“基线失败样本 → 候选 → 逐题比较 → 人工选择”全过程，能追溯采用理由。
- **验收 PA-P5-010-A2**：优化中断或所有候选无改善时，现有 Prompt 版本保持不变，报告如实记录结果。

### PA-P5-011：形成可解释的项目质量看板

- **使用场景**：负责人判断一个应用或版本是否适合当前业务。
- **行为要求**：按项目、应用版本、任务类型和评测时间查看任务成功、答案与引用质量、可靠性、耗时、费用及样本覆盖；展示未评判比例、关键失败和版本变化。允许记录业务必须满足的单项条件以及适用场景。
- **边界与异常**：不同数据集、业务目标或权限范围的项目不得直接给出无条件优劣排名。若采用综合分，必须公开指标、权重和缺失值处理，并同时显示原始维度；综合分不能掩盖越权、关键任务错误或证据缺失。
- **验收 PA-P5-011-A1**：质量更好但费用更高的版本展示完整取舍，而非只给出“更优”标签。
- **验收 PA-P5-011-A2**：样本覆盖不足或使用条件不同的两个项目，比较页提示限制并保留各自条件。

### PA-P5-012：汇总真实用量与有标识的估算费用

- **使用场景**：用户需要了解预算花在哪里，以及是否值得。
- **行为要求**：按租户、项目、应用、运行、模型、工具、知识处理和评测任务查看用量及费用；区分供应方报告用量、估算用量、未知用量和未知价格。费用注明币种、计价依据与生效时间；保留更正前后记录。展示每次运行费用及每个成功任务费用，明确统计范围。仅统计用户自行配置的服务调用；平台额度是使用约束，不表示平台提供付费余额或模型供应。
- **边界与异常**：未知成本不计作零；不同币种未经说明不能直接相加。失败、重试、候选生成和自动评分的费用应计入相关工作成本。父任务汇总包含子任务费用时，不能再将同一调用重复相加。成功任务数为零时“每成功任务费用”显示不适用，不显示零。估算不宣称等于供应方账单。
- **验收 PA-P5-012-A1**：一批含成功、失败、未知价格的任务，汇总显示可确定金额和未知部分，并能回到原始用量依据。
- **验收 PA-P5-012-A2**：更改计价依据后，旧报告保留原口径；新估算清楚标明更正原因和适用范围。

“每成功任务费用”的默认统计口径为同一评测范围内全部已计入任务费用除以已确认成功任务数，包含失败尝试；不确定金额单独列出。其他口径必须显式命名，不能混用。

### PA-P5-013：控制整个任务的预算与新增开销

- **使用场景**：项目并行运行知识处理、应用任务和评测，负责人需要限制总体支出。
- **行为要求**：可设置项目及任务的提醒额度与停止额度；开始收费操作前检查适用限制，运行中持续显示剩余额度和状态。子任务、重试、优化候选和评审调用纳入所属任务费用，不因拆分绕过限制。调整额度需要对应权限并留有记录。
- **边界与异常**：多个任务同时消耗额度时，共同受项目额度约束，不能各自把同一剩余额度全部视为可用。用量延迟、未知价格和已发出的调用可能影响最终金额，应显示所采用的限制口径及未决金额；不能承诺外部账单绝不超过精确数值。停止新增操作后保留已完成结果。
- **验收 PA-P5-013-A1**：任务接近限额时，再启动的模型、工具或评测操作受到限制，子任务不能得到独立的额外额度。
- **验收 PA-P5-013-A2**：价格未知或用量迟到时，按已确认的项目规则提示、阻止或使用备用计量限制，不能悄悄按免费继续。

### PA-P5-014：导出具有证据和适用范围的评测结论

- **使用场景**：负责人需要将阶段结果交给其他成员核对或形成采用决定。
- **行为要求**：可导出汇总、逐题结果、配置版本、指标口径、失败原因、费用状态、人工复核与结论说明。报告区分观察结果、推测原因、已决定事项和未解决问题；记录何人于何时确认结论，并关联需求及后续改进任务。
- **边界与异常**：导出遵守当前权限，敏感问题、答案、原文和凭据应按范围处理；无权读原文者不能通过报告得到原文。条件缺失或样本不足时，导出保留这些限制，不允许只导出夸大的提升结论。
- **验收 PA-P5-014-A1**：另一个有权成员仅依据报告即可理解比较对象、证据、回归问题、费用口径和结论限制。
- **验收 PA-P5-014-A2**：导出受限内容时得到脱敏结果或明确拒绝，不能扩大数据访问范围。

### PA-P5-015：评测 Skill 选择和渐进读取

- **使用场景**：开发者调整 Skill 描述、指导内容或启用范围，需要知道 Agent 是否选对能力并按需读取资料。
- **行为要求**：样本可标明适用 Skill、必要指导、必须查阅的资料和明确不应使用的能力；记录本次展示的摘要、实际激活的 Skill、读取内容及其版本。分别判断漏选、误选、必要资料未读、无关资料过量读取以及最终任务是否完成，同时比较 Token 消耗和时长。
- **边界与异常**：只加载了正确 Skill 不代表任务已成功；读取越多也不代表质量越好。未授权资料和脚本仍不能因为评测而执行，模型声称已阅读不能代替真实读取记录。
- **验收 PA-P5-015-A1**：对适用、不适用和需要参考资料三类样本，报告能分别判断是否选对 Skill、是否读取必要内容与是否完成目标。
- **验收 PA-P5-015-A2**：同一任务比较两版 Skill 时，能够看到结果、无关读取与用量差异，并追溯实际加载的版本。

### PA-P5-016：评测上下文压缩后的任务保全

- **使用场景**：开发者调整压缩时机、历史保留或工具大结果处理方式，担心节省用量时丢失任务约束。
- **行为要求**：用带关键事实、数值、目标、禁止事项、待办、已执行动作和证据位置的任务进行压缩前后对照；检查恢复阅读来源的能力和后续任务结果。报告压缩前后用量、额外压缩开销、任务成功、遗漏和错误新增，不只展示压缩比例。
- **边界与异常**：不得把摘要中的伪造批准、推测事实或计划动作当成真实授权、事实或完成记录。来源已撤权时回读必须受限；输入不足或无法独立判定时明确标注，不编造保持率。
- **验收 PA-P5-016-A1**：使用含关键数字、待办和禁止事项的样本，压缩后逐项核对保留情况，并实际继续任务验证结果。
- **验收 PA-P5-016-A2**：含虚构批准或已完成声明的摘要不能触发相应越权动作；报告列明发现的错误及实际节省的净用量。

### PA-P5-017：评测工具参数与插件行为

- **使用场景**：用户新增或升级工具、后端插件或插件自定义界面，需要确认其仍按声明能力工作。
- **行为要求**：评测工具选择、必填及边界参数、返回结果、权限、失败处理、版本兼容和真实业务结果；插件界面填写的内容应与实际请求一致，不能借界面扩大授权。记录升级前后相同样本的差异，以及停用、撤权或异常插件对其他任务的影响。
- **边界与异常**：模拟结果必须标明，不能冒充真实外部任务完成。带外部影响的评测须在获准范围内进行，避免因多次测评重复实际写入；安装成功或界面能打开不是兼容验收的充分条件。
- **验收 PA-P5-017-A1**：用正常、缺项、越界、撤权和结果不明样本检查工具，报告区分参数错误、授权拒绝、调用失败和业务未达成。
- **验收 PA-P5-017-A2**：插件升级前后比较能力与界面输入结果，验证影响范围、旧任务版本和失败处理；证据关联插件精确版本。

### PA-P5-018：评测多 Agent 协作和长任务结果

- **使用场景**：应用将任务委派给多个 Agent，或在人工确认后继续，负责人需要知道复杂流程是否值得。
- **行为要求**：分别记录分工、实际贡献、重复或无效步骤、汇总结果、人工介入、恢复后的动作和总成本；以可核验的业务结果判断整体成功。可在相同样本上比较单 Agent 与多 Agent，以及不同协作配置的质量、耗时和费用。
- **边界与异常**：每个子任务成功不能自动推出整体成功；恢复后重复外部动作、错误使用旧批准、绕过总预算均应明确暴露。中断、服务失败与业务错误分别归类，未完成样本不能被静默排除。
- **验收 PA-P5-018-A1**：子任务都返回结果但最终结论错误的样本，应被判为整体未达成，并能追溯冲突或汇总问题。
- **验收 PA-P5-018-A2**：对带审批、暂停恢复和预算限制的任务，核对真正执行的动作、最终产物及所有子任务的合计消耗。

### PA-P5-019：提供贯穿全部任务的 Token 消费面板

- **使用场景**：个人用户需要了解自己的对话、Agent、知识处理和质量优化究竟消耗了多少 Token。
- **行为要求**：在同一面板按时间、租户内项目、应用、任务、模型和调用用途筛选；至少覆盖对话、Agent 决策、上下文压缩、知识处理与问答、评测评分、Prompt 优化。展示输入、输出以及服务实际提供的缓存和推理明细，明确哪些数字已报告、哪些为估计、哪些未知；可从总量逐层查看实际调用依据与当前价格口径。
- **边界与异常**：缓存或推理明细可能已包含在输入或输出中，应按该服务的明示口径展示，不能再次相加；口径不明时保留原始说明并标为不可确定。迟到用量更正同一次调用，不新增一笔重复消费；同一调用不能同时作为已报告和估算计入总量。未知项不显示为零，不宣称面板等于供应方账单。其他租户消费与凭据不可见。
- **验收 PA-P5-019-A1**：执行一组包含对话、Agent 子任务、知识问答、评分和优化的操作，面板可逐项定位；父子汇总、重复通知和迟到更正不会使同一调用重复计数。
- **验收 PA-P5-019-A2**：构造已报告、估计、未知及带缓存/推理明细的用量，检查各状态独立显示、包含关系正确；切换账号或请求他租户记录时无法读取其数据。

## 5. 统一质量对象矩阵

| 评测对象 | 主要判断 | 必须保留的依据 | 交付与联验 |
|---|---|---|---|
| 知识检索 | 命中、召回、排序、必要证据完整性 | 原文证据、资料与配置版本、适用分母 | 阶段 5；阶段 6 补扫描文本/表格/跨文档场景 |
| 回答与 Prompt | 正确性、忠实性、引用、格式、错误拒答 | 输入输出、引用、标准、候选差异 | 阶段 5 |
| Skill | 选对能力、必要资料读取、结果与消耗 | 激活、读取、版本与任务记录 | PA-P5-015 |
| 上下文策略 | 关键内容保全、错误新增、回读、净用量 | 压缩前后材料、来源和继续任务结果 | PA-P5-016 |
| 工具与插件 | 参数、权限、兼容、真实结果、影响范围 | 调用记录、插件版本、界面输入、验证结果 | PA-P5-017；阶段 6 用已交付插件联验 |
| Agent 与工作流 | 业务完成、步骤与预算、异常和恢复 | 实际动作、最终产物、完整费用 | 阶段 5—6 |
| 多 Agent | 分工贡献、冲突汇总、重复工作、总结果 | 子任务关系、汇总依据和累计消耗 | PA-P5-018；阶段 6 必须完成真实任务验收 |

所有对象均可使用规则判断、人工复核和经校准的辅助评分，并沿用版本化数据集、配对比较与失败归因。只有业务所需的标准证据已经具备时才计算相应指标。

## 6. 信息与权限要求

数据集、样本标准、评测记录、评分规则、优化候选和费用口径需要可追溯版本。数据集查看、标准修改、独立检验使用、评测执行、人工改分、预算调整与报告导出分别受当前租户和项目权限约束。标准答案和独立检验题目不能因为出现在调试页而泄漏给优化过程。公共资源的评测说明可以公开经审核的摘要，私有评测题目、运行正文、模型连接和凭据不能默认随发布导出。

评测耗时目标和可接受费用应按任务类型与首批样本规模确认。不同业务可采用不同成功标准，但同一次对比必须明确共同口径。[跨阶段要求](../03-cross-cutting-requirements.md)同样适用。

## 7. 阶段端到端验收

| 场景 | 完成证据 | 覆盖需求 |
|---|---|---|
| 建立可信评测集 | 真实样本、人工核验、证据完整性与用途划分记录 | PA-P5-001、PA-P5-002、PA-P5-003 |
| 判断 RAG 是否改善 | 同题配对结果、有效分母、回归题目、条件差异和证据不足说明 | PA-P5-004、PA-P5-005、PA-P5-007 |
| 纠正错误质量结论 | 答案与任务分项判定、自动评分复核、归因及修正记录 | PA-P5-006、PA-P5-008、PA-P5-009 |
| 完成一次 Prompt 优化 | 基线、候选、预算、逐题比较、人工选择的新版本 | PA-P5-010 |
| 作出项目采用决定 | 多维看板、全部尝试费用、未知项、预算限制与可核查报告 | PA-P5-011、PA-P5-012、PA-P5-013、PA-P5-014 |
| Skill 与压缩确实有效 | 选错/漏读样本、关键事实保全、虚假授权拦截和净用量对照 | PA-P5-015、PA-P5-016 |
| 工具、插件与协作有真实结果 | 参数边界、插件版本兼容、最终产物、恢复行为和总费用证据 | PA-P5-017、PA-P5-018 |
| 用户能核对全部 Token 消费 | 跨任务面板、缓存/推理包含关系、未知状态、迟到更正与租户隔离 | PA-P5-019 |

本阶段验收应回顾前序用户旅程；阶段 6 完成后再次对全部产品能力联验，阶段 7 验证部署环境中的同一条业务路径。不能因为本阶段新增看板而把其他尚未完成能力视为完成。

| P5-T02 | 批量评测有明确口径 | PA-P5-004、PA-P5-005、PA-P5-006 | P5-T01；逐题结果和各类分母说明 |

| P5-T05 | 项目质量与费用可判断 | PA-P5-011、PA-P5-012 | P5-T02—P5-T03、阶段 1 用量；多维看板与费用对账依据 |

## 9. 实施前需细化的参数

- 第一批评测任务的业务范围、负责人、样本来源、核验方式与独立检验规模。
- 必须满足的质量条件、不能接受的关键失败，以及各类样本的有效统计范围。
- 自动评分允许使用的服务、人工抽查比例、分歧处理责任和质量结论确认人。
- 费用币种、计价来源、未知成本处理方式、提醒与停止额度、报告留存时间。
- 报告可导出的原文范围、敏感数据处理要求以及不同角色可见的评测细节。
