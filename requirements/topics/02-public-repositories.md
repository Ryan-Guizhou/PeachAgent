# 公共资源仓库需求

> 版本：v0.2 · 日期：2026-11-23
>
> 状态：基于已确认产品边界的详细需求规划；待实施，功能尚未实现。
>
> 阶段归属：阶段 6 必交付，阶段 7 在部署环境联验。
>
> 关联：PA-P6-018；本专题定义公共仓库细则，阶段文档负责完整使用旅程。

## 1. 背景与目标

PeachAgent 的个人用户以租户身份使用全部功能。用户可以在自己的租户中私用应用、插件、Skill、MCP 和 Prompt 模板，也可以选择将一份明确版本提交给平台管理员审核。审核通过后，该精确版本进入统一公共仓库，所有正常用户都可看见、检索和采用。

公共仓库解决可信分发和复用，不负责代用户提供模型服务或免费额度。采用资源不自动执行代码、不自动授权、不携带作者的模型或外部服务密钥。应用默认以可复制安装的配置模板分发；对外开放某个作者托管应用的调用入口是独立的应用发布行为。

## 2. 资源范围与角色

| 资源类型 | 可公开的主要内容 | 采用后的必要动作 |
|---|---|---|
| 应用 | 可复用的 Agent/流程配置、依赖说明、输入输出和使用示例 | 安装到本人租户，配置自己的模型、工具、知识与访问范围 |
| 插件 | 明确版本的后端能力、受控前端界面、说明及依赖 | 完成兼容检查、配置、授权后启用 |
| Skill | 名称、描述、指导、参考资料及可公开的脚本与模板 | 选择适用 Agent，阅读和脚本执行分别受控 |
| MCP | 连接器或连接说明、能力描述、参数与凭据占位模板 | 用户自行配置可用服务和自己的凭据 |
| Prompt 模板 | 指导内容、变量说明、无私人数据的示例 | 填入本租户输入和获准资源，选择自己的模型 |

“公开”在本版指平台所有正常用户可见，不自动等于允许未登录的互联网访问者下载资源。平台管理员审核的是用户主动提交的公开副本，不因此取得该用户全部私人草稿、会话和凭据的访问权。

| 角色 | 主要职责 |
|---|---|
| 资源作者 | 私用、准备公开副本、提交、补充说明、撤回及发布新版本 |
| 正常用户 | 查找已审核资源，查看说明与风险，在本人租户采用 |
| 公共仓库管理员 | 审核精确版本、给出通过或拒绝理由、处理举报与下架 |
| 租户负责人 | 管理本租户安装、配置、执行权限及实际资源消耗 |

## 3. 详细功能需求

### PA-HUB-001：建立五类资源的统一目录

- **使用场景**：用户在一个入口查找可复用资源。
- **行为要求**：提供应用、插件、Skill、MCP、Prompt 模板分类，统一展示名称、用途、作者、版本、适用条件、更新信息和审核公开状态；允许按类型、关键词和标签查找。个人用户可以浏览所有已通过审核且当前可用的公开资源，不设置功能残缺的个人版本。
- **边界与异常**：没有该类资源时明确显示空目录；不能用导入按钮代替真实公共目录。不同资源类型的安装或使用方式要清楚区分，不能一律显示为可直接运行。
- **验收 PA-HUB-001-A1**：五类各发布一个审核通过的版本，另一个正常个人用户均可在相同公共入口查到并进入详情。
- **验收 PA-HUB-001-A2**：按类型筛选不混入不符资源，详情准确说明是模板、连接说明还是可执行插件。

### PA-HUB-002：保持私人资源与公共副本分离

- **使用场景**：作者既要日常私用，也希望选择部分内容公开。
- **行为要求**：新建资源默认保留在本租户，私用不以通过公共审核为前提。仅当作者明确选择提交时，才产生待审核公开副本；私有原件与公开版本分别展示状态和关系。作者继续修改私有原件不会改变已提交或已公开的内容。
- **边界与异常**：保存草稿、安装插件、运行应用、关注目录等动作都不能自动公开私人资料。管理员在审核页面只查看提交范围；无权用户不能通过猜测链接发现私人资源内容。
- **验收 PA-HUB-002-A1**：同名私有原件与公开副本分别修改，另一用户只能看见已通过审核的副本。
- **验收 PA-HUB-002-A2**：从搜索、直链、预览和导出尝试读取他人私人草稿，均不能获得正文或敏感元信息。

### PA-HUB-003：提供足以判断用途和来源的资源说明

- **使用场景**：用户需要判断资源是否适合任务，管理员需要知道发布者提交了什么。
- **行为要求**：提交材料包含资源类别、名称、明确版本、用途、作者或来源、可分享依据、依赖、使用条件、权限需求、外部服务及可能收费说明。示例表明是否可直接运行、需要用户补哪些配置，并说明已完成哪些验证及其范围。
- **边界与异常**：缺少必要说明、来源不清、版本冲突或外部依赖不可说明时提示补充，不能标为完整可用。验证失败或未验证必须如实显示，不把审核通过写成无条件质量保证。
- **验收 PA-HUB-003-A1**：一个首次使用者仅根据详情能理解资源用途、依赖、所需凭据和可能发生的费用。
- **验收 PA-HUB-003-A2**：缺少来源、权限或必要连接条件的提交被指出缺项，未进入已审核可用目录。

### PA-HUB-004：生成去除私人信息的公开副本

- **使用场景**：私有应用或插件配置中包含真实服务地址、密钥、内部资料或个人输入。
- **行为要求**：作者提交前可预览将公开的完整说明、文件、参数模板和示例；生成不含密钥及私人内容的独立副本，用明确占位要求替代需要使用人提供的信息。提示可能的敏感内容与未解决依赖，由作者检查并确认提交范围。操作不修改私有原件。
- **边界与异常**：不能把凭据脱敏显示当成底层文件已去除秘密；下载、示例、附件、历史说明均需属于同一受审范围。不能依赖一次自动提示保证发现所有敏感信息；发现无法处理内容时保持未提交。
- **验收 PA-HUB-004-A1**：含测试密钥和私人示例的原件生成公开副本后，预览与导出均不含该内容，而私有原件保持不变。
- **验收 PA-HUB-004-A2**：仍含未处理敏感项或私人依赖的副本不能被表示为已完成公开准备，用户可修正后重新检查。

### PA-HUB-005：提交可被精确识别的固定版本

- **使用场景**：作者完成公开准备，要求管理员审核。
- **行为要求**：提交时固定资源内容、附件、说明、依赖版本和提交人，产生可追踪的提交记录。作者和管理员均可查看当前待审版本；提交后修改需要形成新提交，不能在等待或已完成审核期间悄悄替换内容。
- **边界与异常**：重复提交同一内容应可辨识；上传未完成、引用变化或附件缺失时不形成可通过的完整提交。可由作者撤回尚未完成审核的提交，撤回后不能继续批准其公开。
- **验收 PA-HUB-005-A1**：提交后修改私有原件，审核页面仍显示原提交内容；修改内容需另一个可区分提交。
- **验收 PA-HUB-005-A2**：提交被撤回或内容不完整时，管理员不能把它发布成可采用资源。

### PA-HUB-006：提供管理员审核队列和详情

- **使用场景**：管理员需要系统处理待审资源，而非通过私聊批准。
- **行为要求**：队列展示类别、版本、作者、提交时间、状态和已有处理人；可查看精确公开副本、权限与依赖、新旧版本差异和作者说明。管理员可以记录需补充事项、通过或拒绝，并留下操作者与时间。
- **边界与异常**：普通用户不能访问审核操作；重复或并发处理应显示最新状态，避免对已撤回提交继续批准。审核访问不带出作者私人资源或真实凭据，执行可疑内容须符合插件和沙箱规则，不能仅为了预览自动执行。
- **验收 PA-HUB-006-A1**：管理员从队列查看资源内容与版本差异，并形成有理由、可追溯的决定。
- **验收 PA-HUB-006-A2**：普通用户尝试审核或管理员处理已撤回提交时，不产生公开版本；可疑说明不会触发自动工具执行。

### PA-HUB-007：只公开审核通过的精确版本

- **使用场景**：审核通过后，资源应按通过范围进入公共仓库。
- **行为要求**：公开的是被批准的同一份资源内容、说明、附件与依赖版本。公共详情显示审核状态和当前可用版本；审批通过与公共可见状态对应，正常用户读到的材料不得与审核时不同。
- **边界与异常**：不能因为同一作者或资源名曾经通过审核就放行新版本。公开途中失败时不显示完整可用，需明确恢复状态；审核后发现内容变化则不能继续沿用原批准。
- **验收 PA-HUB-007-A1**：审核页面与另一用户下载、预览、采用的版本内容一致，能够识别同一批准记录。
- **验收 PA-HUB-007-A2**：在批准后尝试替换附件或说明，新内容保持未公开并要求重新审核。

### PA-HUB-008：处理拒绝、补充、撤回与重新提交

- **使用场景**：提交没有通过，作者需要知道如何调整。
- **行为要求**：作者收到站内结果和具体理由，可查看问题位置、补充说明、撤回或修正后提交新版本。保留各次提交和处理记录，区分待审核、已拒绝、已撤回及审核通过；拒绝不会删除作者私有原件。
- **边界与异常**：私用是否被允许由租户执行权限决定，不因普通公开审核拒绝而自动销毁私有内容；若发现明确风险，按风险处理流程单独说明。拒绝理由中涉及内部审核信息或敏感内容时，不直接公开给全体用户。
- **验收 PA-HUB-008-A1**：作者被拒后能看到理由、修正并提交另一版本，旧拒绝记录保持可查。
- **验收 PA-HUB-008-A2**：撤回提交后公共用户无法读取，普通拒绝不会修改作者的私有原件和其运行版本。

### PA-HUB-009：使所有公开读取入口遵守同一可见规则

- **使用场景**：用户通过目录、搜索、收藏、直链、预览或下载访问资源。
- **行为要求**：所有入口仅提供当前允许公开的已审核版本；搜索摘要、附件、预览、导出与安装入口采用相同状态与权限要求。待审、拒绝、撤回、下架和私人内容不因入口不同而泄漏。
- **边界与异常**：收藏或旧链接不延续已取消的公共读取权；访问结果要区分无权、不可用或已下架，但不得泄露私有内容。清理中间副本时仍应先阻止新的未授权读取，不能等全部清理结束才生效。
- **验收 PA-HUB-009-A1**：对待审版本逐一尝试搜索、直链、预览、下载和安装，均不能取得资源正文。
- **验收 PA-HUB-009-A2**：已公开版本下架后，旧链接与搜索摘要同步失去可读取正文的能力，新请求不能绕过状态限制。

### PA-HUB-010：在采用者租户内安装和配置

- **使用场景**：用户找到适合的公开资源，希望在自己的项目使用。
- **行为要求**：采用前展示精确版本、依赖、权限、所需服务和影响；采用后在本租户形成可管理的副本或安装记录，保留来源与版本关联。用户配置自己的模型、外部工具、知识范围和额度后才能执行；能查看尚缺配置及停用方式。
- **边界与异常**：采用不自动获取作者密钥、作者私有知识或作者租户操作权限，不自动授予插件和脚本执行权。依赖不可用时不能伪装安装完成且可运行；一名用户的修改不改变其他用户的安装或公共原版。
- **验收 PA-HUB-010-A1**：用户乙采用用户甲资源，配置乙的服务后运行，调用、消耗和修改均归乙的租户。
- **验收 PA-HUB-010-A2**：缺少自有凭据或授权时明确阻止相关执行，不能转用作者或平台管理员的服务连接。

### PA-HUB-011：以配置模板分发公共应用

- **使用场景**：作者希望分享已验证应用的组织方式，供他人复用。
- **行为要求**：公开副本包含可分享的 Agent/工作流配置、依赖说明、输入输出示例和验证说明；私人数据引用与凭据改为使用人需要配置的要求。采用者能在自己的租户检查、调整和发布自己的应用。
- **边界与异常**：公共应用详情不默认提供作者托管应用的无限调用权。作者另行开放 Web/API 服务时，入口的执行租户、访问授权、配额和费用归属另行明确，不能用“模板已审核”代替服务访问授权。
- **验收 PA-HUB-011-A1**：一个正常用户采用模板后可配置自己的服务并发布应用，旧作者的私有资料和访问凭据未进入副本。
- **验收 PA-HUB-011-A2**：没有单独开放调用授权时，公开详情不会让访问者执行作者托管任务或消耗作者额度。

### PA-HUB-012：分发包含后端和自定义界面的插件

- **使用场景**：插件作者希望公开新的能力和使用界面。
- **行为要求**：公开审核范围包含插件后端内容、前端界面、说明、依赖及所需权限；采用者可按插件专题进行动态安装、升级、停用和卸载。目录记录公开版本，租户安装记录记录实际启用版本，两者分别可查。
- **边界与异常**：前端内容不能成为未经审核的旁路下载；插件升级改变任意受审部分时需重审。审核通过不承诺插件可在任意环境运行，也不赋予界面读取平台凭据或跨租户数据的权利。
- **验收 PA-HUB-012-A1**：含后端与前端界面的插件作为一个明确版本审核并被另一租户采用，安装能力与公开说明相符。
- **验收 PA-HUB-012-A2**：只替换前端或依赖内容也不能沿用旧批准；已安装租户不会被静默切到未审核新包。

### PA-HUB-013：分发可检查的 Skill 资料包

- **使用场景**：作者共享可复用任务指导、参考、脚本或模板。
- **行为要求**：公开内容明确区分摘要、主指导、参考资料、脚本和附属模板，说明各自用途及所需权限。采用后仍遵守渐进读取、项目规则和受控执行要求；用户可只阅读指导而不启用脚本。
- **边界与异常**：Skill 正文中的指令不能给自己授权，公开参考资料不得携带私人内容；引用的外部资料变化不自动成为已审核包内容。可执行脚本需要采用者的实际授权与隔离条件。
- **验收 PA-HUB-013-A1**：采用一个带参考与脚本的 Skill，能分别查看资料、按需读取、在获得授权后执行允许脚本。
- **验收 PA-HUB-013-A2**：Skill 声称拥有作者权限或要求读取其他租户资料时不产生授权；禁用脚本后仍可使用允许的文字指导。

### PA-HUB-014：发布需自行配置的 MCP 资源

- **使用场景**：作者分享某类 MCP 服务的连接方式和能力说明。
- **行为要求**：资源可包含连接器、连接说明、参数模板、工具/资源/提示模板能力说明、服务条件和凭据占位。采用者填写自己的服务地址与凭据，验证实际可用能力后选择授权范围；能力不支持或服务不可达时明确说明。
- **边界与异常**：不得公开作者令牌、私人服务连接秘密或把所有 MCP 服务描述为免费公共服务。公开说明不是外部服务的访问许可，模板中列出某项能力也不代表实际服务必然提供。读取服务资源和提示模板仍按数据来源处理，不能绕过用户授权。
- **验收 PA-HUB-014-A1**：使用者配置自己的服务并验证实际能力，连接记录和消耗属于自己的租户，公开包不含作者凭据。
- **验收 PA-HUB-014-A2**：未配置凭据、无服务访问权或能力不匹配时，结果清楚失败或限制，不使用平台维护者连接补齐。

### PA-HUB-015：发布不携带私人数据的 Prompt 模板

- **使用场景**：用户共享指导方式和输入变量。
- **行为要求**：公开模板展示正文、变量含义、必要输入、示例及适用模型条件；示例使用可公开资料。采用者填入自己的输入并选择自己的模型；模板变更形成版本，不修改已采用的私有副本。
- **边界与异常**：私人运行样本、凭据、独立检验答案和内部知识不能默认作为示例公开。变量说明或模板正文不能暗中要求读取作者或其他租户的秘密，也不能替代强制权限。
- **验收 PA-HUB-015-A1**：采用模板后用户能检查最终使用内容，完成缺项提示并使用自己的模型执行。
- **验收 PA-HUB-015-A2**：含私人示例或隐藏凭据的待审模板不会公开；新版本通过前，公开用户仍只能读取原已审核版本。

### PA-HUB-016：对每次更新重审并让采用者选择升级

- **使用场景**：作者修复缺陷、增加能力或更新说明。
- **行为要求**：更新形成独立提交，展示与已公开版本的差异、兼容影响、新增权限和依赖变化；审批只适用于相应版本。采用者收到更新信息，可查看差异后选择升级或保留原版；保留安装来源及版本记录。
- **边界与异常**：修改文件、依赖、前端内容、Prompt 示例或对外链接的受审内容均不能绕过重审。公开新版不自动覆盖租户已安装版本或正在运行任务；旧版因风险下架时采用风险规则，不伪装成普通升级。
- **验收 PA-HUB-016-A1**：发布第二版时，未通过审核前目录不提供新版；通过后采用者仍能看到自己的旧安装并自主升级。
- **验收 PA-HUB-016-A2**：新版增加权限时需采用者另行确认实际授权，不能继承不适用的旧授权；在途任务版本不被静默改变。

### PA-HUB-017：区分普通撤回与风险下架

- **使用场景**：作者不再希望公开资源，或管理员发现资源包含泄漏、恶意行为等风险。
- **行为要求**：作者可申请或执行其有权进行的公开撤回，管理员可有理由地下架明确版本；新公开读取和安装随状态受限。展示影响范围并通知已采用用户。普通撤回默认不改写他人已经合法采用的私有副本；风险下架可针对平台内明确受影响版本阻止新的危险执行，并指导处理。
- **边界与异常**：普通撤回、风险禁用、卸载本租户实例是不同动作。不能宣称已经删除他人下载到平台外的副本；也不能用存在旧下载作为继续提供新公开访问的理由。安全处置的范围、依据、对在途操作的处理和恢复条件必须可查。
- **验收 PA-HUB-017-A1**：普通撤回后，新用户无法下载或采用，已安装用户能看到通知与来源状态，私有副本没有被无提示改写。
- **验收 PA-HUB-017-A2**：风险下架精确版本后，平台内受影响的新执行按规则受限，其他无关资源继续可用，处理记录和通知明确。

### PA-HUB-018：提供作者、采用者和管理员的通知与审计

- **使用场景**：用户需要知道审核、更新、下架和举报处理的结果。
- **行为要求**：作者可查自己的提交、审核原因和撤回状态；采用者可查所安装版本的更新与风险信息；管理员可查操作人、对象版本、时间、原因、状态变化和处理结果。提供站内通知、通知详情和资源问题反馈入口，避免依赖外部私聊才能获知结果。
- **边界与异常**：通知失败或未读不改变审核决定；重新通知不重复发布或重新执行资源。通知与审计按角色和租户可见，不携带真实凭据或不应公开的私人材料，保留和删除规则清楚。
- **验收 PA-HUB-018-A1**：依次完成提交、拒绝、重审通过、升级与下架，相关角色能看到对应通知、原因和精确版本记录。
- **验收 PA-HUB-018-A2**：普通用户无法查看他人的私有审核材料或管理记录；通知重发不产生重复公开版本和执行行为。

## 4. 状态与公开判定

| 状态 | 作者 | 管理员 | 其他正常用户 |
|---|---|---|---|
| 私人草稿 | 在本人租户私用和编辑 | 不因审核职责默认可读 | 不可见、不可检索、不可下载 |
| 待审核 / 补充中 | 查看固定提交、撤回或另提版本 | 查看受审副本与处理 | 不可公开读取 |
| 已拒绝 / 已撤回 | 查看自己的记录并另提版本 | 查看授权范围内处理记录 | 不可公开读取 |
| 审核通过且公开有效 | 查看自己提交与公共详情 | 管理当前公开状态 | 可见、检索、预览和采用；执行另行授权 |
| 普通撤回 / 已下架 | 查看原因与影响 | 查看处置与恢复记录 | 不再提供新公开内容；已采用副本按对应规则处理 |

所有读取入口必须判断精确版本当前是否可公开；资源名称、作者历史信誉、旧版曾获批准或用户持有旧链接都不能代替这一判断。

## 5. 端到端验收

1. 两个个人用户各自创建同名私人资源，互不可读；两人均具备提交公开和采用资源的完整功能。
2. 分别以五类资源生成去除私人信息的公开副本，提交后修改私有原件，确认审核内容不变。
3. 管理员拒绝一版、通过另一版；其他正常用户只通过目录、搜索、直链、预览和下载访问已批准版本。
4. 使用者采用后配置自己的模型、工具或 MCP 服务；调用与 Token 消费归属使用者自己的租户，未共享作者密钥。
5. 作者更新内容重审；采用者自主升级，原安装和在途任务不被静默切换。
6. 分别演示普通撤回和风险下架，核对新读取、已有安装、实际执行、通知和审计的不同结果。

## 7. 实施前需细化的参数

- 资源包大小、说明及附件范围、允许的外部依赖类型和预览方式。
- 审核处理时限、通知保留期限、举报分类和风险处置负责角色。
- 公开内容与审核记录的保留周期，以及账号删除对已公开版本的具体安排。
- 各类资源的验证样例、兼容说明范围和发布质量资料格式；不把这些参数变成取消五类资源承诺的条件。
