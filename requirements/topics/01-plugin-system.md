# 插件系统需求：开发、界面、动态执行与生命周期

> 版本：v0.2 · 日期：2026-11-23
>
> 状态：基于用户已确认边界的需求基线；功能尚未实现。
>
> 适用：阶段 1—6 的完整平台能力，阶段 7 验证正式部署后的同等行为。
>
> 本文只规定产品应提供什么；技术方案见[插件运行与界面设计](../../technical/02-plugin-runtime-and-ui.md)。

## 1. 背景与目标

PeachAgent 的使用者既要配置现有能力，也要开发平台原先没有的新能力。仅注册一个 MCP 服务、导入一份 Skill 或复制一条流程，不能覆盖自定义节点、新执行逻辑、专用配置界面和评测扩展的需求。

插件应成为个人用户可开发、调试、安装、授权、使用和更新的独立能力包。平台提供稳定的开发入口和明确的使用规则；插件可以包含配置、受控代码与自定义前端组件或页面。安装、升级、启停和配置不要求重启全部 Runtime 或主平台，已经运行的无关任务不应被打断。

“无需重启全部平台”允许替换、重启或回收受影响的单插件执行实例，不承诺所有插件进程永不重启。已经发布的应用以及在途任务必须明确使用哪个插件版本；新版本安装成功不会自动修改旧引用。

## 2. 范围、用户与边界

| 对象 | 需要完成的任务 | 边界 |
|---|---|---|
| 个人插件开发者 | 声明能力、编写配置或代码、提供界面、调试并打包 | 每个个人用户均可使用，不需要企业身份 |
| 个人插件使用者 | 在自己的租户安装、授权、配置、运行、更新和移除 | 个人安装及凭证不自动共享给其他用户 |
| 应用开发者 | 在 Agent、工作流、知识处理或评测中引用插件 | 已发布应用显式绑定版本及本人配置 |
| 公共仓库发布者 | 提交可复用插件供审核，说明权限与兼容范围 | 不公开凭证、私人知识、运行记录或私人配置 |
| 平台管理者 | 维护兼容范围、公共发布审核及必要资源限制 | 公共审核不代替使用者自己的安装和授权 |

平台必须内置能够完成对话、基础工作流、Agent、知识问答、评测、Prompt 优化和运行管理的能力。插件用于增加或替换受支持的业务能力，不能要求用户先自行开发插件才能完成基本使用路径；平台的插件系统本身属于必交付能力。

包含的扩展种类：工作流节点、Agent 工具、模型接入、知识资料处理和检索、评测器与优化步骤、Skill 及模板资源、自定义配置/调试/结果组件和导航扩展页。各扩展类型随对应阶段成为可用能力，最终必须有可运行样例和明确的开发资料。

不要求插件任意接管平台界面、访问宿主环境或读取其他租户内容；也不把公开发布等同于公共模型服务。模型、MCP、工具及其他外部服务凭证全部由实际使用者自行配置（BYOK）。

## 3. 详细需求

### PA-PLG-001 插件开发入口

- **场景：** 个人用户希望开发自己的扩展能力。
- **要求：** 提供“我的插件/插件开发”入口，可创建、查找、复制和维护本人插件草稿，查看开发指引、样例、调试入口、版本与安装情况。能力类型和目前已支持范围清楚可见，作者与安装使用者身份分别表达。
- **异常边界：** 新建草稿不等于已安装可运行；同名不同来源插件需要能够辨认。未经公开或明确授权的他人草稿不可读取或修改。
- **验收 PA-PLG-001-A1：** 新个人用户可以创建插件草稿，并从入口找到下一步声明、调试和打包路径。
- **验收 PA-PLG-001-A2：** 两个用户的私人插件草稿和调试记录互相隔离。

### PA-PLG-002 能力包身份、内容与版本

- **场景：** 作者需要让使用者知道插件是什么、提供哪些能力以及来自哪里。
- **要求：** 每个插件具有可区分的身份、作者或来源、版本、说明、能力清单、适用平台范围及必要依赖；区分配置资源、执行代码和前端界面内容。支持一个插件包含相互关联的多项能力，但每项能力都能明确识别。
- **异常边界：** 同一已发布版本的内容不得静默替换。插件声明的能力须能在检查或调试中核实，不能通过修改名称冒充其他作者或平台内置能力。
- **验收 PA-PLG-002-A1：** 用户能够在安装前查看包内全部能力及各自用途，区别资源组合与新执行逻辑。
- **验收 PA-PLG-002-A2：** 同版本内容被改变时能够检测并拒绝当成原版本继续使用。

### PA-PLG-003 输入、输出、配置与权限声明

- **场景：** 插件需要接收业务输入、产生结果，并要求某些资料或外部访问。
- **要求：** 作者可声明输入输出、必填项、可选项、常见内容类型、约束、默认值、敏感项、使用者需绑定的凭证、可能费用和外部影响；说明所需权限及界面位置。输入输出可用于节点连线、工具选择、调试和结果检查。
- **异常边界：** 未声明的资料或权限不能自动获得；默认值不能携带作者秘密。错误或缺失输入应在可判断时提前提示；输出不符合声明时不应伪装为成功。
- **验收 PA-PLG-003-A1：** 使用错误类型、缺失必填项或不允许取值调试时，显示具体问题。
- **验收 PA-PLG-003-A2：** 结果不满足声明时能定位到对应插件和结果项，后续步骤不会默默接受错误结果。

### PA-PLG-004 SDK、模板与可复现样例

- **场景：** 开发者首次使用平台扩展能力，希望不修改主平台源码即可开始。
- **要求：** 提供开发工具包或等效开发支持、声明示例、输入输出约定、界面通信说明、错误及用量上报要求、调试与打包说明。按阶段提供配置节点、自定义代码节点/工具、自定义界面、模型接入、知识检索和评测扩展的可运行样例；说明样例依赖与支持范围。
- **异常边界：** 示例不得使用真实秘密、未公开凭证或与平台不兼容的声明。未支持的运行环境明确标记；不声称支持任意语言、任意依赖和任意前端包。
- **验收 PA-PLG-004-A1：** 新开发者按照相应阶段的指引，从样例创建并安装一个自己的插件，无需修改主平台源码。
- **验收 PA-PLG-004-A2：** SDK、样例和平台支持范围一致；不兼容版本在开发或安装时能够发现。

### PA-PLG-005 调试、验证与打包

- **场景：** 作者完成能力声明和实现，需要确认它对正常、错误和边界输入的行为。
- **要求：** 提供输入样例、配置检查、受控试运行、结果预览、调用与用量记录、失败定位和打包入口。用户能明确区分样例数据、真实外部服务和真实费用；界面扩展可以在实际承载位置预览。
- **异常边界：** “调试”不免除授权、BYOK、费用和外部副作用限制。打包不得包含作者的私密配置、模型凭证或私人调试资料；检查未通过的包不能显示为已验证。
- **验收 PA-PLG-005-A1：** 同一插件完成正常输入、无效输入和取消/超限的调试，并保留结果与版本。
- **验收 PA-PLG-005-A2：** 打包后内容与调试通过的版本可对应，包中不包含个人秘密和未选择公开的数据。

### PA-PLG-006 安装前完整性与兼容性检查

- **场景：** 使用者导入自己的包，或从公共仓库选择一个经过审核的包。
- **要求：** 安装前核对来源、内容完整性、能力声明、必要依赖、平台与 SDK 适用范围及所需权限；展示将新增或更新什么。检查结果区分阻止安装的问题与可由用户处理的配置缺失。
- **异常边界：** 缺失文件、重复身份冲突、依赖不存在或不兼容时不得部分启用后声称安装成功；不允许绕过检查直接使包内代码或界面取得执行资格。
- **验收 PA-PLG-006-A1：** 缺依赖、内容损坏和不兼容样例都被阻止并显示原因。
- **验收 PA-PLG-006-A2：** 安装失败不会破坏原已安装版本或其他用户的插件。

### PA-PLG-007 个人安装范围与能力授权

- **场景：** 个人用户希望在自己的一个或多个项目使用插件。
- **要求：** 安装归属本人租户；可选择插件允许使用的本人项目、能力和资料范围。下载、安装、启用、执行授权各有明确状态；进入新项目或增加能力时重新核对适用范围。
- **异常边界：** 公共目录中可见或已被平台审核不等于本人已授权。安装不能使所有用户或所有项目自动获得访问；插件代码或界面声明已获授权不能替代真实记录。
- **验收 PA-PLG-007-A1：** 只授权项目甲的插件不能从未授权项目乙调用。
- **验收 PA-PLG-007-A2：** 撤回能力授权后，旧界面、旧应用和在途任务不能继续发起新的受限动作。

### PA-PLG-008 BYOK 配置与凭证替换

- **场景：** 插件需要模型、MCP 或外部业务服务。
- **要求：** 使用者明确绑定自己的资源和凭证；可以检查配置状态、验证可用性、替换和停用。共享包仅携带需要什么的说明，不包含发布者秘密。插件调用模型时纳入使用者自己的 Token 和预算记录。
- **异常边界：** 缺少凭证时提示本人补齐，不回退到平台、作者或其他用户凭证。前端扩展不能读取完整秘密；凭证停用后不能凭历史配置继续调用。
- **验收 PA-PLG-008-A1：** 两个用户安装同一公开插件，分别使用自己的资源且互不看到秘密。
- **验收 PA-PLG-008-A2：** 未配置或已停用凭证时，相关调用被明确阻止，其他不依赖该凭证的功能仍可使用。

### PA-PLG-009 统一配置表单

- **场景：** 插件需要普通字段、选项、资料选择或凭证绑定，不需要专门界面。
- **要求：** 根据声明提供一致的配置体验，包含提示、必填检查、敏感项保护、默认值说明、保存状态和试用入口；使用者能看到当前配置版本及适用项目。
- **异常边界：** 声明无效时不能生成误导性可用表单；秘密项不因复制、导出或预览而泄露。更换插件版本后，不能默默丢弃不兼容配置。
- **验收 PA-PLG-009-A1：** 不提供自定义界面的插件仍能完成配置、校验、保存和试用。
- **验收 PA-PLG-009-A2：** 升级导致配置项变化时，用户能看到需要调整的内容且旧配置依据保持可追溯。

### PA-PLG-010 自定义组件与页面扩展

- **场景：** 插件需要专门的配置选择器、调试面板、可视化结果或功能页面。
- **要求：** 支持作者交付自定义前端界面，并声明配置、调试、结果和导航扩展页等承载位置。界面可在授权范围内获取完成当前动作所需的最少上下文、修改本插件配置、请求试运行或查看结果，始终显示所属插件及当前项目。开发资料应说明支持的界面产物和运行能力，并提供实际可用的样例；不能把任意前端程序都描述为可直接兼容。
- **异常边界：** 自定义界面不能任意接管整个平台、修改其他插件、读取宿主登录凭证或本人模型密钥，也不能自行扩大资料范围；不能依靠隐藏按钮绕过真实权限检查。授权界面应让用户看清插件将取得哪些业务内容；对已经获准交付的内容，不承诺其绝对不可复制或外传，以最少资料披露和可撤销后续访问控制风险。
- **验收 PA-PLG-010-A1：** 一个插件可在配置区域及结果区域展示专用组件，并可提供登记后的扩展页。
- **验收 PA-PLG-010-A2：** 自定义界面提出超出允许范围的读取、导航或执行请求时被拒绝，且普通平台功能保持可用。

### PA-PLG-011 界面挂载、卸载与局部故障

- **场景：** 用户切换项目、插件版本、配置页面，或插件界面出现异常。
- **要求：** 明确界面加载、可用、失败、关闭和卸载状态；项目和版本切换时重新核对其上下文与授权。加载失败或可恢复错误提供局部提示、关闭、重试及适用的统一表单替代入口。关闭、重载或离开原界面后停止旧会话的有效操作能力，重新启用需要重新核对当前安装、版本和授权。
- **异常边界：** 旧界面在导航、重载、卸载、撤权或版本变更后不能继续读取或修改当前状态；重复或过量操作请求应被限制并可关闭对应区域。不以局部错误隔离承诺任意恶意界面都不可能占用浏览器资源；支持范围和恢复方法应可见、可验证。
- **验收 PA-PLG-011-A1：** 插件界面加载失败后用户仍能使用主平台、关闭该区域并查看错误。
- **验收 PA-PLG-011-A2：** 导航、重载、撤权、切换项目或卸载后，旧界面残留与重复请求不再有效；新界面重新核对当前权限，不能继承旧授权或进入其他项目上下文。

### PA-PLG-012 自定义节点与 Agent 工具执行

- **场景：** 作者需要平台原先没有的新执行逻辑。
- **要求：** 可以开发新的节点或工具能力，声明输入输出与影响范围，在调试通过、安装和授权后分别用于工作流和 Agent；同一能力能够复用，执行结果和错误具有统一可理解形式。
- **异常边界：** 不得仅将“登记现有 MCP/Skill”作为此需求已完成的依据；插件调用内部其他能力仍受实际使用者授权。输出不符合约定或执行状态不明时不能显示业务成功。
- **验收 PA-PLG-012-A1：** 不修改主平台源码，安装一个包含新计算或业务处理逻辑的插件，工作流和 Agent 均能实际调用。
- **验收 PA-PLG-012-A2：** 插件异常、无效输出和外部结果不确定时，上层能正确区分失败、待核实与已完成部分。

### PA-PLG-013 动态安装、升级与配置生效

- **场景：** 平台已有其他任务运行，使用者要改变自己的插件。
- **要求：** 安装、升级、启停和配置生效不要求重启全部 Runtime 或主平台；能够观察每项操作的进行、成功、失败及影响范围。可仅替换受影响的插件执行实例，新版本就绪后才允许显式选择使用。
- **异常边界：** 只支持添加工程依赖、整体重新构建并重启平台的方式不能满足要求。新版本失败不能自动中断无关运行或改变旧引用；个别插件实例重启不应被错误承诺为绝不会发生。
- **验收 PA-PLG-013-A1：** 保持普通任务与旧插件任务运行，同时完成新代码插件安装、配置和版本升级，全局 Runtime 与主平台无需重启。
- **验收 PA-PLG-013-A2：** 新版本未就绪或验证失败时，现有且仍获准的旧版本保持可用，无关任务不受影响。

### PA-PLG-014 应用版本与在途任务绑定

- **场景：** 应用已发布或任务尚未结束，插件出现新版本或新配置。
- **要求：** 应用明确绑定插件版本和配置依据；安装新版不自动修改已发布应用。新旧插件版本可同时服务不同明确引用。运行中、暂停、待审批等未结束任务保留原版本依据，恢复前重新核对当前权限和资源可用性。
- **异常边界：** 找不到原版本时明确阻塞，不静默切换最新版；版本固定不延长已撤销授权，不允许使用已停用凭证。新版采用产生新的应用或配置依据，不能覆写旧运行事实。
- **验收 PA-PLG-014-A1：** 新旧应用分别固定两个插件版本并得到对应结果，安装新版未改变旧应用引用。
- **验收 PA-PLG-014-A2：** 暂停或待审批任务经历插件升级后，恢复使用原版本；原授权撤回时拒绝继续受限动作并说明原因。

### PA-PLG-015 停用、撤权、卸载与影响说明

- **场景：** 用户不再使用插件，或某版本存在需要阻止的新操作。
- **要求：** 区分停止新使用、撤销能力授权、退出活动实例和移除安装内容；操作前列出受影响的应用、项目和未结束任务。仍被引用的版本默认不能直接移除，必须先完成显式替换、取消或其他有记录的处理。
- **异常边界：** 不能把暂停或待审批任务漏算为无引用；不能为了完成卸载而静默改用新版或删除运行依据。紧急撤权可以先阻止后续执行，但应说明对在途任务和历史查阅的影响。
- **验收 PA-PLG-015-A1：** 尝试移除仍被应用及未结束任务引用的版本时，得到完整影响清单和明确阻止。
- **验收 PA-PLG-015-A2：** 完成引用处理后可移除安装；历史仍能说明采用过的版本，后续执行不能继续使用已撤销能力。

### PA-PLG-016 受控代码与脚本执行

- **场景：** 插件包含用户编写的代码或 Skill 附属脚本。
- **要求：** 在真实授权范围内限制资料、文件、外部访问、持续时间和资源消耗；提供取消、超限处理与结果产物记录。执行环境准备失败时明示原因，不绕过限制。基础能力在阶段 3 开放代码插件前具备，阶段 6 扩展复杂协作场景。
- **异常边界：** 插件不能访问其他用户资料、平台管理凭证或不在授权范围的宿主内容；代码执行不等于获得系统管理权。对于外部修改的不确定结果，不能不经核对自动重复操作。
- **验收 PA-PLG-016-A1：** 允许范围内的代码和脚本能够完成任务，越界资料和外部访问被阻止。
- **验收 PA-PLG-016-A2：** 取消、超时及资源超限有明确终态与已有产物，其他插件和租户的普通任务保持可用。

### PA-PLG-017 Token、用量与诊断归属

- **场景：** 插件执行模型调用、检索、评测或优化，用户要理解真实消耗。
- **要求：** 所有插件模型调用进入调用方统一 Token 面板，保留插件版本、任务、个人租户、项目和实际功能来源；对话、Agent、RAG、评测、优化分类保持一致。日志、错误、调用记录和产物按权限可查看。
- **异常边界：** 不允许以插件内调用为由遗漏模型消耗；调用父子关系不能重复计费。供应商无法提供用量时明确缺失或估算；工具及执行资源的非 Token 开销分别展示，不能塞进 Token 数值。
- **验收 PA-PLG-017-A1：** 含插件调用的 Agent、RAG、评测和优化样例可以在面板中定位明细，并与相应任务对应。
- **验收 PA-PLG-017-A2：** 插件再次上报同一次调用或被多个父记录引用时，总 Token 不重复累计，未知用量不伪装为零。

### PA-PLG-018 知识处理与检索扩展

- **场景：** 用户要增加新的资料处理、证据选择或检索能力。
- **要求：** 支持作者开发知识资料处理和检索扩展，并在知识配置与调试入口选择版本。输出应保留文档、版本、位置、权限和相关证据；能使用现有样本比较基础方案与扩展方案，查看失败、结果变化及用量。
- **异常边界：** 插件不能绕过资料授权或虚构证据来源；切换插件后原评测条件仍可解释。仅返回更多片段不自动证明召回率提高。
- **验收 PA-PLG-018-A1：** 安装一个自定义资料处理或检索插件，真实用于知识问答并显示来源，两个个人租户资料隔离。
- **验收 PA-PLG-018-A2：** 在固定资料、问题和标注条件下比较两个版本，报告逐题变化及成本，不隐瞒失败样本。

### PA-PLG-019 评测器与优化步骤扩展

- **场景：** 用户需要针对自己的业务定义判定方式或加入新的 Prompt/应用优化步骤。
- **要求：** 支持声明适用目标、所需样本、判定依据、结果解释、版本和可能费用，并在质量中心使用。优化扩展生成候选供比较与选择，保留原基线与使用条件，能够复用既有回归和人工复核流程。
- **异常边界：** 扩展输出的分数不自动成为最终事实；缺少标注或调用失败不应被算成有利分数。不得偷看受保护测试答案、扩大外部资料授权或自动覆盖已发布应用。
- **验收 PA-PLG-019-A1：** 自定义评测扩展输出逐题判定、依据、版本及失败状态，可由用户复核。
- **验收 PA-PLG-019-A2：** 自定义优化步骤产生候选并完成同条件比较，使用者显式选择后才形成新的可采用版本。

### PA-PLG-020 公共发布与安装联动

- **场景：** 作者希望其他个人用户复用插件。
- **要求：** 插件可进入公共仓库的提交、审核、公开和版本更新流程；公开说明能力、内容、权限、兼容范围及使用者需自行配置的资源。使用者下载后仍要完成本人安装、授权与 BYOK 配置。
- **异常边界：** 本人自用不等于已经公共发布；审核通过不自动授权全体用户。公开包不包含作者凭证、私人知识或运行资料；公共撤回对新获取和既有安装的影响遵循公开仓库规则。
- **验收 PA-PLG-020-A1：** 一个插件从私人开发到经审核公开，再由另一用户独立安装并使用自己的凭证运行。
- **验收 PA-PLG-020-A2：** 非公开版本不能被其他用户发现或下载，公开包中没有作者私密配置。
- **关联：** [公共仓库需求](02-public-repositories.md)规定审核角色、共享范围与撤回细节，本专题不另建一套相反规则。

### PA-PLG-021 应用发布的插件依赖检查

- **场景：** Agent 或工作流准备发布为可供使用的应用。
- **要求：** 发布前核对插件身份、版本、本人配置、凭证、权限和兼容范围；使用者能够看清应用所需能力。复制或获取公共应用时，依赖应可定位，并提示在本人租户重新安装与配置。
- **异常边界：** 缺失插件、禁止使用的版本和未配置凭证不能被伪装成可用应用；应用作者的安装与凭证不能自动成为使用者的执行依据。
- **验收 PA-PLG-021-A1：** 发布含插件应用时能发现缺失依赖，补齐并验证后才可使用。
- **验收 PA-PLG-021-A2：** 另一用户取得应用后，依赖指向明确版本且必须完成本人的安装、授权和凭证绑定。

### PA-PLG-022 兼容检查、升级验证与问题复现

- **场景：** 平台、SDK 或插件发生更新，使用者需要知道现有应用能否继续工作。
- **要求：** 提供版本适用说明、变更记录、样例验证和已知限制；升级前能够检查受影响的声明、界面、配置和执行能力。问题报告包含足以复现的版本、输入样例、预期和实际结果，并保护秘密。
- **异常边界：** 版本号码相近不自动证明兼容；平台升级不能静默删除插件能力或强行转换未验证的配置。不可兼容版本应阻止采用并说明可继续使用或迁移的路径。
- **验收 PA-PLG-022-A1：** 在兼容和不兼容样例中分别得到正确检查结果，新旧配置差异可解释。
- **验收 PA-PLG-022-A2：** 根据脱敏问题报告可以在指定版本复现错误，失败报告保留原始结果而非改写为通过。

### PA-PLG-023 插件资料、产物与配置迁移

- **场景：** 插件产生长期资料或配置格式变化，使用者准备升级、退回或卸载。
- **要求：** 说明插件保存什么、属于哪个个人租户和项目、用途、可导出内容及清理影响；有变化时提供预览、可核对的迁移结果和失败处理。旧配置及在途任务需要的资料在允许范围内保留，回退能力必须说明适用边界。
- **异常边界：** 退回代码版本不等于自动撤销已修改数据或外部操作；不支持安全回退时必须明确阻止并提供恢复说明。删除安装与删除用户资料不能无提示地合并成同一个动作。
- **验收 PA-PLG-023-A1：** 配置或插件资料变更前可看到影响，迁移失败不破坏可保留的原始依据。
- **验收 PA-PLG-023-A2：** 卸载或退回版本时，资料保留、导出、删除和外部操作不能撤回的范围均得到明确说明。

## 5. 主要故障与验收闭环

| 故障或变化 | 必须可观察的结果 |
|---|---|
| 安装时内容不完整、依赖或声明不兼容 | 明确失败，不部分启用，不破坏旧版 |
| 自定义界面崩溃、超时、卸载后继续请求 | 局部失败并停止旧界面的有效能力，主平台可继续操作 |
| 代码插件超限或无法启动 | 受影响调用停止或阻止，记录已有产物和用量，无关任务可继续 |
| 升级中旧任务未结束或正在等待审批 | 旧版本引用保留，新版不会覆盖；恢复时检查当前授权 |
| 撤权与停用发生在任务中途 | 阻止后续受限动作，明确不可继续原因，不伪装完成 |
| 仍有引用时卸载 | 展示应用、项目和未结束任务，默认阻止直接移除 |
| 使用他人公开包但没有个人凭证 | 提示配置自己的凭证，不继承作者或平台凭证 |
| 配置迁移或回退无法保证资料完整 | 明确阻止不安全切换，保留可核对原始依据和恢复说明 |

最终验收至少覆盖：两个个人租户独立安装同一公开包、一个具有新逻辑的代码插件、统一表单与四类界面位置、运行中的版本升级、待审批任务恢复、权限撤回、卸载引用保护、知识/评测扩展，以及统一 Token 面板的归属与不重复统计。
