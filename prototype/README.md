# PeachAgent 交互原型

OTRYX Studio 是 PeachAgent 的原生 HTML、CSS、JavaScript 交互原型，用于体验从配置 Agent／工作流、接入知识和工具，到发布、追踪与评测的产品路径。

**当前提供浏览器本地演示。** 对象维护、变量、分支、审批、版本和规则评分按实际配置变化；模型、MCP、插件、HTTP、数据库与外部写入使用本地模拟。原型没有部署真实 API 或身份服务，不会产生模型费用。

整体需求与 P1–P7 开发安排见 [产品 PRD](../requirements/PRD-PeachAgent.md)；产品开发遵循[当期评审与交付规则](../ci/README.md)。

## 打开体验

下载 [OTRYX_Studio.html](OTRYX_Studio.html)，用桌面浏览器打开。样式和脚本已内联，无需安装前端依赖。GitHub 文件页显示源码，需要下载后打开。

也可以从仓库根目录启动静态服务：

```bash
python -m http.server 8080 --directory prototype
```

访问 <http://localhost:8080/src/index.html>。系统仅提供 `python3` 时替换命令名。若浏览器限制离线页面的 Web Crypto 能力，请使用上述本地 HTTP 入口。

登录页提供“进入演示空间”和“填入演示账号”，也可注册本地账户。公开演示凭据为 `demo@peachagent.local` / `PeachAgent@2026`，仅用于原型。

## 建议体验顺序

| 入口 | 可以验证的产品流程 |
| --- | --- |
| 账户、工作空间与项目 | 注册／登录 → 默认空间和项目 → 创建、重命名、切换、归档与恢复；可删除从未保存业务数据的空目录项 |
| 项目资源副本 | 同空间选择其他项目中的 Prompt、Skill、知识库和模型固定版本 → 导入独立副本；知识库重新绑定检索模型，模型副本默认停用 |
| 凭证中心 | 登记或发现现有凭证引用 → 绑定连接 → 校验格式／记录轮换／撤销 → 检查调用受阻；应用 API Key 仍在发布页维护 |
| 待办与审批 | 统一查看运行确认、API Key 申请及资源审核 → 进入各自业务页处理；不提升当前角色权限 |
| 资源市场 | 选择已发布资源或插件模拟动作清单 → 公开申请 → 管理员审核 → 安装独立模板 |
| 模型中心 | 维护服务商连接与模型实例 → 类型及能力校验 → 模拟调试 → 设置用途默认值；覆盖 LLM、Embedding、Rerank、图像、STT、TTS |
| 智能体／协作计划 | 配置模型和能力 → Chat 只读问答／Plan 生成计划／Agent 执行 → 编辑临时子 Agent、依赖、模型池及预算 → 执行 → 处理写入确认 → 查看父子运行 |
| 工作流 | 编辑节点、连线和参数 → 校验与调试 → 发布版本 → 查看实际选路、审批、返回值或操作回执 |
| 知识库／提示词与 Skills | 维护正文、分段、模板参数与版本 → 检索测试 → 在 Agent 或工作流中引用 |
| 工具与连接 | 配置 MCP／插件实例 → 按 Schema 调试成功、空结果、错误及超时 → 绑定具体工具 → 查看协议记录 |
| 发布与 API | 选择已发布 Agent／工作流 → 上线服务版本 → 预览调用方申请与所有者审批 → 领取 Key → 本地 Playground 调用 → 查看 Run／Trace |
| 质量评测 | 创建数据集 → 维护样例或导入 JSON／JSONL／CSV → 设置规则并保存版本 → 执行、比较与人工复核 → 从运行回收问题样例 |

模型、工具、知识、Prompt／Skill 和数据集各有唯一维护入口。应用服务上线、API Key 申请审批、运行写入确认、公共资源审核分别处理。

## 主题、语言与空间

- 支持日光纸感（`editorial-light`）、深空工作台（`obsidian-dark`）、冷静灰蓝（`nordic-slate`）三套主题。
- 支持 `zh-CN`／`en-US` 核心菜单、登录和常用标签切换；复杂编辑器和部分动态文案仍保留中文，代码、JSON 编辑区保持原文。
- 主题和语言偏好在当前浏览器共享。业务数据按本地账户、空间及项目隔离；默认空间的默认项目兼容原有数据，新增项目独立保存。
- 切换空间或项目前需保存或放弃当前编辑，切换复用会话清理、停止本地运行和评测；保存失败时留在原空间，已停止任务不自动恢复。语言切换会阻止未保存编辑和打开的弹窗。空间名称由空间注册表统一维护。原型不包含云同步、协作成员或服务端多租户授权。
- 侧栏与内容页分别保存滚动位置；相关源码和离线模型检查不能代替目标浏览器体验验收。

## 结果与版本

成功完成可以没有返回值、文件或业务操作。运行状态、可选返回值、操作回执与显式文件分别记录，内部节点输出用于传参和 Trace。

发布版本、服务版本、数据集版本及运行快照独立保存。后续编辑不改写历史，连接停用和当前授权仍参与每次调用校验。临时子 Agent 仅在用户明确保存后进入可复用列表；委派不能扩大父工具权限或预算。

## 模拟边界

| 范围 | 当前限制 |
| --- | --- |
| 账户与数据 | 认证、恢复和持久化在浏览器内完成；本地重置不发送邮件。清理浏览器存储会影响演示数据 |
| 模型与规划 | 模型输出、自动分工、用量和成本为本地模拟或估算；服务商模板不代表已经连接真实服务 |
| 工具与工作流 | 节点配置和控制流可执行；真实 MCP／插件代码、Webhook、定时、数据库及沙盒没有后端，复杂嵌套仍使用高级 JSON |
| 知识检索 | 关键词检索使用保存正文；向量与重排为确定性模拟，没有真实向量库，PDF／Word／OCR 尚未接入 |
| API 与 Key | `.example` 地址是占位；Playground 在本地校验权限和配额，不发 HTTP 请求。所有者／调用方是角色预览，对外 MCP 服务未实现 |
| 质量评测 | 按用户维护的确定性规则判定，尚无 LLM 语义评分；写操作及人工等待受保护阻断，不自动批准 |
| 部署与验收 | Compose 页面仅导出配置草案；完整浏览器视觉、焦点、窄屏、拖动、剪贴板和下载仍待验收 |

请使用示例数据。应用 Key 持久状态仅保留指纹及元数据；模型密钥与连接凭据属于独立配置，原型不能替代生产秘密保管。

## 构建与验证

需要 Node.js 和 Python 3，脚本使用内置模块。从仓库根目录执行：

```bash
node prototype/src/qa/integration.cjs
python prototype/src/qa/verify-sources.py
python prototype/src/build.py
```

先运行契约套件生成 `qa/.generated/` 页面标记，再执行静态检查；构建步骤重新生成离线 HTML。当前检查状态见[验证记录](src/qa/verification.md)及 PR #17 的 CI。CI 还检查重新生成的独立 HTML 是否与提交一致。真实浏览器视觉验收与全量业务文案翻译仍需单独验证。
