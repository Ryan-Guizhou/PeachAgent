# 资产、市场与审核模块验证

## 交付范围

- `ecosystem.js` 注册 `assets`、`market`、`review` 三条路由与带 `eco-` 前缀的动作。
- `ecosystem.css` 只定义 `eco-` 局部类与媒体查询，颜色消费共享语义变量，无外部字体或网络依赖。
- 资产库包含 8 个初始示例，支持知识库、Skill、MCP、提示词、记忆、文件分类，以及安装的 Workflow 蓝图。
- 市场包含 12 个精选示例，使用“研究、表达、核验”的收藏组合视觉；资源可筛选、搜索、加载更多、查看详情和安装。
- Agent 安装写入 `Studio.state.agents`，模型选择首个已连接的模型；其余写入 `ecoAssets`。Workflow 安装同时调用 builder 的 `Studio.installWorkflow(resource)`（若已注册）。
- 资产编辑按补丁版本递增；发布保留独立版本快照，原资产后续编辑不修改审核快照。
- 公共发布支持提交确认、待审核、管理员通过、退回并保留具体原因；未通过的提交不会进入市场目录。
- 上传使用真实 File 元数据，验证格式/大小/空文件；解析是明确标记的本地模拟，支持取消、重试和批量保存；不读取、上传或持久化文件正文。

## 静态交叉审查

- `S.modal` 首先调用 `S.closeModal`，`closeModal` 执行 `onClose`；模型配置的 `onClose` 清空密钥字段并清除模拟测试定时器。模型保存只构造非敏感字段，不把 `apiKey` 写入状态。
- 本模块不提供密钥字段，不发网络请求，不直接使用 localStorage。MCP 地址拒绝用户名、密码、查询参数与片段；内容、名称、说明、标签、审核理由包含明显密钥样式时阻止保存。
- 市场动态目录仅取 `reviews.status === 'approved'`；安装时再次检查资源仍可用。审核动作处理器同时检查 `role === 'admin'` 和 `status === 'pending'`，按钮隐藏不作为唯一权限校验。
- 模块初始化仅在独占数组不存在时加入资产；已有 `ecoAssets`、`installed`、`reviews` 不覆盖。审核种子仅第一次且原 `reviews` 为空时加入。
- 字段 `id`/`name` 与 `S.validate` 的键保持一致。所有表单 `novalidate`，所有按钮 `type=button`；对话框、通知、搜索清除、字段验证复用核心 API。
- 动态用户字符串经过 `S.escape`，包括文件名、资料正文、说明、标签、地址、退回原因与 DOM 属性。
- 全部结果有数量与空状态；筛选保留查询并重置可见数量；中文输入组合期间不执行搜索。

## 已执行验证

1. `node --check ecosystem.js`：通过。
2. Node VM 状态流程验证：3 个路由可渲染；Agent/Skill 安装跨集合可见；重复安装无副本；知识创建、编辑版本递增、空名称阻止；提交审核快照、重复提交阻止；普通成员审批拒绝、管理员通过与退回理由保存：通过。
3. Premium strict 静态审计已运行。项目共报告 8 条 `affordance.actionless-button`，其中本模块 2 条位于动态模板按钮（分类过滤和精选资源）。这些按钮都具有 `data-action`，由 `core.js` document 事件委托处理；审计器只识别内联 onclick/Vue 事件，不能据此证明交互缺失。未修改审计器或添加伪处理器来绕过报告。
4. Python Playwright 已尝试：默认浏览器缓存缺失；指定 `/usr/bin/chromium` 后环境在启动阶段拒绝 Unix socket 创建，未能进入页面。没有把这次尝试记为浏览器通过。完整截图、窄屏与实际 DOM 操作交由主代理统一验证。
