# OTRYX Studio 原型产品约定

更新日期：2026-11-23。

## 用户目标与本轮依据

用户希望获得可实际操作的 HTML + CSS + JavaScript 原型，布局原创、清晰克制，能够覆盖成熟 Agent／工作流产品的大部分常用能力。最新反馈在已完成的对外服务、API Key 和可维护评测集基础上，要求补齐注册登录、稳定侧栏滚动、多类型模型维护和可自主创建子 Agent 的规划任务。

本目录的用户反馈、实际代码和已验证行为是原型说明的依据。这里不把仓库其它产品或技术文档当成本轮原型的约束，也不把原型视为生产系统已经落地。

## 产品定位

一个把 AI 应用从配置、测试、发布到持续改进连接起来的工作空间。个人空间即可创建 Agent、编排工作流、复用知识与工具、向调用方开放应用版本，并从运行记录构建评测集。

界面围绕具体对象组织：Agent、工作流、应用服务、连接、知识库、提示词／Skill、评测集、运行记录。每个对象有唯一维护入口；其它页面通过选择或引用复用它。模板安装、服务接入和运行授权是不同步骤。

## 页面与对象归属

| 区域 | 维护对象 | 关联方式 |
| --- | --- | --- |
| 账户入口 | 注册、登录、恢复、会话状态 | 启动时捕获账户工作区，身份切换重载 |
| 模型中心 | 服务商连接、实例、六类用途、能力与默认值 | Agent、LLM 节点和知识检索引用稳定模型 ID |
| 协作计划 | 运行范围子 Agent、任务依赖、模型池与预算 | 父权限内执行子运行，共享 Trace |
| 智能体 / 工作流 | 草稿、输入输出、工具与上下文绑定、发布版本 | 引用已有资源；发布保存配置，运行和服务／评测固定依赖 |
| 发布与 API | 应用服务、服务版本、调用权限、API Key、申请、调用日志 | 来源必须是已发布 Agent 或工作流 |
| 工具与连接 | MCP、插件包、连接实例、Tools / Resources / Prompts | Agent 与节点引用同一个连接和具体能力 |
| 知识库 | 正文、文档、分段、检索设置与内容版本 | Agent 和知识节点引用可检索内容 |
| 提示词与 Skills | 可维护文本、模板参数、依赖说明与版本 | 作为上下文或模板引用，不自行获得工具执行权 |
| 质量评测 | 输入样例、参考输出、分组、规则、数据版本、评测任务 | 固定应用版本和样例，结果关联原始运行 |
| 资源市场 | 可发现和安装的配置模板、公开审核记录 | 安装后进入对应维护入口；不等同于已授权连接 |
| 运行记录 / 用量与成本 | 执行事实、审批、调用链、结果与估算用量 | 所有执行入口共享 Runtime |

## 完整使用路径

1. **构建与发布**：创建 Agent 或工作流 → 配置知识／工具 → 本地调试 → 发布版本 → 创建服务 → 上线固定版本 → 申请、审批并领取 API Key → Playground 调用 → 查看 Trace。
2. **持续改进**：从运行记录加入评测集 → 人工核对输入与参考输出 → 维护分组和规则 → 固定数据版本 → 对已发布版本评测 → 比较相同样例 → 人工复核 → 将问题样例回收。
3. **内容复用**：创建知识库 → 维护正文 → 分段与检索测试 → 绑定 Agent／节点 → 运行记录内容快照。提示词和 Skill 同样可维护、复制、归档和引用固定版本。
4. **工具接入**：配置 MCP／插件实例 → 检查能力与 Schema → 使用模拟场景调试 → 绑定具体工具 → 在 Chat 或工作流执行 → 按需确认写入 → 追踪同一次调用。

5. **账户与模型**：注册／登录 → 维护服务商连接 → 新增模型并声明能力 → 类型调试 → 设置用途默认值 → 在 Agent、节点或知识库中选择 → 发布固定配置。
6. **自主协作**：输入目标 → 生成临时子 Agent → 审阅分工和依赖 → 扩充允许的模型池或手动指定 → 控制预算与并发 → 执行 → 处理子任务确认 → 查看统一 Trace 和可选结果。

## 状态与结果原则

- 执行成功不要求返回数据或生成文件。运行状态、返回值、操作回执与显式文件独立表达。
- 草稿、发布版本、服务版本、数据集版本和每次运行快照分开。修改当前配置不会改写历史运行和评测。
- 连接停用、凭证不可用等当前控制仍在调用时检查；冻结版本不绕过停用或授权校验。
- 自动规则评分、运行错误、受保护阻断、人工复核分别展示。阻断或未执行样例没有伪造分数。
- 运行审批、API Key 申请审批、公共市场审核是三种不同状态，界面使用各自清楚的名称和入口。
- 不可执行的服务能力明确标注本地模拟或尚未接入。没有真实结果时不显示假成功、假日志或固定优秀评分。

## 原型数据与权限边界

注册账户有各自的浏览器本地工作区；演示账户保留旧空间。页面使用浏览器内状态与 localStorage，密码验证器不属于工作区导出。API Key 的所有者／调用方切换是明确标注的角色预览，不是真实账号隔离。公共市场管理员也是演示角色。模型、MCP、HTTP、数据库、业务写入与价格均是模拟或估算；不会产生真实外发、真实账单或部署。

应用 Key 使用本地随机值和摘要校验，明文只展示一次并保留在当前会话内用于试调，localStorage 只保存指纹和元数据。MCP 保存凭证引用；模型密钥输入在关闭或保存时清空。资料正文和评测样例会保存到浏览器，适合放示例数据。

离线评测执行只读路径：写工具、数据库或人工等待会被阻断，不会自动批准操作。LLM 判分未接入；确定性规则衡量的是配置符合度。知识检索包括本地关键词匹配，以及向量／重排的确定性算法模拟；所选模型配置和阶段被记录，不冒充供应商真实语义检索效果。

交付物为可离线打开的完整 HTML 和可维护的拆分源码。后续正式服务需要另行实现身份隔离、持久任务、密钥保管、真实模型／工具网关、运行隔离与部署。

## 本轮交互约束

侧栏在路由和运行状态更新时保留同一滚动容器与链接；当前菜单重复点击不重置页面。模型维护只有一个主入口，空间设置只提供跳转和个人偏好。模型、服务商、能力与工具定义都进入执行快照；停用仍立即阻断后续新调用。

规划默认仅使用父 Agent 模型，允许池由用户显式扩大。自动分配只在池内选择类型与能力兼容的模型。临时 Agent 不污染永久列表，也不能通过委派扩大工具权限、跳过写入审批或突破父预算。
