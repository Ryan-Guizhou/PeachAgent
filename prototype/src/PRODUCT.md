# OTRYX Studio 原型任务

## 依据
2026-11-23 用户要求：依据前文 Snail AI / AI 平台分析，制作 HTML + CSS + JavaScript 的高保真可交互原型；布局原创，采用 frontend-design-premium。
前文明确：个人用户作为租户、全部功能可用、自配模型、Token 消耗面板；Agent / Workflow / MCP / Skill / Prompt 可组合；公共资源须管理员审核；支持人工审批与恢复执行；配置更新避免整体 Runtime 重启；最终 Docker Compose 部署。

## 本轮范围
原创亮色桌面工作室原型。浏览器本地模拟数据，无后端、真实模型请求、真实发布、真实写入外部业务系统或实际 Docker 部署。所有价格与使用数据是演示数据。API 密钥只保留到当前对话框关闭，绝不进入 localStorage、日志或 URL。
交付可离线双击的完整 HTML，以及可维护的拆分 CSS/JS 源码包。

## 主流程
工作台发起任务 -> 对话/计划/执行 -> 按需调用工具或工作流 -> 按配置人工确认 -> 完成任务 -> 查看执行记录与用量。
完成不以文件为条件：运行可以返回结构化数据、回复文字、产生文件，也可以在中间节点将内容写入指定位置后无返回结束。目标位置的写入回执、运行返回值和可下载文件分别呈现；没有文件不等于失败。
资产创建 -> 提交公共市场审核 -> 切换演示管理员 -> 通过或退回 -> 已通过资源可在市场安装。
工作流编辑 -> 保存草稿 -> 发布版本 -> 运行；运行保存当时的版本。

## 权限及边界
个人空间是默认体验。管理员模式仅用于演示公共资源审核，须明显标注演示角色。运行批准与市场审核是独立状态。所有变更均为本地可重置演示状态。无真实支付或外发操作。

## 本轮补全
以 OTRYX_Studio_Product_Plan.md 为产品规划，增加共享能力目录、MCP/插件调试、节点配置与变量绑定、条件/循环/迭代、Agent 工具调用和统一运行事件。
所有外部模型、MCP、插件、数据库、消息和写入操作通过本地适配器演示。改变参数和连接状态必须改变实际模拟结果。控制流必须根据图和运行数据执行；调用链来自执行事件，不从进度条反推。
运行成功只代表配置的执行目标完成。结束节点可以没有返回字段；产物仅由显式生成节点或工具结果产生。记录可以包含零个或多个写入回执，回执在原型中明确标注“模拟写入”。外部效果可能成功、失败或未知，不以生成文件替代业务完成。
