# OTRYX Studio · 可交互高保真原型

面向个人租户的 AI 工作室。将 MCP、插件、Agent Chat、工作流编排、调试与运行追踪连接起来，保留原创的雾白与深海绿视觉。

**工作流成功完成不要求生成文件，也不要求返回数据。** 中间节点可以已将内容写入指定位置，最后直接结束；也可以判断不需要执行任何操作，正常完成。本原型将运行状态、返回值、目标操作回执、可下载文件分别记录。

OTRYX Studio 是展示用暂定名称。所有模型、远程服务、数据库和目标位置写入均为本地模拟；图的控制流、参数绑定、条件判断、审批与运行事件按实际配置执行。

## 打开方式

- 下载 `OTRYX_Studio.html`，用桌面浏览器打开。全部 HTML、CSS、JavaScript 已包含在文件中，无需安装依赖或联网。
- 如果聊天应用展示的是静态文件预览，请下载后在浏览器打开。
- 源码包内 `index.html` 也可直接打开；修改相邻 CSS/JS 后刷新即可。
- 首次进入可点击页脚“交互指南”。页面本地状态保存在浏览器；在“空间设置 → 偏好”可重置演示。
- 旧版本工作流会保留原始备份，并转为可编辑图。旧运行记录仍可查看；没有事件的旧记录会明确说明，避免伪造调用链。

## 先体验这三条路径

### 1. 写入目标位置，最后无返回结束

1. 打开“工作流”，选择 **研究简报 · 写入团队空间**。
2. 点击搜索节点，在右侧“输入”检查 `input.topic`、`input.limit` 的绑定。
3. 点击 IF 节点，检查“是否找到资料”的条件，以及 true / false 两条路径。
4. 运行草稿或已发布版本，填写主题、目标目录与检索数量。
5. 流程经过搜索、分支、汇合、逐项整理和报告节点，在人工确认处暂停。
6. 确认后，插件将内容写入配置的模拟目标目录，结束节点正常完成。
7. 运行详情应显示 **已完成、1 条操作回执、没有流程返回值、0 个文件**。
8. 点击回执可查看目标位置及对应工具调用；“调用链”可查看实际参数、选中分支、未执行分支、迭代记录与错误。

把主题改为“无结果”，或在调试中切换空结果场景，可以看到另一条条件分支实际执行。

### 2. MCP 调试 → 绑定 Agent → 在 Chat 中调用

1. 打开 **MCP 连接 → Research MCP → 调试台**。
2. 选择“搜索资料”，填写 query / limit，或切换 JSON 输入。
3. 运行成功、空结果、工具错误、超时、结构不匹配等场景。
4. 检查结构化输出、实际记录的原始响应与协议请求 ID；可以保存测试用例并重新载入。
5. 将具体工具挂载到 Agent 草稿，再到 Agent 工作台检查并发布。
6. 打开 **Agent Chat**，在“本次能力”里选择允许的 MCP 与插件工具。
7. 输入“研究 Agent 工作流，把结论写入 /知识库/行业观察”。
8. Chat 会先调用检索工具，再等待写入确认，完成后显示模拟写入位置；工具卡片的调用链入口指向同一次执行。

会话能力只影响下一轮；已经开始的消息冻结当轮配置。全局连接停用仍会阻止后续新调用。

### 3. 传参、并行、循环与子流程

- **多路分析 · 返回结构化数据**：并行获取资料，命名汇合后执行有界循环，返回对象而不是文件。
- **复用发布子流程**：把父流程输入映射到已发布摘要子流程，查看父子 Run 与版本快照。
- **更新业务记录 · 无返回值**：按 key 更新数据表，只保留操作回执。
- **生成文件 · 显式成果节点**：通过成果节点生成 Markdown 文件。文件是显式配置的结果。

## 工作流结果模型

| 信息 | 是否必须 | 界面含义 |
| --- | --- | --- |
| 执行状态 | 必须 | 运行中、等待处理、成功、失败、拒绝、停止 |
| 返回值 | 可选 | 明确配置的结构化数据或对话回复 |
| 操作回执 | 可选，零条或多条 | 节点写入的目标位置、操作记录与调用 ID |
| 文件 | 可选，零个或多个 | 显式成果节点生成的可预览、可下载文件 |
| 内部节点输出 | 按实际执行产生 | 调试与调用链中的数据，不自动成为流程返回值 |

无返回模式会忽略不再使用的返回字段。取消不会撤销已完成写入；超时或协议异常导致外部完成状态不确定时，记录会保留“未知”，不伪造成功回执。

### 37 个节点族

- 入口：用户输入、Webhook、定时、插件事件。
- 智能处理：LLM、Agent、问题分类、参数提取。
- 知识与上下文：知识检索、文档提取、记忆、MCP 资源、Prompt。
- 工具：MCP 工具、插件动作、HTTP、代码、数据库、沙箱。
- 数据：字段映射、模板、变量赋值、列表操作。
- 控制：IF、Switch、互斥汇合、并行、迭代、循环、Break/Continue、人工输入、子流程、等待。
- 完成：对话回复、最终输出、显式成果、终止。

“节点族”可能含多个模式，例如并行拆分与汇合。扩展节点以模拟输入和受控处理器验证配置，不会在浏览器执行任意代码、启动 stdio 进程或连接数据库。

## 范围与实现边界

### 已实际执行的前端行为

- 上游输入按路径解析，类型不匹配和未产生变量会报错。
- 分支选择、空结果、迭代次数、循环状态、重试及错误出口由运行数据决定。
- 审批绑定当前等待记录；不重复处理，不重放此前成功写入。
- 单节点测试与重跑创建独立记录，历史输入输出不会被改写。
- 发布与运行使用独立快照；不可用的固定工具版本会明确报错。
- Agent 和工作流调用共享工具适配器、事件、调用 ID 与 Trace；子运行费用不会由父层重复计入。
- 刷新页面后无法恢复的执行会停止并保留记录，不自动重复外部操作。

### 仍为演示或后续工程范围

- 模型响应、检索内容、外部写入、费用、OAuth、连接发现和网络协议均由本地适配器模拟。
- 37 类节点并不意味着 37 类生产服务已经接入。Webhook、定时、数据库、沙箱等未接真实服务。
- 迭代/循环的嵌套 body、ELIF 组和复杂 Schema 提供高级 JSON 配置；尚未实现完整的嵌套子画布。
- Agent 使用确定性本地选择规则模拟工具规划，不是真实大模型推理；工具的输入、状态、审批和返回执行路径是真实前端逻辑。
- 市场模板、资产说明与实际连接实例分开管理。安装模板不等于已获得服务授权。
- 质量中心评分为原有示例数据，不表示完整自动评测系统。
- Sa-Token、持久任务队列、真正的凭据保管、远端追踪上报、多用户权限、真实热更新与 Docker 后端需要后续实现。
- Compose 页面导出配置草案；没有可直接拉取的 OTRYX 生产镜像。

## 数据与安全边界

此文件不向外部服务发出业务请求，不产生真实费用，也不对外发布内容。MCP 只配置凭证引用；模型密钥输入演示在关闭或保存时清空。文件导入仅读取元数据，不上传正文。

原型使用 localStorage 持久化演示状态。浏览器存储不可用时保留当前会话内状态；不要在原型中输入真实密钥或敏感业务材料。

## 构建与验证

```bash
node qa/integration.cjs
python qa/verify-sources.py
python build.py
```

`build.py` 将所有 CSS/JS 内联到上一级 `OTRYX_Studio.html`。

验证包括 29 项 Runtime 契约、228 个工作流检查器渲染变体、13 个 MCP/插件页面变体，以及 78 个跨模块页面状态与 20 组行为检查。具体结果见 `qa/verification.md`。

**浏览器验收限制：**当前执行环境无法启动受限的浏览器预览；未声称完成真实浏览器视觉、焦点、拖动、下载、原生选择弹层或窄屏截图验收。响应式和键盘支持已经写入源码，仍需在目标浏览器中实际检查。
